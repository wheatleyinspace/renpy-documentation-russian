Инструкции Python

Движок Ren'Py написан на языке программирования Python и включает полноценную поддержку интеграции кода Python непосредственно в сценарии Ren'Py. Возможности Python можно использовать для самых разных задач — от простого изменения игрового флага до создания совершенно новых отображаемых объектов (displayables). В этой главе рассматриваются способы прямого вызова кода Python из сценариев Ren'Py с помощью различных инструкций Python.

Начиная с версии 8.4, Ren'Py поддерживает Python 3.12. Версия Python, используемая в Ren'Py, может обновляться в будущих релизах. Сценарии Ren'Py должны быть совместимы с Python 3.12 и более новыми версиями.

Примечание

Если вы уже знаете Python, это даст вам огромное преимущество. Однако не всё, что применимо в чистом Python, напрямую переносимо в Ren'Py. Например, внешние пакеты Python, не поставляемые в составе Ren'Py, могут не заработать без дополнительной настройки.

Существуют также некоторые конструкции Python, которые технически работают, но могут нарушить систему сохранений игры. Обязательно ознакомьтесь со страницей сохранение, загрузка и откат, особенно с разделом что нельзя сохранять. (Следует проявлять особую осторожность с открытыми файлами, сетевыми сокетами, итераторами, задачами, объектами Future и генераторами.)

Наконец, хотя многие инструкции Ren'Py имеют эквивалентные функции Python, эти эквиваленты могут работать менее эффективно. Например, Ren'Py умеет заранее предсказывать выполнение инструкции show и фоново подгружать изображения в память, но не может предсказать вызов функции renpy.show().

Инструкция python

Инструкция python принимает блок кода Python и выполняет его, когда управление доходит до этой инструкции. Простейшая инструкция Python выглядит очень кратко:

python:
    flag = True

При необходимости инструкции Python могут быть гораздо сложнее:

python:
    player_health = max(player_health - damage, 0)
    if enemy_vampire:
        enemy_health = min(enemy_health + damage, enemy_max_health)

У инструкции Python есть два модификатора, изменяющих её поведение:

hide

С модификатором hide инструкция выполнит блок кода Python в анонимной локальной области видимости. Эта область видимости будет полностью уничтожена по завершении блока Python.

Это позволяет использовать временные переменные, которые не должны сохраняться в файл сохранения игры — однако для доступа к глобальным переменным хранилища (store) к ним придётся обращаться через объект store (например, store.my_var), а не напрямую.

in

Модификатор in принимает имя хранилища. Вместо выполнения в стандартном хранилище по умолчанию блок Python выполнится в указанном именованном хранилище.

Однострочная инструкция Python

Очень частый случай — необходимость выполнить одну строку кода Python в стандартном хранилище. Например, однострочник Python часто используется для инициализации или переключения флага. Чтобы сделать написание таких строк максимально удобным, существует однострочная форма инструкции Python.

Однострочная инструкция Python начинается со знака доллара $ и содержит код Python до конца этой строки. Примеры однострочников Python:

# Установка флага.
$ flag = True

# Инициализация переменной.
$ romance_points = 0

# Увеличение значения переменной.
$ romance_points += 1

# Вызов функции, предоставляющей возможности Ren'Py.
$ renpy.movie_cutscene("opening.ogv")

Однострочные инструкции Python всегда выполняются в стандартном хранилище (store).

Инструкция init python

Инструкция init python выполняет код Python на этапе инициализации, до того, как игра будет загружена. Помимо прочего, её можно использовать для определения классов и функций, настройки стилей, переменных конфигурации или постоянных данных (persistent).

init python:

    def auto_voice_function(ident):
        return "voice/" + ident + ".ogg"

    config.auto_voice = auto_voice_function

    if persistent.endings is None:
        persistent.endings = set()

init 1 python:

    # Плохая концовка всегда открыта по умолчанию.
    persistent.endings.add("bad_ending")

Между словами init и python можно указать число приоритета. Если приоритет не указан, используется 0. Блоки init выполняются строго в порядке возрастания приоритета — от меньших чисел к большим. Инструкции init с одинаковым приоритетом выполняются в алфавитном порядке путей к файлам, а внутри одного файла — сверху вниз.

Во избежание конфликтов с внутренними механизмами Ren'Py разработчикам следует использовать приоритеты в диапазоне от -999 до 999. Приоритеты меньше 0 обычно используются для библиотек и настройки тем оформления. Обычные блоки init игры должны иметь приоритет 0 или выше.

Инструкции init python также поддерживают конструкции hide и in.

Переменные, значения которых заданы в блоке init python, не сохраняются, не загружаются из сохранений и не участвуют в механизме отката (rollback). Поэтому значения таких переменных не следует изменять после завершения фазы инициализации.

Предупреждение

Классы, созданные в Ren'Py без наследования или с явным наследованием от object, а также их подклассы, не поддерживают использование __slots__. Попытка использовать slots приведёт к некорректной работе механизма отката в старых версиях Ren'Py и к вызову исключения в новых версиях.

Если вам необходимы slotted-классы, явно наследуйте их от python_object — такие объекты не поддерживают откат.

Инструкция define

Инструкция define задаёт значение одной переменной на этапе инициализации (init time). Такая переменная считается константой и не должна изменяться во время игры. Например:

define e = Character("Эйлин")

эквивалентно (за исключением некоторых преимуществ, описанных ниже):

init python:
    e = Character("Эйлин")

Инструкция define может принимать необязательное имя хранилища (см. ниже), указываемое перед именем переменной через точку. Хранилище создаётся автоматически, если оно ещё не существует. Например:

define character.e = Character("Эйлин")

Инструкция define может принимать индекс, позволяя добавлять элементы в словари:

define config.tag_layer["eileen"] = "master"

Помимо оператора присваивания =, инструкция define поддерживает ещё два оператора. Оператор += выполняет сложение (обычно используется для объединения списков). Оператор |= (побитовое ИЛИ) обычно используется для объединения множеств (set). Например:

define config.keymap["dismiss"] += [ "K_KP_PLUS" ]
define endings |= { "best_ending" }

Инструкция define может принимать необязательный приоритет инициализации между словом define и именем переменной. Если приоритет не указан, используется 0. Например:

define -1 config.image_directories = [ "images", "dlc/images" ]

Одним из преимуществ инструкции define является то, что она фиксирует имя файла и номер строки, на которой произошло присваивание, и делает эту информацию доступной для функции навигации в лаунчере. Другое преимущество состоит в том, что статический анализатор Инструмент Lint сможет проверять объявленные значения — например, обнаруживать, не объявлена ли одна и та же переменная дважды с разными значениями.

Переменные, объявленные с помощью инструкции define, считаются константами, не сохраняются и не загружаются из файлов сохранения и не должны изменяться во время игры. Это требование неизменяемости распространяется и на объекты, доступные через эти переменные по атрибутам или индексам. (Ren'Py не блокирует такие изменения принудительно, но это приведёт к неопределённому поведению игры.)

Инструкция default

Инструкция default устанавливает начальное значение переменной, если эта переменная ещё не была определена на момент запуска игры или после загрузки сохранения. Например:

default points = 0

Если переменная points не была определена при запуске игры, эта инструкция примерно эквивалентна следующему коду:

label start:
    $ points = 0

Фактическое присваивание значения происходит перед запуском заставки (splashscreen) и главного меню. Если переменная points отсутствует в загружаемом файле сохранения, инструкция default эквивалентна:

label after_load:
    $ points = 0

Инструкция default может принимать имя хранилища, указываемое через точку перед именем переменной. Хранилище будет создано автоматически, если оно не существует. Например:

default schedule.day = 0

Как и для инструкции define, анализатор Инструмент Lint выполняет специальные проверки и оптимизации для инструкций default.

Примечание

Настоятельно рекомендуется объявлять через default каждую переменную в игре, значение которой может меняться в процессе сюжета! Если объявить переменную через init python или define, а игрок в процессе игры изменит её, затем выйдет в главное меню и начнёт новую игру — переменная сохранит своё изменённое значение (произойдёт утечка состояния прошлой сессии в новую игру). Если же создавать эти переменные внутри метки start, они будут отсутствовать при загрузке старых сохранений.

Имена в хранилище

Стандартным местом, где Ren'Py хранит игровые переменные Python, является пространство имён, называемое хранилищем (store). Очень важно следить за тем, чтобы используемые имена переменных в хранилище не конфликтовали между собой.

Инструкция define присваивает значение переменной, даже когда используется для создания персонажа. Это означает, что нельзя использовать одно и то же имя для персонажа и для флага/счётчика.

Следующий ошибочный сценарий:

define e = Character("Эйлин")

label start:

    $ e = 0

    e "Привет, мир."

    $ e += 1
    e "Вы заработали очко!"

не будет работать, поскольку переменная e используется одновременно и как объект персонажа, и как числовой флаг. Другие элементы, которые обычно размещаются в хранилище — это переходы (transitions) и трансформации (transforms).

Имена, начинающиеся с символа подчёркивания _, зарезервированы для внутреннего использования Ren'Py. Кроме того, существует Указатель зарезервированных имён.

Другие именованные хранилища

Именованные хранилища позволяют структурировать функции и переменные Python по отдельным модулям. Размещая код Python в именованных хранилищах, вы сводите к минимуму вероятность конфликтов имён. Каждое хранилище соответствует модулю Python. Хранилище по умолчанию называется store, а доступ к именованному хранилищу осуществляется в виде store.named.

Именованные хранилища можно создавать с помощью блоков python in (или их вариантов init python in и python early in), а также с помощью инструкций default, define или transform. Переменные из них можно импортировать индивидуально с помощью from store.named import variable, а само хранилище можно импортировать с помощью from store import named.

К именованным хранилищам можно обращаться, передавая конструкцию in инструкциям python, init python или python early — весь код внутри них будет выполняться в контексте указанного хранилища.

Например:

init python in mystore:

    serial_number = 0

    def serial():

        global serial_number
        serial_number += 1
        return serial_number

default character_stats.chloe_substore.friends = {"Эйлин",}

label start:
    $ serial = mystore.serial()

    if "Люси" in character_stats.chloe_substore.friends:
        chloe "Люси — моя подруга!"
    elif character_stats.chloe_substore.friends:
        chloe "У меня есть друзья, но Люси не из их числа."

    python in character_stats.chloe_substore:
        friends.add("Джереми")

Обратите внимание, что, как и в Python, импорт связывает имя заново, а не создаёт псевдоним. Обновление переменной, импортированной из именованного хранилища, не обновит саму переменную внутри хранилища. Например:

init python in mystore:

    value = 0

init python:
    from store.mystore import value

label start:

    $ value = 1

    "[value] равно 1, но [mystore.value] остаётся равным 0."

Из блока python in к внешнему стандартному хранилищу можно обратиться через renpy.store или с помощью import store.

Именованные хранилища полностью участвуют в сохранении, загрузке и откате точно так же, как и стандартное хранилище. Специальные системные пространства имён, такие как persistent, config, renpy... никогда не поддерживали и не поддерживают создание вложенных подхранилищ внутри себя.

Константные хранилища

Именованное хранилище можно объявить константным, присвоив переменной с именем _constant значение True, например:

init python in mystore:
    _constant = True

Когда хранилище объявлено константным, переменные в нём не сохраняются в файл сохранения, а объекты, доступные исключительно через эти переменные, не участвуют в механизме отката (rollback).

Переменные в константном хранилище могут изменяться во время фазы инициализации (init). Исключительно после завершения фазы init (включая инструкции define, transform и т.д.) хранилище обязано оставаться неизменным.

Поскольку Ren'Py не отслеживает это принудительно, ответственность за неизменность переменных константного хранилища после этапа init целиком лежит на разработчике игры.

Смысл объявления хранилища константным заключается в экономии ресурсов: каждая переменная и хранилище требуют небольших накладных расходов памяти и процессора для поддержки сохранения, загрузки и отката. Константное хранилище полностью исключает эти накладные расходы.

JSONDB

class JSONDB(filename, default=None)

JSONDB — это двухуровневая база данных, использующая формат JSON для хранения своих данных. Она предназначена для использования разработчиками игр для хранения данных в файле, который может отслеживаться системой контроля версий как часть сценария игры. Например, в ней можно хранить параметры, связанные с каждой конкретной инструкцией say, изменяющие способ её отображения.

JSONDB не предназначена для данных, изменяющихся в ходе действий игрока или в результате игрового процесса. Для таких данных гораздо лучше подходят постоянные переменные (persistent) или обычные файлы сохранения.

База данных должна содержать только те типы данных, которые Python может сериализовать в JSON. Сюда входят списки, словари (со строковыми ключами), строки, числа, True, False и None. Подробнее о совместимости, преобразовании форматов и возможных подводных камнях см. в документации Python.

Оба уровня базы данных представляют собой словари со строковыми ключами. Первый уровень доступен только для чтения: при обращении по ключу к словарю первого уровня создаётся словарь второго уровня (при необходимости с начальным содержимым по умолчанию). Словарь второго уровня доступен для чтения и записи, и при изменении любого ключа во втором уровне это изменение сохраняется в базу данных на диск при выходе из игры.

Как и другие постоянные данные, JSONDB не участвует в механизме отката (rollback).

Объект JSONDB следует создавать во время инициализации (в блоке init python или с помощью инструкции define). Он автоматически сохранится на диск при условии, что хотя бы один ключ в словаре был изменён. Например:

define balloonData = JSONDB("balloon.json", default={ "enabled" : False })

Этот код создаёт JSONDB, сохранённую в файле balloon.json, со значением параметра enabled по умолчанию равным False. Значения второго уровня можно использовать как обычные словари:

screen say(who, what):

    default bd = balloonData[renpy.get_translation_identifier()]

    if bd["enabled"]:
        use balloon_say(who, what)
    else:
        use adv_say(who, what)

    if config.developer:
        textbutton "Режим диалоговых облачков (Balloon)":
            action ToggleDict(bd, "enabled")

Конструктор JSONDB принимает следующие аргументы:

filename

Имя файла, в котором сохраняется база данных. Путь указывается относительно каталога игры game/. Рекомендуется использовать расширение «.json».

default

Если значение не None, должен быть передан словарь. При создании нового словаря второго уровня этот объект поверхностно копируется (shallow copy) и используется для инициализации нового словаря. Новый словарь будет записан в базу данных только в том случае, если в нём сохранён хотя бы один ключ.

Собственные и сторонние модули и пакеты Python

Ren'Py поддерживает импорт чисто питоновских (pure-Python) модулей и пакетов. Собственные модули и пакеты (написанные специально для игры) можно помещать непосредственно в каталог game/. Сторонние пакеты рекомендуется размещать в каталоге game/python-packages/.

Например, чтобы установить пакет python-dateutil, перейдите в базовый каталог игры и выполните команду:

pip install --target game/python-packages python-dateutil

В обоих случаях модуль или пакет можно импортировать из блока init python:

init python:
    import dateutil.parser

Не все пакеты Python совместимы с Ren'Py. Разработчик обязан самостоятельно проверить устанавливаемые библиотеки и убедиться в их корректной работе.

Откат и isinstance

Код Python, написанный в файлах .rpy, автоматически трансформируется Ren'Py для поддержки отката (rollback). Код Python, импортируемый из внешних файлов .py, такой трансформации не подвергается. В результате объекты, созданные в коде .py, не будут поддерживать откат и не должны изменяться после создания.

В рамках этой трансформации Ren'Py подменяет стандартные классы dict, list и set своими собственными версиями с поддержкой отката. Эти классы являются прямыми наследниками встроенных классов Python, поэтому все стандартные методы работают как обычно. Однако эти классы не пройдут проверку на точное соответствие экземпляру встроенных типов Python.

Чтобы решить эту проблему, Ren'Py предоставляет прямой доступ к оригинальным классам Python:

class python_dict

Класс python_dict — это оригинальный встроенный класс dict языка Python.

class python_list

Класс python_list — это оригинальный встроенный класс list языка Python.

class python_set

Класс python_set — это оригинальный встроенный класс set языка Python.
