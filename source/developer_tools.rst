========================
Инструменты разработчика
========================

Ren'Py включает множество функций, облегчающих жизнь разработчика. Для работы многих
из них необходимо, чтобы переменная :var:`config.developer` имела значение True.

.. _lint:

Инструмент Lint
---------------

Инструмент Lint (доступный из лаунчера) проверяет игру на наличие потенциальных ошибок
или неоптимальных решений и дает рекомендации разработчикам по их исправлению.
Поскольку некоторые из этих проблем могут проявляться только на определенных платформах,
настоятельно рекомендуется понимать и исправлять все найденные предупреждения, даже
если локально ошибка не воспроизводится.

Lint также выводит полезную информацию и статистику о проекте.

Обратите внимание, что использование Lint не заменяет полноценного тестирования игры.

.. _console:

Консоль Shift+O
---------------

Консоль отладки позволяет интерактивно выполнять операторы сценария Ren'Py и выражения
Python, сразу видя результаты. Консоль доступна в режиме разработчика или когда переменная
:var:`config.console` установлена в True; ее можно открыть нажатием клавиш Shift+O.

Консоль можно использовать для:

* Перехода к метке (label).
* Интерактивной проверки операторов сценария Ren'Py.
* Вычисления выражений и выполнения инструкций Python с просмотром результатов.
* Отслеживания изменений выражений Python по ходу игры.

Поддержка редактора Shift+E
---------------------------

Сочетание клавиш Shift+E открывает текстовый редактор по умолчанию (выбранный в лаунчере
и настраиваемый согласно :doc:`editor`), открывая файл сценария на номере строки, где
написан текущий выполняемый оператор.

Меню разработчика Shift+D
-------------------------

Когда переменная :var:`config.developer` равна True, нажатие клавиш Shift+D открывает
меню разработчика, обеспечивающее быстрый доступ ко многим сервисным функциям.

Перезагрузка Shift+R
--------------------

Когда переменная :var:`config.developer` равна True, нажатие клавиш Shift+R сохраняет
текущее состояние игры, перезагружает скрипты и заново загружает игру. Обычно это возвращает
игру к последнему неизмененному оператору, встреченному до нажатия Shift+R.

После первой перезагрузки игра переходит в режим автоматической перезагрузки (autoreload):
любые изменения файлов, к которым обращалась игра с момента прошлой перезагрузки, вызовут
автоматическую перезагрузку игры.

Это позволяет вносить изменения в сценарий во внешнем текстовом редакторе без необходимости
закрывать и перезапускать Ren'Py вручную.

Обратите внимание, что состояние игры (включая значения переменных и списки показанных сцен)
сохраняется при перезагрузке. Это означает, что если изменен оператор, меняющий переменные,
необходимо откатиться назад (rollback) и заново выполнить этот оператор.

Перезагрузка по Shift+R не работает во время повтора сцен (replay).

Инспектор стилей Shift+I
------------------------

Когда :var:`config.developer` равно True, нажатие клавиш Shift+I запускает инспектор стилей.
Под курсором мыши отображается список отображаемых объектов в порядке их отрисовки (самый
верхний объект — в конце списка). Для каждого объекта выводится его тип, используемый стиль
и размеры отрисовки.

Клик по имени стиля отображает стили, от которых данный стиль наследуется, а также свойства,
которые каждый стиль привносит в итоговый отображаемый объект.

Быстрый пропуск (Fast Skipping)
-------------------------------

Когда переменная :var:`config.developer` или :var:`config.fast_skipping` равна True,
нажатие клавиши быстрого пропуска (по умолчанию ``>``) заставляет игру мгновенно
перемотать сценарий до следующего важного взаимодействия. Важным взаимодействием считается
событие, не являющееся оператором say, переходом или командой pause (обычно это следующее
меню выбора или пользовательский интерактивный экран).

.. _warping_to_a_line:

Переход к строке (Warping)
--------------------------

Ren'Py поддерживает переход к заданной строке сценария без необходимости вручную проходить
всю игру от начала. Хотя этот метод имеет ряд ограничений и нюансов, он очень удобен для
быстрого предварительного просмотра разрабатываемой сцены.

Для вызова перемещения запустите Ren'Py с параметром командной строки ``--warp``, указав
комбинацию `имя_файла:строка`. Например::

    renpy.exe my_project --warp script.rpy:458

(где `my_project` — полный путь к базовому каталогу проекта).

При запуске перемещения Ren'Py находит оператор, ближайший к указанной строке (на ней или
перед ней), и строит обратный маршрут от начала игры. Анализируется до ``config.warp_limit``
операторов от конца этого пути. Ren'Py выполняет совместимые операторы (такие как scene,
show и hide) по пути следования, после чего передает управление целевому оператору.

Диалоги персонажей ADV, NVL и речевых пузырей (bubble) также воспроизводятся для
восстановления контекста без ожидания клика пользователя:

* Диалоги ADV добавляют завершенные строки в историю диалогов.
* Диалоги NVL добавляют строки в историю и в список NVL. Команда ``nvl clear`` и параметр
  персонажа ``clear=True`` очищают список NVL без очистки истории.
* Диалоги речевых пузырей добавляют строки в историю, восстанавливают сохраненные пузыри
  и обновляют параметры компоновки. Пузыри очищаются согласно базе данных пузырей и
  переменной :var:`bubble.clear_retain_statements`, включая пропущенные меню и операторы
  ``call screen`` (сами эти операторы при этом не выполняются).

Ограничения на длину истории и списка NVL сохраняют силу. Восстановленные записи истории
не создают контрольных точек отката. Сам целевой оператор не симулируется: он выполняется
в штатном режиме после вызова метки ``after_warp``.

Персонажи поддерживают повтор диалогов при warp по умолчанию; параметр ``Character(..., warp=False)``
отключает его для конкретного персонажа. Другие вызываемые объекты say пропускаются, если
только их атрибут ``warp`` не равен True. Разрешенный объект вызывается стандартно и может
проверять :func:`renpy.is_warping` для предотвращения нежелательных интерактивных побочных
эффектов. Встроенные персонажи подавляют колбэки взаимодействия, хуки голоса и переходы
say во время симуляции, но текстовые фильтры, подстановки, динамические имена и хуки
подготовки персонажей продолжают работать.

Если реплика при warp вызывает обычное исключение, Ren'Py записывает его в лог, игнорирует
этот оператор и продолжает перемещение. Исключения управления потоком движка (Quit, restart)
не игнорируются.

Ограничения функции warp: анализируется только один путь исполнения, игра не вычисляет
сложную логику условий перехода между ветками.

Главная особенность: произвольный код Python перед целевым оператором не выполняется,
поэтому переменные могут остаться неинициализированными. Чтобы обойти это, можно объявить
метку ``after_warp``, которая вызывается после завершения симуляции, но до выполнения целевого
оператора. В ней можно инициализировать необходимые переменные проекта и затем вернуться
по return. Переменные ``default`` остаются доступными во время работы warp.

Переводы используются при полном воспроизведении блоков перевода.

Для работы механизма перемещения по строкам переменная :var:`config.developer` должна быть равна True.

Настройка лаунчера
------------------

Лаунчер Ren'Py можно настроить для отображения нужных файлов и папок проекта. Для этого
создайте файл `project.json` следующего содержания::

    {
        "renpy_launcher":
        {
            "open_directory":
            {
                "game": "game",
                "base": ".",
                "images": "game/images",
                "audio": "game/audio",
                "gui": "game/gui"
            },
            "edit_file":
            {
                "script.rpy": "game/script.rpy",
                "options.rpy": "game/options.rpy",
                "gui.rpy": "game/gui.rpy",
                "screens.rpy": "game/screens.rpy"
            }
        }
    }

Если файл уже существует, добавьте ключ `renpy_launcher` и вложенные структуры. Вы можете
редактировать словари для изменения доступных папок и файлов.
