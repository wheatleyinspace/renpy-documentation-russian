Пользовательские инструкции (CDS)

Пользовательские инструкции (Creator-Defined Statements, CDS) позволяют добавлять собственные инструкции в скриптовый язык Ren'Py. Это даёт возможность расширять синтаксис возможностями, которые не поддерживаются стандартными средствами.

CDS могут быть более гибкими и выразительными, чем прямой эквивалент на чистом Python.

Например, выбор случайной реплики диалога:

label introduction:
    python:
        greetings = ['Hello.', 'Welcome.', 'Can I help you?']
        greeting = renpy.random.choice(greetings)

    "[greeting]"

Парсер Ren'Py заранее не знает, что именно происходит в блоке python или как его следует выполнять. Он ничего не делает с этим кодом до момента непосредственного выполнения и вызовет ошибку, если возникнет исключение.

Использование CDS позволяет вам:

  • Проверять корректность синтаксиса при разборе (например, убедиться, что элементы списка, передаваемого в renpy.random.choice, содержат валидный текст).

  • Игнорировать некорректные данные при выполнении (для некритичных функций зачастую лучше пропустить выполнение, чем вызывать исключение).

  • Предсказывать отображаемые объекты (если функция использует их).

  • Предоставлять дополнительную информацию во время линтинга (Инструмент Lint) (если во время выполнения ошибка была проигнорирована, здесь можно вывести отчёт о ней).

Например, то же поведение, но оформленное в виде CDS:

python early:
    def parse_random(lexer):
        subblock_lexer = lexer.subblock_lexer()
        choices = []

        while subblock_lexer.advance():
            with subblock_lexer.catch_error():
                statement = subblock_lexer.renpy_statement()
                choices.append(statement)

        return choices


    def next_random(choices):
        return renpy.random.choice(choices)


    def lint_random(parsed_object):
        for i in parsed_object:
                check = renpy.check_text_tags(i.block[0].what)
                if check:
                    renpy.error(check)


    renpy.register_statement(
        name="random",
        block=True,
        parse=parse_random,
        next=next_random,
        lint=lint_random,
    )

Теперь random доступен как инструкция языка:

label introduction:
    random:
        "Hello."
        "Welcome."
        "Can I help you?"

Использование CDS само по себе не гарантирует успешности выполнения, но чем качественнее написан разбор вашей инструкции, тем лучше Ren'Py сможет «понять», чего именно вы от неё ожидаете.

Использование

Пользовательские инструкции (CDS) должны подчиняться следующим правилам:

  • Они должны быть определены в блоке python early.

  • Их нельзя использовать в том же файле, где они определены.

  • Файл, содержащий CDS, должен загружаться раньше любого файла, использующего эту инструкцию. (Поскольку Ren'Py загружает файлы в порядке сортировки путей по Unicode, обычно имеет смысл начинать имя файла с CDS с префикса 01 или другого меньшего номера. Подробнее о порядке загрузки файлов Ren'Py с нюансами каталогов game/libs/ и game/mods/ см. в разделе Фаза синтаксического анализа скрипта.)

Пользовательские инструкции регистрируются с помощью функции renpy.register_statement(). Эта функция принимает другие функции, выполняющие различные операции над содержимым CDS.

Например, новая инструкция line, позволяющая указывать реплики текста без кавычек:

line e "These quotes will show up," Eileen said, "and don't need to be backslashed."

Функции parse передаётся содержимое лексера для синтаксического анализа. Функция execute должна выполнять действие над разобранным содержимым. Функция lint должна сообщать о любых ошибках в разобранном содержимом.

python early:
    def parse_smartline(lexer):
        who = lexer.simple_expression()
        what = lexer.rest()
        return (who, what)

    def execute_smartline(parsed_object):
        who, what = parsed_object
        renpy.say(eval(who), what)

    def lint_smartline(parsed_object):
        who, what = parsed_object
        try:
            eval(who)
        except Exception:
            renpy.error("Character not defined: {}".format(who))

        tte = renpy.check_text_tags(what)
        if tte:
            renpy.error(tte)

    renpy.register_statement(
        "line",
        parse=parse_smartline,
        execute=execute_smartline,
        lint=lint_smartline,
    )

Справочник API

renpy.register_statement(name, parse=None, lint=None, execute=None, predict=None, next=None, scry=None, block=False, init=False, translatable=False, execute_init=None, init_priority=0, label=None, warp=None, translation_strings=None, force_begin_rollback=False, post_execute=None, post_label=None, predict_all=True, predict_next=None, execute_default=None, reachable=None)

Регистрирует пользовательскую инструкцию (Creator-Defined Statement).

name

Либо разделённый пробелами список имён, с которых начинается инструкция, либо пустая строка для определения новой инструкции по умолчанию (инструкция по умолчанию заменит инструкцию say).

block

Может принимать одно из следующих значений:

  • False, указывая, что инструкция не ожидает блок.

  • True, указывая, что инструкция ожидает блок и будет выполнять его синтаксический анализ.

  • "possible", указывая, что инструкция может как принимать, так и не принимать блок.

  • "script", указывая, что блок должен интерпретироваться как блок инструкций языка скриптов Ren'Py. См. параметр next касательно реализации передачи управления с помощью этого.

  • "script-possible", обрабатывается как "script", если блок присутствует, и False в противном случае.

  • "atl", указывая, что блок должен интерпретироваться как трансформация ATL. Передаётся в качестве дополнительного аргумента в execute.

  • "atl-possible", обрабатывается как "atl", если блок присутствует, и False в противном случае.

parse

Функция, принимающая объект Lexer. Эта функция должна выполнить синтаксический анализ инструкции и вернуть объект. Этот объект затем передаётся в качестве аргумента во все остальные функции.

lint

Вызывается для проверки инструкции линтером. Принимает один аргумент — объект, возвращённый из parse. Должна вызывать renpy.error для сообщений об ошибках.

execute

Функция, вызываемая при выполнении инструкции. Принимает один аргумент — объект, возвращённый из parse. Если присутствует блок ATL, передаётся именованный аргумент atl с трансформацией ATL.

execute_init

Функция, вызываемая во время инициализации (init time) с приоритетом 0. Принимает один аргумент — объект, возвращённый из parse.

predict

Функция, вызываемая для предсказания изображений, используемых инструкцией. Принимает один аргумент — объект, возвращённый из parse. Должна возвращать список отображаемых объектов, используемых инструкцией.

next

Функция, вызываемая для определения следующей инструкции.

Если block не равен "script", принимает один аргумент — объект, возвращённый функцией parse. Если block равен "script", передаётся дополнительный аргумент — объект, именующий первую инструкцию в блоке.

Функция должна возвращать либо строку с меткой для перехода, либо второй аргумент для передачи управления внутрь блока, либо None для продолжения выполнения инструкции, следующей за данной. Она также может возвращать результат вызова Lexer.renpy_statement() или Lexer.renpy_block() внутри функции parse.

label

Функция, вызываемая для определения метки этой инструкции. Если возвращает строку, эта строка используется в качестве метки инструкции, к которой можно совершать переход (jump) или вызов (call), как к любой другой метке.

warp

Функция, вызываемая для определения того, должна ли эта инструкция выполняться во время перемещения (warp). Если функция существует и возвращает True, она выполняется во время warp; в противном случае инструкция не выполняется во время warp.

scry

Используется внутренними механизмами Ren'Py.

init

True, если эта инструкция должна выполняться во время инициализации. (Если инструкция ещё не находится внутри блока init, она автоматически помещается в блок init.)

Скорее всего, вам это не нужно, если у вас задана функция execute_init, поскольку оборачивание инструкции в блок init приведёт к тому, что execute_init и execute будут вызваны одновременно.

translatable

Если установлено в True, инструкция будет включена в блок перевода, как правило, в блок, содержащий последующую инструкцию say. Может быть установлено в True только для однострочных инструкций. Используется для инструкций вроде nvl clear и voice, которые могут требовать изменения синхронно с диалогом.

init_priority

Целое число, определяющее приоритет инициализации блока init, создаваемого параметрами init и execute_init. Также может быть функцией, принимающей разобранный блок и возвращающей целое число.

translation_strings

Функция, вызываемая с разобранным блоком. Ожидается возврат списка строк или кортежей вида (номер строки, строка), которые затем регистрируются как доступные для перевода.

force_begin_rollback

Следует устанавливать в True для инструкций, которые с большой вероятностью вызывают окончание быстрого пропуска, аналогично menu или call screen.

post_execute

Функция, которая выполняется как часть следующей инструкции после данной. (Добавление функции post_execute изменяет содержимое файла RPYC, что требует принудительной перекомпиляции [Force Compile].)

post_label

Функция, вызываемая для определения метки инструкции post_execute. Если возвращает строку, эта строка используется в качестве метки инструкции, к которой можно совершать вызов и переход, как к любой другой метке. Это можно использовать для создания уникальной точки возврата.

predict_all

Если True, предсказывает все подвыражения (sub-parses) данной инструкции и инструкцию, следующую за данной.

predict_next

Вызывается с единственным аргументом — меткой инструкции, которая будет выполняться после данной.

Должна вызываться для предсказания инструкций, которые могут выполняться после текущей. Ожидается возврат списка меток или объектов SubParse. Не вызывается, если predict_all равно True.

execute_default

Функция, вызываемая одновременно с выполнением инструкций default — после фазы init, но до начала игры; при загрузке сохранения; после отката; перед проверкой линтером; и потенциально в других случаях.

Вызывается с единственным аргументом — объектом, возвращённым из parse.

reachable

Функция, вызываемая для того, чтобы позволить данной инструкции настроить её участие в анализе достижимости линтером (reachability analysis).

По умолчанию пользовательский блок инструкции, блоки подвыражений, созданные с помощью Lexer.renpy_block(), и инструкция, следующая за данной, считаются достижимыми, если достижима сама данная инструкция. Инструкция также достижима, если у неё есть функция label.

Это поведение можно настроить, указав функцию reachable. Эта функция принимает пять аргументов (далее «метка» может быть строкой или специальным объектом):

  • Объект, возвращённый функцией parse.

  • Логическое значение (bool), равное True, если инструкция достижима.

  • Метка инструкции.

  • Метка следующей инструкции или None, если следующей инструкции нет.

  • Если block установлен в "script", метка первой инструкции в блоке или None, если блока нет.

Ожидается возврат множества (set), которое может содержать:

  • Метку или объект subparse инструкции, которая достижима.

  • True, указывая, что эта инструкция не должна сообщаться линтером как недостижимая, но не является внутренне достижимой. (Она станет достижимой, если другая инструкция сообщит о её достижимости.)

  • None, который игнорируется.

Эта функция может вызываться несколько раз с обоими значениями is_reachable, позволяя инструкции настраивать своё поведение в зависимости от того, достижима она или нет. (Например, следующая инструкция может быть достижима только в том случае, если достижима данная.)

Предупреждение

Использование пустой строки в качестве имени для переопределения инструкции say обычно является плохой идеей. Дело в том, что при замене встроенной инструкции Ren'Py её поведение зависит от эквивалентов инструкций (Эквиваленты инструкций на Python). В случае инструкции say эти эквиваленты не поддерживают id и системы перевода. В результате игра, переопределяющая инструкцию по умолчанию, не сможет использовать эти возможности (без их полной повторной самостоятельной реализации).

Объект Lexer

Функция parse пользовательской инструкции принимает экземпляр объекта Lexer.

class Lexer
property init

True, если лексер находится внутри инструкции init, иначе False.

property init_priority

Если init равен True, содержит приоритет блока init.

error(msg)
Параметры:

msg (str) -- Сообщение для добавления в список обнаруженных ошибок синтаксического анализа.

Добавляет msg (с указанием текущей позиции) в список обнаруженных ошибок синтаксического анализа. Это прерывает разбор текущей инструкции, но не препятствует дальнейшему разбору файла.

require(thing, name=None)

Пытается разобрать thing и сообщает об ошибке, если это сделать не удаётся.

Если thing — строка, пытается разобрать её с помощью match().

В противном случае thing должен быть другим методом этого объекта lexer, вызываемым без аргументов.

Если name не указано, в сообщении используется имя метода (или thing, если это строка); в противном случае используется name.

eol()
Результат:

True, если лексер находится в конце строки, иначе False.

Тип результата:

bool

expect_eol()

Вызывает ошибку, если лексер находится не в конце строки.

expect_noblock(stmt)

Вызывается для указания того, что эта инструкция не ожидает блок. Если блок обнаружен, вызывает ошибку. stmt должен быть строкой, которая будет добавлена к сообщению об ошибке.

expect_block(stmt)

Вызывается для указания того, что инструкция требует наличия непустого блока. stmt должен быть строкой, которая будет добавлена к сообщению об ошибке.

has_block()
Результат:

True, если текущая строка содержит непустой блок, иначе False.

Тип результата:

bool

match(re)

Сопоставляет строку с произвольным регулярным выражением.

Все методы сопоставления в лексере реализованы через эту функцию. Сначала они пропускают пробельные символы, затем пытаются сопоставить регулярное выражение со строкой. Если сопоставление успешно, возвращается совпавший текст. В противном случае возвращается None, а состояние лексера остаётся неизменным.

Тип результата:

image_name_component()

string()

Сопоставляет строку Ren'Py в кавычках.

label_name(declare=False)

Сопоставляет имя метки, как абсолютное, так и относительное. Если declare равно True, устанавливается глобальное имя метки. (Обратите внимание, что это не объявляет метку фактически — инструкция должна сделать это, вернув её из функции label.)

simple_expression()

Сопоставляет простое выражение Python и возвращает его в виде строки. Часто используется, когда ожидается имя переменной. Не рекомендуется изменять результат. Правильное действие — вычислить результат в дальнейшем.

delimited_python(delim)

Сопоставляет выражение Python, заканчивающееся разделителем delim, например ':'. Часто используется, когда ожидается условие перед двоеточием. Не рекомендуется изменять результат. Правильное действие — вычислить результат в дальнейшем. Вызывает ошибку, если конец строки достигнут до разделителя.

arguments()

Должен вызываться перед круглыми скобками со списком аргументов. Если скобки не указаны, возвращает None; в противном случае возвращает объект, представляющий аргументы вызова функции. У этого объекта есть метод evaluate, принимающий необязательный словарь scope и возвращающий кортеж, первым элементом которого является кортеж позиционных аргументов, а вторым — словарь именованных аргументов.

rest()

Пропускает пробелы и возвращает оставшуюся часть строки.

checkpoint()

Возвращает непрозрачный объект, представляющий текущее состояние лексера.

revert(o)

Если o — объект, возвращённый из checkpoint(), возвращает состояние лексера к тому, каким оно было при вызове checkpoint(). (Используется для поиска с возвратом / backtracking.)

subblock_lexer()
Результат:

Объект Lexer для блока, связанного с текущей строкой.

advance()

В лексере подблока переходит к следующей строке. Этот метод необходимо вызвать перед первой строкой, чтобы её можно было разобрать. Возвращает True, если успешно выполнен переход к строке в блоке, или False, если пройдены все строки блока.

renpy_statement()

При вызове разбирает текущую строку как инструкцию скрипта Ren'Py, генерируя ошибку, если это невозможно. Возвращает непрозрачный объект, который может быть возвращён функцией next, переданной в renpy.register_statement(), либо передан в renpy.jump() или renpy.call(). Этот объект не следует сохранять, кроме как в качестве части результата разбора инструкции.

Когда инструкция, возвращённая этим методом, завершается, управление передаётся инструкции, следующей за пользовательской инструкцией (которая может быть инструкцией, созданной с помощью post_execute).

renpy_block(empty=False)

Разбирает все оставшиеся строки текущего блока как скрипт Ren'Py и возвращает SubParse, соответствующий первой инструкции в блоке. Блок связывается в цепочку таким образом, что выполняются все инструкции в блоке, а затем управление передаётся инструкции, следующей за данной пользовательской инструкцией.

Обратите внимание, что этот метод разбирает текущий блок. В более типичном случае, когда требуется разобрать подблок текущей инструкции, правильным способом является:

def mystatement_parse(l):

    l.require(':')
    l.expect_eol()
    l.expect_block("mystatement")

    child = l.subblock_lexer().renpy_block()

    return { "child" : child }
empty

Если True, разрешает разбор пустого блока. (Пустой блок эквивалентен блоку с единственной инструкцией pass.)

Если False, пустой блок вызывает ошибку.

catch_error()

Контекстный декоратор, используемый в сочетании с инструкцией with, который перехватывает и выводит ошибки лексера внутри своего контекстного блока, после чего продолжает выполнение после блока.

Вот пример того, как его можно использовать для вывода нескольких ошибок в одном подблоке:

def mystatement_parse(l):

    l.require(':')
    l.expect_eol()
    l.expect_block("mystatement")

    strings = [ ]
    ll = l.subblock_lexer()

    while ll.advance():
        with ll.catch_error():
            strings.append(ll.require(ll.string))
            ll.expect_noblock("string inside mystatement")
            ll.expect_eol()

    return { "strings" : strings }
