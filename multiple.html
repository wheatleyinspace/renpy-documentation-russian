Диалог нескольких персонажей

Ren'Py поддерживает одновременное отображение диалога нескольких персонажей. Совместный диалог вызывается передачей репликам аргумента multiple. Например:

e "Ren'Py поддерживает одновременное отображение нескольких реплик диалога." (multiple=2)
l "Давно пора! Я ждала этого годами." (multiple=2)

Совместный диалог вызывается передачей реплике диалога аргумента multiple с указанием количества объединяемых реплик. (Так, при multiple=3 будут объединены три блока диалога.)

Механизм совместного диалога основан на многократном отображении экрана say с различными стилями. Каждый экземпляр экрана say отвечает за отображение реплики одного персонажа.

Существует несколько ограничений для совместного диалога:

  • При отображении совместного диалога текстовые теги, вызывающие паузу в тексте (например, {p} и {w}), не будут работать должным образом. Это связано с тем, что каждый экран отображается только один раз, тогда как эти теги требуют многократного отображения экрана для своей работы.

  • Режим авточтения работает только для последнего текстового блока. Хотя в большинстве случаев этого достаточно, это может приводить к проблемам, если последний блок текста короче остальных, так как авточтение может сработать раньше времени.

  • Инструкция extend не работает. (Она применится только к последнему блоку текста.)

Стили

В целом совместный диалог работает путём многократного отображения экрана say, при этом стили различных отображаемых объектов систематически переименовываются в соответствии с номером блока и общим количеством блоков.

В частности, совместный диалог использует стили с именами вида blockn_multiplem_stylename, где n — номер блока (начиная с 1, а не с 0), а m — общее количество одновременно отображаемых блоков диалога.

В приведённом выше примере окнам, соответствующим каждому блоку диалога, присваиваются имена:

  • block1_multiple2_say_window

  • block2_multiple2_say_window

Эта схема именования используется для текста диалога, имени персонажа, рамки имени (namebox), а также для самого окна диалога (window). Она спроектирована так, чтобы можно было эффективно использовать наследование стилей. Для стилей окна мы получим:

say_window

Используется в обычном случае одиночного диалогового окна и может служить базовым стилем для всех окон диалога.

multiple2_say_window

Может использоваться для общих свойств обоих диалоговых окон, например изменения фона и уменьшения внешних (margin) и внутренних (padding) отступов.

block1_multiple2_say_window

Может использоваться для позиционирования первого из двух диалоговых окон, например с помощью xalign 0.0 для размещения его в левой части.

block2_multiple2_say_window

Аналогично, может использоваться для позиционирования второго окна, с помощью xalign 1.0 для размещения его в правой части.

Экран multiple_say

Для более тонкого управления существует экран multiple_say. Если он определён, экран multiple_say используется вместо стандартного экрана say. Он принимает третий аргумент, multiple, являющийся кортежем. Первый элемент кортежа — это номер блока, а второй — общее количество экранов.

Режим NVL

По умолчанию в режиме NVL несколько блоков текста отображаются друг над другом. Это поведение можно настроить, изменив экран nvl, которому передаётся список объектов с аргументом multiple, которые можно переупорядочить и отобразить нужным образом.
