.. _displayables:

====================
Отображаемые объекты
====================

Отображаемый объект (displayable) — это объект, который может быть показан
пользователю на экране. Отображаемые объекты Ren'Py могут использоваться
множеством способов:

* Присваивание имени изображения с помощью оператора ``image``.
* Добавление на экран с помощью оператора ``add`` языка экранов.
* Присваивание определённым конфигурационным переменным.
* Присваивание свойствам стилей.

Когда функция или переменная Ren'Py ожидает отображаемый объект, ей можно передать:

* Объект типа Displayable, созданный вызовом одной из описанных ниже функций.
* Строку, содержащую двоеточие ``:``. Это редкий случай, см. раздел
  :ref:`префиксы отображаемых объектов <displayable-prefix>` ниже.
* Строку с точкой ``.``. Такая строка интерпретируется функцией :func:`Image`
  как имя файла изображения.
* Цвет. Цвет может быть задан как шестнадцатеричная строка цвета в формате
  "#rgb", "#rgba", "#rrggbb" или "#rrggbbaa", объект :class:`Color`, либо
  кортеж (r, g, b, a), где каждый компонент — целое число от 0 до 255. Цвета
  передаются в :func:`Solid`.
* Имя изображения. Любая другая строка интерпретируется как ссылка на изображение,
  определённое оператором image или автоматически найденное в :ref:`каталоге images <images-directory>`.
* Список. Если передан список, каждый элемент раскрывается согласно приведённым
  правилам и проверяется на совпадение с именем файла или изображения. При первом
  совпадении перебор прекращается, и найденный элемент обрабатывается, как описано выше.

Строки могут содержать одну или несколько подстановок в квадратных скобках, например
"eileen [mood]" или "eileen_[outfit]_[mood].png". В этом случае создаётся динамическое
изображение (dynamic image). В динамических изображениях :ref:`интерполяция текста
<text-interpolation>` выполняется в начале каждого взаимодействия (такого как операторы
say и меню). Результирующая строка обрабатывается по правилам выше.

Если строка содержит "[prefix\_]", эта подстановка заменяется каждым из префиксов стилей,
ассоциированных с текущим отображаемым объектом.

Изображения
-----------

Наиболее часто используемый отображаемый объект — Image, который загружает файл с диска
и выводит его на экран. Поскольку Image используется повсеместно, при указании строки с
именем файла в контексте, ожидающем displayable, объект Image создаётся автоматически.
Единственный случай, когда требуется вызывать Image напрямую — необходимость создать
изображение со свойствами стиля.

.. include:: inc/im_image

::

    # Эти две строки эквивалентны.
    image logo = "logo.png"
    image logo = Image("logo.png")

    # Использование Image позволяет задать позицию по умолчанию
    # прямо в определении изображения.
    image logo right = Image("logo.png", xalign=1.0)

Рекомендуется использовать четыре формата растровых изображений:

* AVIF
* WEBP
* PNG
* JPG

И один векторный формат:

* SVG

Неанимированные файлы GIF и BMP также поддерживаются, однако не рекомендуются для
использования в современных проектах.

Загрузка Image из файла на диске и его декодирование для вывода на экран занимает
значительное время. Хотя оно измеряется десятыми или сотыми долями секунды, этого
достаточно, чтобы вызвать просадку частоты кадров (FPS) и создать неприятные задержки.

Поскольку Image имеет фиксированный размер и не меняется в ответ на ввод игрока, состояние
игры или размер доступной области, его можно загрузить заранее и поместить в область памяти,
называемую кэшем изображений (image cache). Когда декодированное изображение находится в кэше,
оно мгновенно отрисовывается на экране.

Ren'Py старается предсказывать, какие изображения понадобятся в будущем, и заблаговременно
загружает их в кэш. Когда память в кэше требуется для новых изображений, Ren'Py выгружает
изображения, которые больше не используются.

По умолчанию Ren'Py упреждающе кэширует объём данных, эквивалентный 8 экранам. (Если разрешение
вашего экрана 800x600, один экран данных — это одно изображение 800x600, два 400x600 и т. д.).
Этот объём можно настроить с помощью переменной :var:`config.image_cache_size`.

Хотя точное потребление памяти зависит от платформы и сопутствующих накладных расходов, как
общее правило: каждый пиксель в кэше изображений занимает 4 байта в оперативной памяти и
4 байта в видеопамяти.

Изображения SVG
---------------

Ren'Py поддерживает многие возможности стандарта SVG 1.0 с помощью библиотеки NanoSVG.
Некоторые неподдерживаемые функции:

* Текстовые элементы игнорируются. Если текст преобразован в кривые (контуры/paths), он отрисуется.
* Встроенные растровые изображения игнорируются.
* Скрипты игнорируются.
* Анимации игнорируются.

Список поддерживаемых возможностей NanoSVG можно найти
`здесь <https://core.tcl-lang.org/tips/doc/trunk/tip/507.md>`__.

Рекомендуется преобразовывать в контуры (paths) все элементы SVG-изображения, которые
не отображаются должным образом.

Ren'Py отрисовывает изображения SVG с расчётом на виртуальный экран с разрешением 96 DPI.
При масштабировании окна изображение SVG пропорционально увеличивается или уменьшается, при
этом механизм :ref:`передискретизации (oversampling) <oversampling>` гарантирует чёткость
отрисовки в виртуальном разрешении.

Это обеспечивает высокую резкость векторной графики SVG при отсутствии искажений.

Подобные изображениям объекты
-----------------------------

Эти отображаемые объекты называются «подобными изображениям» (image-like), поскольку они
занимают прямоугольную область экрана и не реагируют на пользовательский ввод. В отличие
от обычных изображений, они могут менять свой размер для заполнения области (Frame, Tile, Solid)
или позволяют явно задавать свои размеры (Composite, Crop, Null). Они не являются манипуляторами изображений.

К подобным изображениям объектам применимы :ref:`позиционные свойства стиля <position-style-properties>`.

.. include:: inc/disp_imagelike

Динамические отображаемые объекты
---------------------------------

Динамические отображаемые объекты показывают дочерний displayable на основе текущего
состояния игры.

Обратите внимание, что динамические отображаемые объекты всегда отображают своё текущее
состояние. Из-за этого они не участвуют в переходах (или, точнее, отображают одно и то же
содержимое как в начальном, так и в конечном состоянии перехода).

По своему назначению динамические объекты рассчитаны на редко меняющиеся элементы и случаи,
когда такое изображение находится за пределами экрана (например, система кастомизации
персонажа). Они не предназначены для часто меняющихся элементов, таких как мимика и эмоции персонажа.

.. include:: inc/disp_dynamic


Отображаемые объекты слоёв
--------------------------

Отображаемые объекты слоёв (Layer displayables) отображают содержимое слоя на основе
состояния игры. Они предназначены для использования с :var:`config.detached_layers`.

Как и в случае с динамическими displayable, отображаемые слои всегда показывают своё
текущее состояние. Поэтому содержимое объекта слоя не участвует в переходах, если переход
не направлен непосредственно на сам этот отображаемый слой.

.. include:: inc/disp_layer

::

    # Новый изолированный слой для трансляции.
    define config.detached_layers += [ "broadcast" ]

    # Отображаемый объект слоя для представления телевизора и показа слоя broadcast.
    image tv = Window(Layer("broadcast"), background='#000', padding=(10, 10), style="default")

    image living_room = Placeholder('bg', text='living_room')
    image studio = Solid('7c7')
    image eileen = Placeholder('girl')

    label example:
        pause

        # Настраиваем сцену трансляции.
        scene studio onlayer broadcast
        with None

        # Начинаем новую сцену в гостиной.
        scene living_room

        # Показываем телевизор в нижнем правом углу экрана.
        show tv:
          align (.75, .75) zoom .3

        # Показываем Айлин в трансляции.
        show eileen onlayer broadcast

        # Растворение в гостиной, пока Айлин выходит в телевизор справа.
        with {'master': dissolve, 'broadcast': moveinright}
        pause


Боксы компоновки и сетки
------------------------

Боксы компоновки (layout boxes) — это отображаемые объекты, размещающие свои дочерние
элементы на экране. Они могут выстраивать дочерние элементы по горизонтали, по вертикали
или размещать их с использованием стандартного алгоритма позиционирования.

Отображаемые объекты боксов принимают любое количество позиционных и именованных аргументов.
Позиционные аргументы должны быть отображаемыми объектами, добавляемыми в бокс как дочерние
элементы. Именованные аргументы — это свойства стилей, применяемые к боксу.

К боксам применимы :ref:`position-style-properties` и :ref:`box-style-properties`.

.. include:: inc/disp_box

::

    # Отображение двух логотипов слева и справа друг от друга.
    image logo hbox = HBox("logo.png", "logo.png")

    # Отображение двух логотипов один над другим.
    image logo vbox = VBox("logo.png", "logo.png")

    # Отображение двух логотипов. Так как оба по умолчанию встают в
    # левый верхний угол экрана, мы используем Image для их позиционирования.
    image logo fixed = Fixed(
        Image("logo.png", xalign=0.0, yalign=0.0),
        Image("logo.png", xalign=1.0, yalign=1.0))


Макет Grid отображает свои дочерние элементы в виде таблицы (сетки). Он принимает
:ref:`position-style-properties` и свойство стиля :propref:`spacing`.

.. include:: inc/disp_grid

Манипуляторы изображений
------------------------

:doc:`Манипуляторы изображений <im>` — это устаревший класс отображаемых объектов,
применяющих трансформации или операции исключительно к другим изображениям или манипуляторам
изображений (за исключением прочих типов displayable).

Манипулятор изображений можно использовать везде, где принимается displayable, но не
наоборот. Объект :func:`Image` является разновидностью манипулятора изображений, поэтому
Image можно использовать везде, где требуется манипулятор.

Их применение носит исторический характер. Большинство манипуляторов изображений, описанных
в прошлом, больше не рекомендуются к использованию: они страдают от внутренних архитектурных
проблем, и в целом (за исключением :func:`im.Data`) отображаемый объект :func:`Transform`
предоставляет аналогичные возможности без этих недостатков.

Полный список манипуляторов изображений приведён в документации по :doc:`манипуляторам изображений <im>`.

Заполнители (Placeholders)
--------------------------

Отображаемый объект Placeholder используется для показа заглушек фона или персонажей.
Заполнители используются автоматически при вызове неопределённого изображения в режиме
разработчика. Их также можно использовать вручную, если стандартные варианты не подходят. ::

    # По умолчанию будет использован заполнитель girl.
    image sue = Placeholder("boy")

    label start:
        show sue angry
        "Sue" "Как поживаешь? А теперь готовься к поражению!"

Префиксы отображаемых объектов
------------------------------

Префиксы отображаемых объектов позволяют разработчикам определять собственные отображаемые
объекты и обращаться к ним в любом месте Ren'Py, где ожидается displayable. Отображаемый объект
с префиксом представляет собой строку с двоеточием. Префикс находится слева от двоеточия,
а аргумент — справа от него. Переменная :var:`config.displayable_prefix` сопоставляет префикс
с функцией. Функция принимает аргумент и возвращает либо displayable, либо None.

Например, префикс big возвращает изображение, увеличенное в два раза по сравнению с оригиналом::

    init -10 python:
        def embiggen(s):
            return Transform(s, zoom=2)

        config.displayable_prefix["big"] = embiggen

Конструкция ``init -10`` гарантирует, что префикс будет определён до любых использующих его изображений.
Затем префикс можно использовать при определении изображений::

    image eileen big = "big:eileen happy"

или в любом другом месте, где требуется displayable.
