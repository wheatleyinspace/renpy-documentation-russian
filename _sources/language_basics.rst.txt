============
Основы языка
============

Прежде чем перейти к описанию языка Ren'Py, необходимо рассмотреть
структуру сценария Ren'Py. Сюда входит то, как файлы разбиваются на
блоки, состоящие из строк, и как эти строки делятся на элементы,
составляющие инструкции.

Файлы
=====

Сценарий игры на Ren'Py формируется из всех файлов в каталоге :file:`game/`,
имеющих расширение :file:`.rpy`. Ren'Py считывает каждый из этих файлов и
использует их содержимое в качестве единого сценария игры.

Как правило, нет никакой разницы между сценарием, написанным в одном большом
файле, и сценарием, разбитым на множество отдельных файлов. Управление внутри
сценария (в том числе между файлами) передаётся с помощью перехода (jump) или
вызова (call) :doc:`метки <label>` в другом файле. Это делает разделение сценария
на файлы вопросом личного удобства: одни авторы предпочитают маленькие файлы
(например, отдельный файл на каждое событие или игровой день), другие — один
цельный файл сценария.

Для ускорения загрузки Ren'Py при запуске компилирует файлы :file:`.rpy`
в файлы :file:`.rpyc`. При изменении файла :file:`.rpy` соответствующий
файл :file:`.rpyc` автоматически обновляется при следующем старте Ren'Py. Однако,
если файл :file:`.rpyc` существует без соответствующего ему файла :file:`.rpy`,
Ren'Py продолжит использовать :file:`.rpyc`. Это может приводить к ошибкам, если
файл :file:`.rpy` был удалён, переименован или перемещён без удаления старого
файла :file:`.rpyc`: содержащийся в нём сценарий всё равно будет выполняться.

Имена файлов должны начинаться с буквы или цифры, но не могут начинаться
с «00», так как такие имена зарезервированы Ren'Py для собственных системных файлов.

Базовый каталог
---------------

Базовый каталог — это каталог, содержащий все файлы, распространяемые
вместе с игрой (хотя обычно не все файлы из базового каталога попадают
в итоговый дистрибутив). См. также: :doc:`build`. Файлы вроде README
следует размещать именно в базовом каталоге.

Базовый каталог создаётся внутри «Каталога проектов» (который настраивается
в лаунчере) при создании новой игры. Например, если каталог проектов называется
:file:`renpygames`, а игра названа «HelloWorld», то базовым каталогом будет
:file:`renpygames/HelloWorld`.

Каталог игры
------------

Каталог игры — это папка с именем «game» внутри базового каталога. Например,
если ваш базовый каталог — :file:`renpygames/HelloWorld`, то каталогом игры
будет :file:`renpygames/HelloWorld/game`.

Каталог игры содержит все файлы, используемые игрой. Он (включая все подкаталоги)
сканируется на наличие файлов :file:`.rpy` и :file:`.rpyc`, которые объединяются
в сценарий игры. Он также сканируется на наличие архивных файлов :file:`.rpa`,
которые автоматически подключаются к игре. Наконец, когда Ren'Py запрашивает
путь к файлу, этот путь (за очень редкими исключениями) указывается относительно
каталога игры (обратите внимание, что :var:`config.searchpath` может изменять пути поиска).

Комментарии
===========

Файл сценария Ren'Py может содержать комментарии. Комментарий начинается с
символа решётки (``#``) и продолжается до конца строки. В качестве исключения,
символ решётки внутри строки не считается началом комментария.

::

    # Это комментарий.
    show black # это тоже комментарий.

    "# Это не комментарий, так как решётка находится внутри строки."

Ren'Py полностью игнорирует комментарии при выполнении, обрабатывая сценарий так,
будто комментариев в нём не было.


Логические строки
=================

Файл сценария делится на :dfn:`логические строки`. Логическая строка
всегда начинается с начала строки в файле. Логическая строка заканчивается
в конце строки файла, за исключением следующих случаев:

* Последним символом строки является обратный слэш (``\``).

* Строка содержит открывающую скобку (``(``, ``{`` или ``[``), для которой
  ещё не встретилась соответствующая закрывающая скобка (соответственно
  \ ``)``, ``}`` или ``]``).

* Конец строки файла пришёлся на середину строки текста — *любой* строки,
  даже в одинарных кавычках (в отличие от правил Python).

Как только логическая строка заканчивается, следующая логическая строка начинается
с начала следующей строки файла.

Большинство инструкций в языке Ren'Py состоят из одной логической строки.

::

   "Это одна логическая строка"

   "Поскольку эта строка содержит строковый литерал, она продолжается,
    даже когда строка файла заканчивается."

   $ a = [ "Из-за скобок эта строка также",
           "занимает более одной строки файла." ]

Пустые строки игнорируются и не считаются логическими строками.


Отступы и блоки
===============

:dfn:`Отступ` — это пробелы в начале каждой логической строки, используемые
для выравнивания инструкций Ren'Py. В Ren'Py отступы должны состоять
исключительно из пробелов (символы табуляции недопустимы).

Отступы используются для объединения инструкций в :dfn:`блоки`. Блок — это
группа строк и, как правило, группа связанных инструкций. Правила разделения
файла на блоки таковы:

* В начале файла открыт базовый блок.

* Новый блок начинается каждый раз, когда логическая строка имеет больший отступ,
  чем предыдущая логическая строка.

* Все логические строки внутри одного блока должны иметь абсолютно одинаковый отступ.

* Блок завершается, когда встречается непустая логическая строка с меньшим
  отступом, чем строки в данном блоке.

Отступы имеют важнейшее значение в Ren'Py, как и в Python, и некорректные
отступы могут вызывать синтаксические или логические ошибки. В то же время,
использование отступов для выражения структуры блоков делает код гораздо
чище и нагляднее, чем в языках с фигурными скобками или ключевыми словами begin/end.

::

    "Эта инструкция и следующая за ней инструкция if являются частью блока."

    if True:

        "Но эта инструкция является частью нового блока."

        "Это тоже часть нового блока."

    "А это снова часть первого блока."

Элементы инструкций
===================

Инструкции Ren'Py состоят из нескольких базовых синтаксических элементов.

:dfn:`Ключевое слово (Keyword)`
    Ключевое слово — это слово, которое должно буквально присутствовать в сценарии
    игры. Ключевые слова обычно служат для обозначения инструкций и свойств.

:dfn:`Имя (Name)`
    Имя начинается с буквы или символа подчёркивания, за которыми следует ноль
    или более букв, цифр и символов подчёркивания. В Ren'Py символы Unicode
    в диапазоне от U+00a0 до U+fffd также считаются буквами.

    .. warning::

        Имена, начинающиеся с одного символа подчёркивания (_), зарезервированы
        для внутреннего использования Ren'Py, если иное не указано в документации.

        Когда имя начинается с двух подчёркиваний (__), но не заканчивается ими,
        оно преобразуется в уникальное имя, привязанное к конкретному файлу.

:dfn:`Имя изображения (Image Name)`
    :dfn:`Имя изображения` состоит из одного или нескольких компонентов, разделённых
    пробелами. Первый компонент имени изображения называется :dfn:`тегом изображения`.
    Второй и последующие компоненты являются :dfn:`атрибутами изображения`. Компонент
    изображения состоит из букв, цифр и символов подчёркивания.

    Например, в имени изображения ``mary beach night happy`` тегом изображения является
    ``mary``, а атрибутами изображения — ``beach``, ``night`` и ``happy``.

    Слова ``at``, ``as``, ``behind``, ``onlayer``, ``with`` и ``zorder`` не могут
    использоваться в качестве частей имени изображения.

:dfn:`Строка (String)`
    Строка начинается с символа кавычки (одного из: ", ' или \`), содержит
    последовательность символов и заканчивается тем же самым символом кавычки.

    Символ обратного слэша (\\) используется для экранирования кавычек, специальных
    символов, таких как % (записывается как \\%), [ (записывается как \\{) и
    { (записывается как \\{). Он также используется для вставки переноса строки
    с помощью последовательности \\n.

    Внутри строк Ren'Py идущие подряд пробелы и переносы строк сжимаются в один
    пробел, если только перед пробелом не стоит обратный слэш. ::

        'Строки не могут содержать свой символ-ограничитель без экранирования.'

        "Между двумя следующими
         словами будет ровно один пробел."

        "Между этими\nсловами будет перевод строки."

        "А между этими\ \ \ словами будет ровно три пробела."

    Поддерживается префикс ``r`` для «сырых» (raw) строк, подчиняющийся тем же
    правилам, что и в Python. Другие префиксы (например, ``u``, ``b`` или ``f``)
    не поддерживаются непосредственно в сценарии Ren'Py. Строки в тройных кавычках,
    как правило, не принимаются там, где ожидается обычная строка, а если
    принимаются, то дают иной результат — см., например, :ref:`режим монолога <monologue-mode>`.

    .. note::

        Это относится к строкам, расположенным *непосредственно* в сценарии Ren'Py,
        например в :ref:`инструкциях say <say-statement>` или :doc:`меню <menus>`.
        Строки внутри :ref:`инструкций python <python-statement>` или в выражениях
        (см. ниже) подчиняются стандартным правилам Python.

:dfn:`Простое выражение (Simple Expression)`
    Простое выражение — это выражение Python, используемое для включения кода
    Python в определённые части сценария Ren'Py. Простое выражение начинается с:

    * Имени.
    * Строки.
    * Числа.
    * Любого выражения Python в круглых скобках.

    За ним может следовать любое количество:

    * Точек, за которыми следует имя.
    * Выражений Python в круглых скобках.

    Например, ``3``, ``(3 + 4)``, ``foo.bar`` и ``foo(42)`` являются простыми
    выражениями. А вот выражение ``3 + 4`` без скобок таковым не является, так
    как простое выражение заканчивается на первом же операторе.

:dfn:`Выражение Python (Python Expression)`
    Выражение Python — это произвольное выражение Python, которое не может
    содержать двоеточие. Они используются для задания условий в инструкциях
    :ref:`if <if-statement>` и :ref:`while <while-statement>`.


Общий синтаксис инструкций
==========================

Большинство инструкций Ren'Py имеют общий синтаксис. За исключением
:ref:`инструкции say <say-statement>`, они начинаются с ключевого слова,
задающего инструкцию. За этим ключевым словом следует параметр, если инструкция
его принимает.

За параметром следует одно или несколько свойств. Свойства могут указываться
в любом порядке, при условии, что каждое свойство указано не более одного раза.
Свойство всегда начинается с ключевого слова. Для большинства свойств за именем
следует один из синтаксических элементов, описанных выше.

Если с инструкцией связан блок кода, строка заканчивается двоеточием (:). В противном
случае строка просто заканчивается.


.. _python-basics:

Синтаксис выражений Python
==========================

.. note::

    Вам необязательно детально изучать этот раздел прямо сейчас. Вы можете пропустить
    его и вернуться к нему позже, если вам встретится непонятный пример или если вы
    захотите глубже понять, как именно работают механизмы под капотом.

Многие части Ren'Py принимают выражения Python. Например, определение нового
персонажа включает вызов функции :func:`Character`. Хотя возможности выражений
Python огромны, для создания базовой игры на Ren'Py требуется лишь небольшая их часть.

Краткий обзор выражений Python:

:dfn:`Целое число (Integer)`
    Целое число — это число без дробной части. ``3`` и ``42`` — целые числа.

:dfn:`Число с плавающей точкой (Float)`
    Число с плавающей точкой — это число с дробной частью (десятичной точкой).
    ``.5``, ``7.`` и ``9.0`` — числа с плавающей точкой.

:dfn:`Строка (String)`
    Строки Python начинаются с " или ' и заканчиваются тем же символом. Символ
    \\ используется для экранирования кавычек и задания спецсимволов, таких как
    перевод строки (\\n). В отличие от строк Ren'Py, стандартные строки Python
    в одну кавычку не могут переноситься на несколько строк файла и не могут
    ограничиваться символом \`.

:dfn:`True, False, None`
    Три специальных логических значения: ``True`` означает истину, ``False`` —
    ложь, а ``None`` представляет отсутствие значения.

:dfn:`Кортеж (Tuple)`
    Кортежи используются для представления коллекций фиксированной длины, где
    важен порядок и количество элементов. Например, двухэлементный кортеж (пара)
    часто представляет ширину и высоту, а четырёхэлементный кортеж (x, y, width, height) —
    прямоугольник.

    Кортежи начинаются с круглой скобки ``(``, состоят из нуля или более выражений
    Python, разделённых запятыми, и заканчиваются круглой скобкой ``)``. В качестве
    особого случая одноэлементный кортеж обязательно должен содержать запятую после
    элемента. Примеры::

        ()
        (1,)
        (1, "#555")
        (32, 24, 200, 100)

:dfn:`Список (List)`
    Списки используются для коллекций, количество элементов в которых может
    изменяться. Список начинается с квадратной скобки ``[``, содержит разделенный
    запятыми перечень выражений и заканчивается скобкой ``]``. Примеры::

        []
        [1]
        [1, 2]
        [1, 2, 3]

:dfn:`Переменная (Variable)`
    Выражения Python могут использовать переменные, хранящие значения, объявленные
    с помощью :ref:`инструкции define <define-statement>` или :ref:`инструкции default <default-statement>`.
    Имя переменной подчиняется правилам составления :dfn:`имён`, описанным в
    разделе :ref:`Элементы инструкций <elements-of-statements>`. Примеры::

        playername
        love_love_points
        trebuchet2_range

:dfn:`Доступ к полю (Field Access)`
    Модули и объекты Python имеют атрибуты (поля), доступ к которым осуществляется
    указанием точки и имени поля после выражения (обычно переменной). Например::

       config.screen_width

    состоит из переменной (config), за которой следует обращение к полю (screen_width).

:dfn:`Вызов (Call)`
    Выражения Python могут вызывать функции, возвращающие значение. Вызов
    начинается с выражения (обычно переменной), за которым следует открывающая
    круглая скобка, разделённый запятыми список аргументов и закрывающая скобка.
    Список аргументов начинается с позиционных аргументов (выражений Python). За
    ними следуют именованные аргументы, состоящие из имени параметра, знака
    равенства и значения. В этом примере::

        Character("Эйлин", type=adv, color="#0f0")

    мы вызываем функцию :func:`Character`. Ей передаётся один позиционный
    аргумент (строка "Эйлин") и два именованных аргумента: ``type`` со значением
    переменной ``adv`` и ``color`` со строковым значением ``"#0f0"``.

    Вызывать можно не только функции, но и любые объекты, поддерживающие вызов —
    такие объекты называют :dfn:`вызываемыми объектами (callables)`.

При чтении документации вам могут встретиться сигнатуры функций следующего вида:

.. function:: Sample(name, delay, position=(0, 0), **properties)

    Демонстрационная функция, которая на самом деле не существует в Ren'Py,
    а используется исключительно в документации в качестве примера.

Эта функция:

* Имеет имя «Sample».
* Имеет два позиционных параметра: `name` и `delay`. В реальной функции типы
  этих параметров были бы разъяснены в сопроводительном описании.
* Имеет один именованный аргумент `position` со значением по умолчанию (0, 0).

Поскольку в конце сигнатуры указано ``**properties``, это означает, что функция
может принимать любые :doc:`свойства стиля <style_properties>` в качестве
дополнительных именованных параметров. Другие специальные обозначения — это
``*args`` (произвольное количество позиционных параметров) и ``**kwargs``
(различные именованные параметры, подробно поясняемые в описании функции).

Когда в сигнатуре функции встречается одиночный символ ``/``, это означает, что
все параметры перед ним являются исключительно позиционными и не могут передаваться
по имени. Когда же встречается одиночный символ ``*``, это означает, что все
параметры *после* него являются исключительно именованными и могут передаваться
только с явным указанием синтаксиса ``имя=значение``.

Возможности Python выходят далеко за рамки этого руководства. Для более глубокого
изучения мы рекомендуем официальный учебник Python, доступный на
`python.org <https://docs.python.org/tutorial/index.html>`__. Хотя глубокое знание
Python вовсе не обязательно для работы с Ren'Py, понимание базовых инструкций
и выражений очень пригодится при разработке игр.
