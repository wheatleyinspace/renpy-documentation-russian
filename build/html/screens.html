Экраны и язык экранов

Все, что пользователь видит в игре Ren'Py, можно разделить на изображения и пользовательский интерфейс. Изображения отображаются для пользователя с помощью операторов scene, show и hide и обычно являются частью рассказываемой истории. Все остальное, что видит пользователь, относится к пользовательскому интерфейсу, который настраивается с помощью экранов (screens).

Экраны могут отображаться четырьмя способами:

  • Неявно, при выполнении операторов сценария. Например, оператор say приводит к отображению экрана say.

  • Автоматически. Например, Ren'Py отображает экран main_menu при запуске игры или при возврате пользователя в главное меню.

  • В качестве действия, связанного с кнопкой, кнопкой мыши или клавишей клавиатуры. По умолчанию экран save отображается, когда пользователь нажимает правую кнопку мыши или клавишу Escape. Также можно определить экранную кнопку, отображающую экран save.

  • Явно, с помощью операторов, предназначенных для показа экранов.

Одновременно может отображаться более одного экрана.

Экраны выполняют две основные функции. Первая — отображение информации пользователю. Информация может выводиться с помощью текста, полос и изображений. Часть информации, отображаемой таким образом, жизненно важна для игрового процесса. Экран say, например, используется для показа диалога пользователю, включая имя персонажа и его реплику.

Вторая функция экрана — предоставление пользователю возможности взаимодействовать с игрой. Кнопки и полосы позволяют пользователю вызывать действия и настраивать значения. Ren'Py включает в себя набор предопределенных действий, позволяющих продвигаться по игре, управлять настройками, сохранять и загружать игру и вызывать множество других операций. Создатель игры также может писать новые действия на Python.

Экраны обновляются в начале каждого взаимодействия (interaction) и каждый раз при перезапуске взаимодействия. Обратите внимание, что оператор with None не вызывает взаимодействия и, следовательно, не обновляет экран. Для вызова взаимодействия при необходимости достаточно использовать with Pause(0).

С каждым экраном связана область видимости (scope), задающая значения некоторым переменным. В экранах существуют различные виды переменных, разрешение которых происходит в следующем порядке:

  • В первую очередь проверяются локальные переменные. Они существуют только в экране, который включается в другой экран с помощью оператора use, а не отображается (или вызывается) сам по себе. Они очень похожи на экранные переменные (см. ниже) и создаются тем же способом, за исключением того, что локальные переменные доступны только используемому экрану. Они задаются с помощью действия SetLocalVariable и других действий либо через блок или строку Python в используемом экране. Действия вроде SetScreenVariable не будут работать с локальными переменными.

    • Локальные параметры — это параметры, принимаемые используемым экраном. Они находятся в той же области видимости, что и локальные переменные, и подчиняются тем же правилам и ограничениям, что и параметры экрана (см. ниже).

  • Если имя не может быть разрешено среди локальных переменных (или если мы находимся не в экране, используемом другим экраном), поиск имени производится среди экранных переменных. Это переменные, созданные с помощью операторов Default или Python внутри экрана верхнего уровня. Экранные переменные могут устанавливаться через действие SetScreenVariable, среди прочих, либо через блок или строку Python в экране верхнего уровня, или в любом используемом экране, если локальная переменная с таким именем отсутствует.

    • Параметры экрана (то есть значения, определенные и переданные через круглые скобки оператора screen) находятся в той же области видимости, что и экранные переменные (то есть они не могут иметь одинаковые имена), но их нельзя задавать или изменять через действия, поскольку они будут сбрасываться до исходных значений в произвольные моменты времени, включая каждый раз при выполнении действия. Поэтому, если бы их значение было изменено через действие SetScreenVariable (или любое другое действие), оно было бы немедленно сброшено после этого. Это также относится к переменным, определенным во внутриэкранных блоках Python, так как эти блоки выполняются в произвольные моменты времени, в отличие от внутриэкранного оператора default, который выполняется только в момент отображения экрана.

  • В последнюю очередь имя переменной ищется в общем хранилище (store), где находятся все глобальные переменные Ren'Py. Такие переменные могут устанавливаться с помощью действия SetVariable, среди прочих.

Примечание

Если вам нужно, чтобы действие изменяло переменную внутри экрана, и вы хотите, чтобы этот экран иногда отображался напрямую, а иногда использовался внутри другого экрана, используйте SetLocalVariable. Это менее эффективно, но будет работать в обоих случаях.

Экраны не должны вызывать побочных эффектов, видимых за пределами экрана. Ren'Py выполняет экран несколько раз по мере необходимости. Он запускает экран в процессе предсказания изображений перед тем, как экран будет впервые показан. Поэтому, если выполнение экрана имеет побочные эффекты, они могут происходить в непредсказуемые моменты времени.

Использование генераторов Python в экранах может привести к непредсказуемым результатам. Это связано с особенностями того, как интерпретатор Python компилирует исходный код Python, используемый в контексте экрана. Генераторы можно использовать в функциях Python, вызываемых из экрана, но не в самом коде экрана.

Язык экранов

Язык экранов представляет собой преимущественно декларативный способ отображения экранов. Он состоит из оператора, объявляющего новый экран, операторов, добавляющих отображаемые объекты на этот экран, и управляющих операторов.

Вот пример экрана:

screen say(who, what):
    window id "window":
        vbox:
            spacing 10

            text who id "who"
            text what id "what"

Первая строка — это оператор screen языка Ren'Py, используемый для объявления экрана. Имя экрана — say, поэтому именно этот экран используется для отображения диалога. Он принимает два параметра: who (кто говорит) и what (что говорит).

Экран содержит окно (window), которому присвоен идентификатор (id) "window". Это окно содержит вертикальный блок (vbox) с интервалом между элементами в 10 пикселей. Внутри находятся два текстовых поля: одно отображает имя говорящего, а второе — произносимый текст.

Синтаксис языка экранов

Большинство операторов языка экранов имеют общий синтаксис. (Некоторые управляющие операторы имеют другие синтаксические конструкции.) Оператор начинается в начале строки с ключевого слова, задающего данный оператор.

Если оператор принимает параметры, они следуют непосредственно за ключевым словом. Параметры представляют собой простые выражения, разделенные пробелами, если не указано иное.

За позиционными параметрами следует список свойств. Свойство состоит из имени свойства и следующего за ним значения свойства. Значения свойств являются простыми выражениями, если не указано иное. Список свойств представляет собой разделенный пробелами список таких свойств.

Если оператор заканчивается двоеточием :, он принимает блок строк с отступом. Каждая строка в блоке может представлять собой одно из двух:

  • Список свойств.

  • Оператор языка экранов.

Оператор screen

Оператор screen — это оператор языка сценариев Ren'Py, используемый для объявления нового экрана. Он разбирается по общему синтаксису языка экранов.

Он принимает один параметр — имя экрана. Это имя, а не выражение. Оператор принимает следующие свойства:

modal

Если True, экран является модальным. Модальный экран блокирует взаимодействие пользователя с отображаемыми объектами под ним, за исключением раскладки клавиш по умолчанию. Оценивается один раз при запуске игры.

sensitive

Выражение, определяющее, чувствителен ли экран к взаимодействию. Это выражение вычисляется как минимум один раз за каждое взаимодействие.

tag

Разбирается как имя, а не выражение. Задает тег, связанный с этим экраном. Показ экрана заменяет другие экраны с тем же тегом. Это используется, например, для гарантии того, что в одном и том же контексте одновременно отображается только один экран меню.

zorder

Управляет тем, насколько близко к пользователю отображается экран (глубина по оси Z). Чем больше число, тем ближе экран к пользователю. По умолчанию 0.

variant

Если присутствует, должен быть строкой или списком строк, определяющим вариант экрана. См. Варианты экранов.

style_prefix

Строка, задающая префикс стиля для дочерних элементов этого экрана, как описано ниже.

layer

Строка, задающая имя слоя, на котором экран отображается по умолчанию.

roll_forward

Если True, перемотка вперед (roll forward) будет включена, когда экран используется в операторе call screen. Если False, перемотка вперед отключена; если None или не указано, используется значение config.call_screen_roll_forward.

При перемотке вперед из оператора call screen возвращаемые значения и финальные переходы (jumps) сохраняются, но другие побочные эффекты не возникают. Это означает, что если экран содержит только действия Jump() и Return(), включение roll_forward безопасно. Другие действия могут иметь побочные эффекты, которые не произойдут при перемотке вперед.

Если первой строкой экрана является строка Python, она используется в качестве строки документации (docstring) для экрана. Докстринг можно получить с помощью renpy.get_screen_docstring().

screen hello_world():
     """
     Отображает приветственное сообщение hello world.
     """

     tag example
     zorder 1
     modal False

     text "Hello, World."

Экран может принимать список параметров:

screen center_text(s, size=42):
     text s size size

Если экран не имеет параметров, ему все равно следует передавать пустые круглые скобки. Если какой-либо другой экран использует оператор use для вызова экрана без скобок, разница в поведении описана в разделе оператор use. Если ни один другой экран не вызывает данный экран через use, отсутствие круглых скобок приводит к чистой неэффективности внутренней работы Ren'Py, см. раздел оптимизации экранов относительно параметров.

Операторы пользовательского интерфейса

Операторы пользовательского интерфейса создают отображаемые объекты и добавляют их либо на экран, либо во вмещающий отображаемый объект. Они позволяют выводить информацию, взаимодействовать с игрой или реагировать на различные события.

Все операторы пользовательского интерфейса принимают следующие общие свойства:

at

Это может быть трансформация, список трансформаций или анонимная трансформация (трансформация, определенная непосредственно в блоке at)

transform hello_t:
    align (0.7, 0.5) alpha 0.0
    linear 0.5 alpha 1.0

screen hello_title():
    text "Привет." at hello_t
    text "Привет." at transform:
        align (0.2, 0.5) alpha 0.0
        linear 0.5 alpha 1.0

Эти трансформации используются для оборачивания данного отображаемого объекта. Внешние события show, hide, replace и replaced передаются трансформации тогда и только тогда, когда она добавлена непосредственно на экран.

Например, если vbox обернут в трансформацию и добавлен непосредственно на экран, события передаются этой трансформации. Но если трансформация оборачивает textbutton, добавленный внутрь этого vbox, этой второй трансформации события не передаются.

Один оператор может иметь одновременно как свойство at, так и блок at transform. Свойство должно идти первым и применяется первым.

screen title():
    add "title background":
        at sepia

    text "Название игры":
        at sepia, truecenter
        at transform:
            alpha 0.0
            linear 0.5 alpha 1.0
default_focus

Если указано и True, отображаемый объект получает фокус по умолчанию. Когда несколько отображаемых объектов имеют это свойство, их значения сравниваются, и объект с наибольшим значением default_focus становится выбранным по умолчанию.

Фокус по умолчанию используется только тогда, когда последнее взаимодействие не было щелчком мыши, движением мыши или касанием сенсорного экрана.

extra_alt

Используется для указания дополнительного текста голосового дублирования (alt-текста) для Голосовое сопровождение интерфейса (Self-Voicing). Если задано, дополнительный текст произносится игроку при нажатии клавиши '?', когда самоозвучивание включено.

Свойство extra_alt наследуется всеми дочерними элементами отображаемого объекта, если у них не задан более конкретный extra_alt.

Дополнительный текст предназначен для предоставления слабовидящим игрокам дополнительной информации о группах элементов интерфейса.

focus

Принимает строку или целое число и присваивает имя отображаемому объекту для целей фокусировки. Ren'Py ищет структурное сходство между именами фокуса при выборе объекта для передачи фокуса в начале взаимодействия. Если блоку присвоено имя фокуса, и третья кнопка в этом блоке находилась в фокусе в конце взаимодействия, то третья кнопка блока с таким же именем будет выделена в начале следующего взаимодействия.

group_alt

Используется для указания префикса группы для Голосовое сопровождение интерфейса (Self-Voicing). При включенном самоозвучивании префикс группы произносится в первый раз, когда объект с этим префиксом группы получает фокус, но не повторяется, пока не будет сфокусирован объект с другим префиксом группы.

Свойство group_alt наследуется всеми дочерними элементами, если у них не задано собственное значение group_alt.

id

Идентификатор для оператора пользовательского интерфейса. При отображении экрана значения свойств могут быть переданы отображаемым объектам с заданным идентификатором. Некоторые экраны требуют обязательного создания отображаемого объекта с определенным идентификатором.

Когда отображаемый объект создается с id, идентификатор сохраняется как строка в атрибуте с именем id объекта Displayable.

prefer_screen_to_id

Если True, когда свойство задано как экраном, так и через идентификатор отображаемого объекта, используется свойство экрана. Если False (по умолчанию), используется свойство отображаемого объекта. (Это может использоваться для определения того, переопределяет ли экран свойства, установленные объектом Character.)

style

Строка, задающая имя стиля, применяемого к этому отображаемому объекту. Стиль определяет значения по умолчанию для свойств стиля.

style_prefix

Задает префикс для стиля этого отображаемого объекта и всех его дочерних элементов, если только у этих дочерних элементов не задан более конкретный стиль или префикс стиля.

Имя стиля формируется путем объединения префикса стиля, знака подчеркивания и суффикса стиля. Суффикс стиля либо указывается с помощью style_suffix, либо определяется самим отображаемым объектом.

Например, если у vbox задан префикс стиля "pref", объекту vbox будет присвоен стиль "pref_vbox". Если не задан более конкретный стиль или префикс стиля, кнопка внутри этого vbox получит стиль "pref_button".

Стили, к которым обращаются таким образом, создаются автоматически, если стиль еще не существует. Установка префикса в None удаляет префикс у данного отображаемого объекта и его дочерних элементов.

style_group

Псевдоним для style_prefix, использовавшийся в старых версиях Ren'Py.

style_suffix

Задает суффикс, который объединяется с style_prefix для генерации имени стиля. Если указано "small_button", а префикс стиля равен "pref", будет использоваться стиль "pref_small_button".

Если префикс стиля не используется, это значение применяется непосредственно как имя стиля. Суффикс стиля применяется только к одному отображаемому объекту, а не к объекту и всем его потомкам.

tooltip

Назначает всплывающую подсказку (tooltip) этому отображаемому объекту. Когда объект получает фокус, значение этого свойства становится доступным через функцию GetTooltip(). Дополнительные сведения см. в разделе Всплывающие подсказки (Tooltips).

Объекты, передаваемые в tooltip, должны поддерживать сравнение на равенство. Если равенство не поддерживается, может произойти бесконечный цикл.

arguments

Кортеж или список, содержащий дополнительные позиционные аргументы, передаваемые отображаемому объекту.

properties

Словарь, содержащий дополнительные свойства, передаваемые отображаемому объекту.

Многие операторы пользовательского интерфейса принимают группы свойств стиля или свойств трансформации. К этим свойствам может быть применен префикс стиля, определяющий, когда они действуют. Например, если тексту задано свойство hover_size, оно определяет размер текста при наведении курсора.

Операторы пользовательского интерфейса принимают предложение as, за которым следует имя переменной без кавычек. Отображаемый объект, создаваемый оператором, присваивается этой переменной. (Пример можно найти в документации по drag and drop.)

Bar

Создает горизонтальную полосу, которую можно использовать для просмотра или изменения данных. Принимает следующие свойства:

value

Текущее значение полосы. Может быть либо объектом значения полосы, либо числом.

range

Максимальное значение полосы. Требуется, если value является числом. Игнорируется, если value — объект значения полосы.

adjustment

Объект ui.adjustment(), который настраивает эта полоса.

changed

Если указано, должно быть функцией Python. Функция вызывается со значением регулировки при ее изменении.

hovered

Действие, выполняемое при получении полосой фокуса.

unhovered

Действие, выполняемое при потере полосой фокуса.

released

Действие, выполняемое при отпускании кнопки мыши на полосе. Вызывается даже в том случае, если значение полосы не изменилось.

action

Действие, выполняемое при изменении значения полосы.

Обязательно должно быть указано одно из двух: value или adjustment. Кроме того, эта функция принимает:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля полос (Bar)

Не принимает дочерних элементов.

screen volume_controls():
    frame:
        has vbox

        bar value Preference("sound volume") released Play("sound", "audio/sample_sound.ogg")
        bar value Preference("music volume")
        bar value Preference("voice volume")

Button

Создает область экрана, которую можно активировать для выполнения действия. Кнопка не принимает позиционных параметров и поддерживает следующие свойства:

action

Действие, выполняемое при активации кнопки. Кнопка активируется при клике по ней мышью или при выборе с клавиатуры и нажатии Enter. Это свойство также управляет чувствительностью кнопки, если свойство sensitive не указано или равно None, и тем, выбрана ли кнопка, если selected не указано или равно None.

alternate

Действие, выполняемое при альтернативной активации кнопки. Альтернативная активация происходит при щелчке правой кнопкой мыши на ПК или при долгом нажатии на сенсорных устройствах.

hovered

Действие, выполняемое при получении кнопкой фокуса.

unhovered

Действие, выполняемое при потере кнопкой фокуса.

selected

Выражение, определяющее, выбрана ли кнопка в данный момент. Это выражение вычисляется как минимум один раз за каждое взаимодействие. Если не указано или равно None, состояние выбора определяется действием (action).

sensitive

Выражение, определяющее, чувствительна ли кнопка к нажатию. Вычисляется как минимум один раз за каждое взаимодействие. Если не указано или равно None, чувствительность определяется действием (action).

keysym

Строка, задающая символ клавиши (keysym), описывающий клавишу клавиатуры, нажатие которой вызывает действие этой кнопки.

alternate_keysym

Строка, задающая символ клавиши (keysym), описывающий клавишу клавиатуры, нажатие которой вызывает альтернативное действие этой кнопки.

Также принимает:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля окон

  • Свойства стиля кнопок

Принимает один дочерний элемент. Если указано ноль, два или более дочерних элементов, они неявно оборачиваются в fixed, который затем добавляется в кнопку.

Dismiss

Оператор dismiss создает узкоспециализированный отображаемый объект dismiss, который получает фокус, когда ни один другой объект не находится в фокусе, и выполняет действие при своей активации. В этом отношении он работает аналогично поведению оператора say.

Используется редко, в основном для закрытия модального фрейма при клике пользователя за его пределами, как во всплывающих окнах.

Принимает следующие свойства:

action

Действие, выполняемое при активации dismiss. Это свойство обязательно.

keysym

Строка, задающая символ клавиши (keysym), описывающий клавишу, нажатие которой вызывает действие dismiss. Заменяет стандартный keysym "dismiss".

modal

По умолчанию dismiss является модальным, предотвращая обработку событий отображаемыми объектами «позади» него.

Также принимает:

  • Общие свойства

  • Свойства стиля hover_sound и activate_sound.

Пример использования dismiss:

screen dismiss_test():

    dismiss action Return()

    frame:
        modal True
        align (.5, .3)
        padding (20, 20)

        has vbox

        text "Это очень важное сообщение.":
            xalign 0.5
            textalign 0.5

        # Dismiss сам по себе может быть неочевиден, поэтому добавим и кнопку.
        textbutton "Закрыть":
            xalign 0.5
            action Return()

См. также использование dismiss совместно с nearrect.

Fixed

Создает область, в которую можно добавлять дочерние элементы. По умолчанию fixed расширяется, заполняя всю доступную область, однако свойства xmaximum и ymaximum могут изменить этот размер.

Дочерние элементы размещаются в соответствии с их свойствами стиля позиционирования. При неправильном позиционировании они могут перекрывать друг друга.

Оператор fixed не принимает параметров и поддерживает следующие группы свойств:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля Fixed

Принимает любое количество дочерних элементов, добавляемых внутрь fixed.

Часто нет необходимости явно создавать объект fixed. Каждый экран уже заключен внутрь объекта fixed, и многие операторы языка экранов автоматически создают fixed, если им передано два или более дочерних элемента.

screen ask_are_you_sure:
    fixed:
         text "Вы уверены?" xalign 0.5 yalign 0.3
         textbutton "Да" xalign 0.33 yalign 0.5 action Return(True)
         textbutton "Нет" xalign 0.66 yalign 0.5 action Return(False)

Frame

Фрейм (кадр) — это окно, содержащее фон, предназначенный для отображения элементов пользовательского интерфейса, таких как кнопки, полосы и текст. Принимает следующие группы свойств:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля окон

Принимает один дочерний элемент. Если передано ноль, два или более дочерних элементов, для их размещения создается fixed.

screen test_frame():
    frame:
        xpadding 10
        ypadding 10
        xalign 0.5
        yalign 0.5

        vbox:
            text "Режим экрана"
            null height 10
            textbutton "Полноэкранный" action Preference("display", "fullscreen")
            textbutton "Оконный" action Preference("display", "window")

Grid

Отображает свои дочерние элементы в виде сетки (таблицы). Каждому дочернему элементу выделяется область одинакового размера, равная размеру самого крупного элемента.

Принимает два параметра: количество столбцов и количество строк в сетке. Если сетка заполнена не полностью, оставшиеся ячейки заполняются объектом null.

Grid принимает несколько свойств, управляющих размещением дочерних элементов:

transpose

Если False (по умолчанию), сначала заполняются строки, затем столбцы. Если True, сначала заполняются столбцы, затем строки.

right_to_left

Если True, ячейки заполняются справа налево вместо стандартного направления слева направо.

bottom_to_top

Если True, ячейки заполняются снизу вверх вместо стандартного направления сверху вниз.

Также принимает:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля сеток (Grid)

Должно быть передано ровно (столбцы * строки) дочерних элементов. Передача другого количества дочерних элементов вызовет ошибку.

screen grid_test:
     grid 2 3:
         text "Верх-Лево"
         text "Верх-Право"

         text "Центр-Лево"
         text "Центр-Право"

         text "Низ-Лево"
         text "Низ-Право"

Hbox

Отображает свои дочерние элементы рядом друг с другом в невидимом горизонтальном блоке. Не принимает параметров и поддерживает следующие группы свойств:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля блоков (Box)

Дочерние отображаемые элементы интерфейса добавляются в блок.

screen hbox_text():
    hbox:
         text "Слева"
         text "Справа"

Imagebutton

Создает кнопку, состоящую из изображений, меняющих свое состояние при наведении курсора. Не принимает параметров и поддерживает следующие свойства:

auto

Используется для автоматического определения изображений кнопки. Должно быть строкой, содержащей подстановку %s. Если это так, и одно из свойств изображений не указано, %s заменяется именем этого свойства, и полученное значение используется как путь к файлу по умолчанию.

Например, если auto равно "button_%s.png", а idle опущено, для idle по умолчанию будет использоваться "button_idle.png". Аналогично, если auto равно "button %s", используется изображение с тегом button idle.

Поведение auto можно переопределить через функцию config.imagemap_auto_function.

insensitive

Изображение, используемое, когда кнопка нечувствительна к нажатию.

idle

Изображение, используемое, когда кнопка не в фокусе.

hover

Изображение, используемое при наведении курсора на кнопку.

selected_idle

Изображение, когда кнопка выбрана и не находится в фокусе.

selected_hover

Изображение, когда кнопка выбрана и на нее наведен курсор.

action

Действие, выполняемое при активации кнопки. Также управляет чувствительностью кнопки (если sensitive не задано или None) и ее выбранным состоянием (если selected не задано или None).

alternate

Действие, выполняемое при альтернативной активации кнопки (ПКМ или долгое касание).

hovered

Действие, выполняемое при получении кнопкой фокуса.

unhovered

Действие, выполняемое при потере кнопкой фокуса.

selected

Выражение, определяющее, выбрана ли кнопка. Вычисляется как минимум один раз за каждое взаимодействие.

sensitive

Выражение, определяющее чувствительность кнопки к взаимодействию.

keysym

Строка с символом клавиши (keysym), нажатие которой активирует кнопку.

alternate_keysym

Строка с символом клавиши (keysym), нажатие которой активирует альтернативное действие кнопки.

Также принимает:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля окон

  • Свойства стиля кнопок

Не принимает дочерних элементов.

screen gui_game_menu():
     vbox xalign 1.0 yalign 1.0:
          imagebutton auto "save_%s.png" action ShowMenu('save')
          imagebutton auto "prefs_%s.png" action ShowMenu('preferences')
          imagebutton auto "skip_%s.png" action Skip()
          imagebutton auto "afm_%s.png" action Preference("auto-forward mode", "toggle")

Input

Создает область ввода текста, позволяющую пользователю вводить текст. При нажатии Enter введенный текст возвращается взаимодействием. (Когда экран вызывается через call screen, результат помещается в переменную _return.)

В силу ограничений используемых библиотек на Android и веб-платформе ввод текста ограничен базовыми буквенно-цифровыми символами.

Оператор input не принимает позиционных параметров и поддерживает следующие свойства:

value

Объект значения ввода, используемый этим полем ввода. Объекты InputValue определяют, откуда берется значение по умолчанию, что происходит при изменении текста, что происходит при нажатии Enter и доступен ли текст для редактирования по умолчанию.

Не следует указывать одновременно с default и changed.

default

Текст по умолчанию в данном поле ввода.

length

Максимальная длина текста в символах.

pixel_width

Максимальная ширина поля ввода в пикселях. Если ввод символа приведет к превышению этой ширины, нажатие клавиши игнорируется.

allow

Строка символов, разрешенных для ввода в это поле. (По умолчанию разрешены все символы.)

exclude

Строка символов, запрещенных для ввода. (По умолчанию "{}".)

copypaste

Если True, в поле ввода становится доступно копирование и вставка. (По умолчанию отключено.)

prefix

Неизменяемая строка, добавляемая перед введенным пользователем текстом.

suffix

Неизменяемая строка, добавляемая после введенного пользователем текста.

changed

Функция Python, вызываемая с текущим введенным текстом при каждом его изменении.

mask

Если указано, строка, заменяющая каждый отображаемый символ в тексте (например, для маскирования пароля).

caret_blink

Если не False, период мигания каретки ввода по умолчанию. Переопределяет config.input_caret_blink.

multiline

Если True, появляется возможность перевода каретки на новую строку с клавиатуры (по умолчанию Shift+Enter, настраивается через config.keymap['input_next_line']).

action

Nearrect

Оператор nearrect принимает один дочерний элемент и размещает его рядом с прямоугольником. Обычно это прямоугольник фокуса, зафиксированный действием CaptureFocus(). Это можно использовать для всплывающих подсказок, контекстных или выпадающих меню.

Nearrect принимает следующие свойства:

rect

Если указано, должен быть прямоугольником (x, y, w, h), относительно которого позиционируется дочерний элемент.

focus

Если указано, строка. Эта строка передается эквиваленту функции GetFocusRect() для поиска прямоугольника. Если прямоугольник фокуса с таким именем найден, дочерний элемент отображается.

Передача значения "tooltip" использует координаты последнего отображаемого объекта, находившегося в фокусе при показе подсказки.

Если указано, переопределяет rect.

preferred_side

Одно из значений: "left", "top", "right", "bottom", определяющее предпочтительную сторону размещения nearrect. Если на указанной стороне недостаточно места, используется противоположная сторона. По умолчанию "bottom".

prefer_top

Устарело. Эквивалентно preferred_side "top".

invert_offsets

Если True, и на предпочтительной стороне недостаточно места, смещения xoffset и yoffset умножаются на -1, так как дочерний элемент окажется на противоположной стороне прямоугольника. По умолчанию False.

Также принимает:

  • Общие свойства

  • Свойства стиля позиционирования

Nearrect отличается от других контейнеров тем, что он размещает дочерний элемент рядом с заданным прямоугольником, а не внутри него. Для preferred_side со значением "top" или "bottom" (соответственно "left", "right") дочерний элемент сначала рендерится с полной доступной шириной (соответственно высотой) и максимальной доступной высотой (соответственно шириной) выше и ниже прямоугольника. Затем вычисляется положение по Y (соответственно по X) следующим образом:

  • Если элемент помещается на preferred_side прямоугольника, он размещается вплотную к нему.

  • В противном случае, если он помещается с противоположной стороны, он размещается там.

  • В противном случае элемент размещается вплотную к предпочтительной стороне (preferred_side).

Позиционирование по X (соответственно по Y) вычисляется по обычным правилам с использованием свойств xpos и xanchor (соответственно ypos, yanchor) дочернего элемента и свойств, задающих их (таких как xalign). Свойства позиции отсчитываются от координаты X (соответственно Y) прямоугольника, а при передаче числа с плавающей запятой — от его ширины (соответственно высоты).

В конце позиционирования свойства xoffset и yoffset применяются как обычно.

Если дочерним элементом nearrect является трансформация, ей передаются события show и hide. Однако положение изменится мгновенно. Nearrect лучше всего размещать на верхнем уровне экрана, применяя трансформации и позиционирование к его дочернему элементу, а не к самому nearrect.

Один из вариантов использования nearrect — выпадающие меню:

default difficulty = "Обычная"

screen select_difficulty():

    # Этот фрейм при необходимости может иметь сложный макет.
    frame:
        align (.5, .3)
        padding (20, 20)

        has vbox

        # Кнопка, нажатие которой открывает выпадающее меню
        textbutton "Сложность: [difficulty]":

            # Это действие захватывает прямоугольник фокуса и тем самым
            # открывает выпадающее меню.
            action CaptureFocus("diff_drop")

        textbutton "Готово":
            action Return()

    # Здесь могут быть любые другие элементы экрана, но nearrect должен
    # быть на верхнем уровне и отображаться последним (кроме своего потомка).

    # Отображаем выпадающее меню, только если фокус был захвачен.
    # Вместо обычного if можно использовать showif
    if GetFocusRect("diff_drop"):

        # Если пользователь кликает вне меню, закрываем его.
        # Действие ClearFocus закрывает данное выпадающее меню.
        dismiss action ClearFocus("diff_drop")

        # Размещает элемент рядом (обычно под) кнопкой выше.
        nearrect:
            focus "diff_drop"

            # Наконец, этот фрейм содержит варианты выбора в меню,
            # каждый из которых использует ClearFocus для закрытия меню.
            frame:
                modal True

                has vbox

                textbutton "Легкая" action [ SetVariable("difficulty", "Легкая"), ClearFocus("diff_drop") ]
                textbutton "Обычная" action [ SetVariable("difficulty", "Обычная"), ClearFocus("diff_drop") ]
                textbutton "Высокая" action [ SetVariable("difficulty", "Высокая"), ClearFocus("diff_drop") ]
                textbutton "Кошмарная" action [ SetVariable("difficulty", "Кошмар"), ClearFocus("diff_drop") ]

Выпадающие меню могут выиграть от улучшенной стилизации, которая в данном примере не приведена.

Side

Размещает отображаемые элементы по углам или в центре сетки. Принимает один параметр — строку со списком позиций через пробел. Каждый компонент этого списка должен быть одним из следующих:

'c', 't', 'b', 'l', 'r', 'tl', 'tr', 'bl', 'br'

'c' означает центр (center), 't' — верх (top), 'tl' — верхний левый угол (top left), 'br' — нижний правый угол (bottom right) и так далее.

Side принимает следующие свойства:

spacing

Расстояние между строками и столбцами сетки.

Поддерживает следующие группы свойств:

  • Общие свойства

  • Свойства стиля позиционирования

Отрисовка side начинается с трехэтапного процесса определения минимальных размеров центра, сторон и углов:

  • Сначала определяется минимальный размер центра путем предложения ему пространства (0, 0).

  • Затем определяются минимальные размеры сторон: им предлагается минимальный размер прилегающего края центра и 0 в другом направлении. То есть 't' и 'b' получают (center_min_width, 0), а 'l' и 'r' получают (0, center_min_height).

  • Наконец, определяются минимальные размеры углов: каждому предлагается минимальный размер прилегающих сторон. Например, 'tl' получит (left_min_width, top_min_height) и так далее.

Любой отображаемый объект может вырасти больше предложенного размера. Может потребоваться явно задать минимальный размер углам или сторонам (с помощью xminimum или yminimum), чтобы обеспечить им правильный размер.

После шага определения размеров создается сетка, в которой каждая строка и столбец достаточно велики, чтобы вместить самый крупный дочерний элемент в этой строке и столбце. Если задано xfill или yfill, центру выделяется дополнительное пространство, чтобы Side заполнил всю доступную область.

Затем дочерние элементы отрисовываются в порядке их объявления и помещаются в соответствующие ячейки по стандартному алгоритму. Элементы соответствуют позициям в списке places, поэтому количество потомков должно совпадать с количеством элементов в строке places.

screen side_test():
     side "c tl br":
          text "Центр"
          text "Верх-Лево"
          text "Низ-Право"

Viewport

Область просмотра (viewport) — это область экрана, которую можно прокручивать перетаскиванием мышью, колесом мыши или полосами прокрутки. Используется для отображения частей объектов, размер которых превышает экран. Принимает следующие свойства:

child_size

Размер, предлагаемый дочернему элементу для отрисовки. Кортеж вида (xsize, ysize). Обычно опускается, когда дочерний элемент может самостоятельно вычислить свой размер. Если любой компонент равен None, используется собственный размер дочернего элемента.

mousewheel

Одно из значений:

False

Игнорировать колесо мыши (по умолчанию).

True

Прокручивать по вертикали.

"horizontal"

Прокручивать по горизонтали.

"change"

Прокручивать вертикально только в том случае, если это приведет к перемещению области просмотра. В противном случае событие колеса мыши передается остальному интерфейсу (например, размещение строки key "viewport_wheeldown" action Return() перед областью просмотра приведет к возврату из экрана, если прокрутка достигла дна).

"horizontal-change"

Сочетает горизонтальную прокрутку с режимом change.

draggable

Если True, перетаскивание мышью будет прокручивать область просмотра. Также может быть вариантом экрана, в случае чего область просмотра станет перетаскиваемой только при активности данного варианта (например, draggable "touch").

edgescroll

Управляет автоматической прокруткой при достижении курсором края области просмотра. Если не None, должен быть кортежем из двух или трех элементов:

  • Первый элемент — расстояние от края области просмотра в пикселях, при котором начинается прокрутка.

  • Второй элемент — максимальная скорость прокрутки в пикселях в секунду.

  • Третий элемент (необязательный) — функция, регулирующая скорость в зависимости от близости курсора к краю. Функция принимает число от -1.0 до 1.0 и возвращает число в том же диапазоне. По умолчанию функция возвращает переданное значение, обеспечивая пропорциональную прокрутку.

xadjustment

Объект ui.adjustment(), используемый для оси X области просмотра. При опускании создается новый.

yadjustment

Объект ui.adjustment(), используемый для оси Y области просмотра. При опускании создается новый.

xinitial

Начальное горизонтальное смещение. Может быть целым числом в пикселях или числом с плавающей запятой, задающим долю от возможного смещения.

yinitial

Начальное вертикальное смещение. Целое число в пикселях или число с плавающей запятой.

scrollbars

Если не None, вместе с этой областью просмотра добавляются полосы прокрутки. Это работает за счет создания макета side и помещения области просмотра в его центр. Если scrollbars равно "horizontal", горизонтальная полоса помещается под областью. Если "vertical", вертикальная полоса помещается справа. Если "both", создаются обе полосы.

Когда scrollbars не None, viewport принимает свойства с префиксами:

  • Свойства с префиксом viewport_ передаются области просмотра.

  • Свойства с префиксом side_ передаются контейнеру side.

  • Свойства с префиксом scrollbar_ передаются горизонтальной полосе прокрутки (если она есть).

  • Свойства с префиксом vscrollbar_ передаются вертикальной полосе прокрутки (если она есть).

Также принимаются свойства без префиксов: Свойства стиля позиционирования передаются в контейнер side, а прочие свойства без префиксов передаются в viewport.

arrowkeys

Если True, область просмотра можно прокручивать клавишами со стрелками влево, вправо, вверх и вниз. Это имеет приоритет над сменяемостью фокуса, однако стрелки начнут менять фокус, когда прокрутка достигнет границы.

pagekeys

Если True, прокрутку можно выполнять клавишами PageUp и PageDown (отключает их стандартную функцию отката/перемотки).

Также принимает следующие группы свойств стиля:

  • Общие свойства

  • Свойства стиля позиционирования

Принимает один дочерний элемент. Если указано ноль, два или более дочерних элементов, создается fixed для их размещения.

Для управления прокруткой через полосы часто удобнее всего назначить id области просмотра и затем использовать XScrollValue() и YScrollValue() с этим id.

screen viewport_example():
    side "c b r":
         area (100, 100, 600, 400)

         viewport id "vp":
             draggable True

             add "washington.jpg"

         bar value XScrollValue("vp")
         vbar value YScrollValue("vp")

Vpgrid

Vpgrid (сетка в области просмотра) объединяет viewport и grid в один отображаемый объект. Vpgrid принимает несколько дочерних элементов (как grid) и оптимизирован так, что отрисовываются только те элементы, которые попадают в видимую область просмотра.

Vpgrid предполагает, что все дочерние элементы имеют одинаковый размер, определяемый размерами первого дочернего элемента. Если vpgrid отображается некорректно, убедитесь, что все элементы имеют одинаковый размер.

Vpgrid обязательно должен иметь как минимум одно из свойств: cols или rows. Если одно из них опущенно или равно None, второе вычисляется автоматически исходя из размера, отступов и количества элементов. Если строка или столбец заполнены не полностью, пустые ячейки заполняются отображаемыми объектами null.

Свойства vpgrid:

cols

Количество столбцов в сетке.

rows

Количество строк в сетке.

transpose

Если True, сначала заполняются столбцы, затем строки. По умолчанию зависит от свойств cols и rows. Если задано cols, сначала заполняются столбцы, иначе — строки.

Кроме того, vpgrid принимает все свойства, доступные для viewport, а также следующие группы свойств стиля:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля сеток (Grid)

При указании свойства scrollbars свойства с префиксами передаются в vpgrid так же, как и в случае с viewport. (Свойства с префиксом viewport_ передаются самому vpgrid.)

screen vpgrid_test():

    vpgrid:

        cols 2
        spacing 5
        draggable True
        mousewheel True

        scrollbars "vertical"

        # Поскольку есть полосы прокрутки, это позиционирует side, а не vpgrid.
        xalign 0.5

        for i in range(1, 101):

            textbutton "Кнопка [i]":
                xysize (200, 50)
                action Return(i)

Window

Окно — это контейнер с фоном, предназначенным для отображения внутриигрового диалога. Принимает следующие группы свойств:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля окон

Принимает один дочерний элемент. Если указано ноль, два или более дочерних элементов, для их размещения создается fixed.

screen say(who, what):
    window id "window":
        vbox:
            spacing 10

            text who id "who"
            text what id "what"

Операторы изображений-карт (Imagemap)

Удобный способ создания экранов, особенно для разработчиков с визуальным мышлением — создание карты изображений (imagemap). При создании imagemap оператор imagemap используется для задания до шести изображений. Операторы hotspot (активная зона) и hotbar (активная полоса) вырезают прямоугольные области из изображения и назначают им действия и значения.

Вот пример экрана настроек с использованием карты изображений:

screen preferences():

    tag menu
    use navigation

    imagemap:
        auto "gui_set/gui_prefs_%s.png"

        hotspot (740, 232, 75, 73) action Preference("display", "fullscreen") alt _("Полноэкранный режим")
        hotspot (832, 232, 75, 73) action Preference("display", "window") alt _("Оконный режим")
        hotspot (1074, 232, 75, 73) action Preference("transitions", "all") alt _("Все переходы")
        hotspot (1166, 232, 75, 73) action  Preference("transitions", "none") alt _("Без переходов")

        hotbar (736, 415, 161, 20) value Preference("music volume") alt _("Громкость музыки")
        hotbar (1070, 415, 161, 20) value Preference("sound volume") alt _("Громкость звуков")
        hotbar (667, 535, 161, 20) value Preference("voice volume") alt _("Громкость голоса")
        hotbar (1001, 535, 161, 20) value Preference("text speed") alt _("Скорость текста")

Imagemap

Оператор imagemap используется для объявления карты изображений. Не принимает позиционных параметров и поддерживает следующие свойства:

auto

Используется для автоматического определения изображений карты. Строка, содержащая %s. Если одно из свойств изображений опущено, %s заменяется именем этого свойства, и значение используется по умолчанию.

Например, если auto равно "imagemap_%s.png", а idle опущено, для idle по умолчанию будет использоваться "imagemap_idle.png". Если auto равно "imagemap %s", используется изображение с тегом imagemap idle.

Поведение auto можно переопределить через функцию config.imagemap_auto_function.

ground

Изображение для тех областей карты, которые не входят ни в один hotspot или hotbar.

insensitive

Изображение, используемое, когда активная зона или полоса нечувствительна.

idle

Изображение, когда активная зона не выбрана и не находится в фокусе, а также для пустой части неактивных полос.

hover

Изображение, когда активная зона не выбрана и находится под курсором, а также для пустой части полос в фокусе.

selected_idle

Изображение выбранной зоны не в фокусе, а также для заполненной части неактивных полос.

selected_hover

Изображение выбранной зоны под курсором, а также для заполненной части активных полос.

alpha

Если True (по умолчанию), активная зона получает фокус только тогда, когда курсор находится над непрозрачной областью изображения hover. Если False, зона получает фокус при попадании в ее прямоугольные границы.

cache

Если True (по умолчанию), данные активных зон кэшируются для повышения производительности ценой небольшого дополнительного дискового пространства.

Принимает следующие группы свойств:

  • Общие свойства

  • Свойства стиля позиционирования

  • Свойства стиля Fixed

Imagemap создает fixed, позволяя добавлять к нему любые дочерние элементы (не только hotspot и hotbar).

Hotspot

Активная зона (hotspot) — это кнопка, состоящая из части содержащей ее карты изображений. Принимает один позиционный параметр — кортеж (x, y, width, height), задающий область карты, образующую кнопку. Поддерживает следующие свойства:

action

Действие, выполняемое при активации кнопки. Также управляет чувствительностью кнопки и ее выбранным состоянием.

alternate

Действие при альтернативной активации кнопки (ПКМ или долгое касание).

hovered

Действие при получении фокуса.

unhovered

Действие при потере фокуса.

selected

Выражение, определяющее, выбрана ли кнопка в данный момент.

sensitive

Выражение, определяющее, чувствительна ли кнопка к нажатию.

keysym

Строка с символом клавиши, активирующей кнопку.

alternate_keysym

Строка с символом клавиши, активирующей альтернативное действие кнопки.

Также принимает:

  • Общие свойства

  • Свойства стиля кнопок

Hotspot создает fixed, позволяя добавлять к нему дочерние элементы. Этот fixed имеет размер, равный активной зоне, что означает, что дочерние элементы будут позиционироваться относительно этой зоны.

Элементам hotspot следует задавать свойство стиля alt для поддержки самоозвучивания Ren'Py.

Hotbar

Активная полоса (hotbar) — это полоса, состоящая из части содержащей ее карты изображений. Принимает один позиционный параметр — кортеж (x, y, width, height), задающий область карты. Поддерживает следующие свойства:

value

Текущее значение полосы: объект значения полосы или число.

range

Максимальное значение полосы. Требуется, если value — число.

adjustment

Объект ui.adjustment(), который регулирует эта полоса.

Обязательно должно быть указано одно из двух: value или adjustment. Также принимает:

  • Общие свойства

  • Свойства стиля полос (Bar)

Не принимает дочерних элементов.

Элементам hotbar следует задавать свойство стиля alt для работы самоозвучивания Ren'Py.

Оператор add

Оператор add является особенным, поскольку он добавляет на экран уже существующий отображаемый объект. Поэтому он не принимает общих свойств операторов пользовательского интерфейса.

Add

Добавляет изображение или другой отображаемый объект на экран. Необязательно принимает свойства трансформации. Если указано хотя бы одно свойство трансформации, создается Transform, оборачивающий изображение, и свойства передаются этой трансформации.

Если отображаемый объект равен None, на экран ничего не добавляется.

Не принимает дочерних элементов.

screen add_test():
    add "logo.png" xalign 1.0 yalign 0.0

Продвинутые отображаемые объекты

В дополнение к общеупотребительным операторам язык экранов включает операторы, соответствующие продвинутым отображаемым объектам. Отображение объекта на оператор просто: позиционные параметры объекта становятся позиционными параметрами оператора. Именованные аргументы и соответствующие свойства стиля становятся свойствами языка экранов.

Операторы продвинутых отображаемых объектов:

Areapicker

Предназначен для использования в инструментах разработки, позволяет пользователю выбрать прямоугольную область на экране. Принимает следующие свойства:

cols

Если не None, делит экран на сетку с указанным количеством столбцов.

rows

Если не None, делит экран на сетку с указанным количеством строк.

position

Если не None, функция, вызываемая с координатами x и y точки первого клика пользователя, округленными до шага сетки.

changed

Вызывается с кортежем прямоугольника (x, y, width, height) каждый раз, когда пользователь изменяет выделенную область.

finished

Вызывается с кортежем (x, y, width, height), когда пользователь завершает выбор области.

persist

Если True, дочерний элемент будет отображаться в выбранной области после завершения выбора. Если False (по умолчанию), дочерний элемент скрывается после завершения выбора.

Принимает группу свойств:

  • Общие свойства

Areapicker принимает один дочерний элемент, который отображается в выбранной области.

Drag

Создает перетаскиваемый объект Drag, который можно перемещать по экрану. За исключением d, передаваемого языком экранов, принимает все свойства, определенные в этом классе.

Также принимает следующие свойства:

  • Общие свойства

  • Свойства стиля hover_sound и activate_sound

  • Свойство стиля focus_mask

Drag принимает один дочерний элемент, либо свойство стиля child может использоваться для передачи дочернего элемента и его вариантов в фокусе.

Draggroup

Создает группу перетаскиваемых объектов DragGroup. Принимает те же свойства, что и DragGroup, а также:

  • Общие свойства

Группа перетаскивания может иметь ноль или более объектов drag в качестве потомков. Она также может содержать обычные объекты, в каковом случае работает подобно fixed.

Оператор has

Оператор has позволяет указать контейнер вместо fixed для операторов, принимающих только один дочерний элемент. Оператор has может использоваться только внутри оператора, принимающего один дочерний элемент. За ключевым словом has в той же строке следует другой оператор, который обязательно должен быть контейнером, принимающим более одного потомка.

Оператор has меняет способ разбора содержащего его блока. Дочерние отображаемые объекты, созданные в этом блоке, добавляются в контейнер, а не в родительский элемент. Именованные аргументы к родительскому элементу после оператора has не допускаются. В одном блоке можно использовать несколько операторов has.

Оператор has может быть передан потомком следующих операторов:

  • button

  • frame

  • window

В качестве контейнера оператору has можно передавать следующие операторы:

  • fixed

  • grid

  • hbox

  • side

  • vbox

screen volume_controls():
     frame:
         has vbox

         bar value Preference("sound volume")
         bar value Preference("music volume")
         bar value Preference("voice volume")

Управляющие операторы

Язык экранов включает управляющие операторы для условного выполнения, итерации, включения других экранов, выполнения действий при возникновении событий и выполнения произвольного кода Python.

Default

Оператор default задает значение переменной по умолчанию, если она не была передана в качестве аргумента экрану и не унаследована от экрана, вызвавшего нас оператором use.

screen scheduler():
    default club = None
    vbox:
         text "Чем бы вы хотели заняться?"
         textbutton "Художественный кружок" action SetScreenVariable("club", "art")
         textbutton "Литературный клуб" action SetScreenVariable("club", "writing")

         if club:
             textbutton "Выбрать" action Return(club)

For

Оператор for аналогичен оператору for в Python, за исключением того, что он не поддерживает ветку else (однако поддерживает операторы continue и break). Он поддерживает распаковку в кортежи (в том числе вложенные), а также присваивание переменным.

$ numerals = [ 'I', 'II', 'III', 'IV', 'V' ]

screen five_buttons():
    vbox:
        for i, numeral in enumerate(numerals):
            textbutton numeral action Return(i + 1)

Оператор for принимает предложение index:

screen five_buttons():
    vbox:
        for i, numeral index numeral in enumerate(numerals):
            textbutton numeral action Return(i + 1)

Если предложение index указано, оно должно состоять из выражения, возвращающего хэшируемое и сравнимое значение, уникальное для каждой строки списка. Ren'Py использует это значение, чтобы гарантировать, что трансформации и другие состояния связываются с правильной итерацией. Если вы замечаете странное поведение при добавлении или удалении элементов из списка, по которому идет итерация, вам стоит использовать предложение index.

If

Оператор языка экранов if аналогичен оператору if в Python/Ren'Py. Он поддерживает ветки if, elif и else.

screen skipping_indicator():
    if renpy.is_skipping():
         text "Пропуск."
    else:
         text "Не пропускается."

On

Оператор on позволяет экрану выполнять действие при возникновении события. Принимает один параметр — строку с именем события. Должно быть одним из:

  • "show"

    Событие возникает при отображении экрана (обратите внимание: если экран с тем же тегом уже отображается, вместо этого возникает событие "replace").

  • "hide"

    Событие возникает при скрытии экрана (если он заменяется экраном с тем же тегом, вместо этого возникает событие "replaced").

  • "replace"

    Событие возникает при показе экрана, заменяющего экран с тем же тегом.

  • "replaced"

    Событие возникает, когда экран заменяется экраном с тем же тегом.

Затем указывается свойство action, задающее действие, выполняемое при возникновении события.

screen preferences():
    frame:
        has hbox

        text "Экран"
        textbutton "Полноэкранный" action Preferences("display", "fullscreen")
        textbutton "Оконный" action Preferences("display", "window")

    on "show" action Show("navigation")
    on "hide" action Hide("navigation")

Use

Оператор use позволяет экрану включать в себя другой экран. Принимает имя используемого экрана. За ним необязательно может следовать список аргументов в круглых скобках.

Если используемый экран не имеет скобок, он получает доступ на чтение и запись к области видимости текущего экрана, дополненной любыми именованными аргументами, переданными через оператор use. В противном случае его область видимости инициализируется результатом присваивания аргументов этим параметрам.

screen file_slot(slot):
    button:
        action FileAction(slot)

        has hbox

        add FileScreenshot(slot)
        vbox:
            text FileTime(slot, empty="Пустой слот.")
            text FileSaveName(slot)


screen save():
    grid 2 5:
        for i in range(1, 11):
             use file_slot(i)

Оператор use может принимать предложения-свойства: id и as. Эти свойства должны располагаться после списка параметров (если он есть) и обязательно в первой строке оператора, а не внутри его блока.

Предложение id полезно только тогда, когда два экрана с одинаковым тегом используют один и тот же вложенный экран. В этом случае, когда один экран заменяет другой, состояние используемого экрана переносится из старого в новый.

transform t1():
    xpos 150
    linear 1.0 xpos 0

screen common():
    text "Тест" at t1

screen s1():
    tag s
    use common id "common"
    text "s1" ypos 100

screen s2():
    tag s
    use common id "common"
    text "s2" ypos 100

label start:
    show screen s1
    pause
    show screen s2
    pause
    return

За предложением as должно следовать имя переменной. Когда используемый экран завершает работу, значение переменной main в этом экране присваивается указанной переменной. Например:

screen child():
    add MyCreatorDefinedDisplayable() as main

screen parent():
    use child as mycdd

    # Здесь экземпляр MyCreatorDefinedDisplayable присвоен mycdd.

Вместо имени экрана можно указать ключевое слово expression, за которым следует выражение, возвращающее имя экрана для использования. Если требуются параметры, ключевое слово pass должно разделять выражение и параметры.

screen ed(num):
    text "Эд"
    text "Капитан"

screen kelly(num):
    text "Келли"
    text "Первый помощник"

screen bortus(num):
    text "Бортус"
    text "Второй помощник"

screen crew():
    hbox:
        for i, member in enumerate(party):
            vbox:
                use expression member.screen pass (i + 1)

Использование Use и Transclude

Оператор use может также принимать блок с операторами языка экранов. Когда такой блок передан, используемый экран может содержать оператор transclude. Оператор transclude заменяется операторами, содержащимися в блоке оператора use.

Это позволяет создавать многократно используемые макеты с помощью экранов. Например:

screen movable_frame(pos):
    drag:
        pos pos

        frame:
            background Frame("movable_frame.png", 10, 10)
            top_padding 20

            transclude

задуман как переиспользуемый компонент, оборачивающий другие компоненты. Вот пример его использования:

screen test:
    use movable_frame((0, 0)):
        text "Меня можно перетаскивать."

    use movable_frame((0, 100)):
        vbox:
            text "Меня тоже можно перетаскивать."
            textbutton "Понятно!" action Return(True)

Конструкции use и transclude лежат в основе пользовательских операторов языка экранов.

Python

Язык экранов также включает однострочные и многострочные операторы Python, которые могут выполнять произвольный код на Python. Код Python выполняется в области видимости экрана.

Код Python не должен вызывать побочных эффектов, видимых за пределами экрана. Ren'Py запускает экран несколько раз по мере необходимости. Он запускает экран в рамках процесса предсказания изображений перед его первым показом. Поэтому, если экран имеет побочные эффекты, они могут происходить в непредсказуемые моменты времени.

screen python_screen:
    python:
        test_name = "Тест %d" % test_number

    text test_name

    $ test_label = "test_%d" % test_label

    textbutton "Запустить тест" action Jump(test_label)

Оператор showif

Оператор showif принимает условие. Он показывает свои дочерние элементы, когда условие истинно, и скрывает их, когда условие ложно. Если у дочерних элементов есть трансформации, им передаются события ATL для управления процессом показа и скрытия, что позволяет Ren'Py анимировать появление и исчезновение элементов.

Оператор showif оборачивает свои дочерние элементы в отображаемый объект, управляющий процессом отображения и скрытия.

Несколько операторов showif можно объединять в единую конструкцию showif/elif/else, аналогично оператору if. В отличие от оператора if, showif выполняет все свои блоки, включая код Python, даже если условие ложно. Это необходимо потому, что оператору showif нужно предварительно создать дочерние элементы, которые он скрывает.

Showif передает своим дочерним элементам три события:

appear

Передается, если условие истинно в момент первого показа экрана, чтобы мгновенно отобразить элемент.

show

Передается, когда условие меняется с ложного на истинное.

hide

Передается, когда условие меняется с истинного на ложное.

В этих целях условие ветки elif всегда считается ложным, если любое из предшествующих условий истинно, тогда как условие ветки else истинно только тогда, когда все предшествующие условия ложны.

Например:

transform cd_transform:
    # Выполняется до appear, show или hide.
    xalign 0.5 yalign 0.5 alpha 0.0

    on appear:
        alpha 1.0
    on show:
        zoom .75
        linear .25 zoom 1.0 alpha 1.0
    on hide:
        linear .25 zoom 1.25 alpha 0.0

screen countdown():
    default n = 3

    vbox:
        textbutton "3" action SetScreenVariable("n", 3)
        textbutton "2" action SetScreenVariable("n", 2)
        textbutton "1" action SetScreenVariable("n", 1)
        textbutton "0" action SetScreenVariable("n", 0)

    showif n == 3:
        text "Три" size 100 at cd_transform
    elif n == 2:
        text "Два" size 100 at cd_transform
    elif n == 1:
        text "Один" size 100 at cd_transform
    else:
        text "Пуск!" size 100 at cd_transform

label start:
    call screen countdown

Операторы экранов

В дополнение к объявлению экранов через оператор screen существуют три оператора языка сценариев Ren'Py, взаимодействующие с экранами.

Show Screen

Оператор show screen отображает экран. Он принимает имя экрана, ряд необязательных предложений и необязательные аргументы Python, передаваемые экрану. Функции renpy.show_screen() и renpy.call_screen() принимают дополнительные специальные именованные аргументы.

Оператор show screen принимает следующие предложения, некоторые из которых аналогичны предложениям оператора show:

as

Предложение as принимает имя. Если не указано, по умолчанию используется тег, связанный с экраном (см. Оператор screen). Если тег не задан, используется имя экрана.

onlayer

Слой, на котором будет отображен экран.

zorder

Порядок по оси Z, на котором отображается экран. Если не указан, по умолчанию используется значение zorder, связанное с экраном. Если оно не задано, по умолчанию равно 0.

expression

Если указано ключевое слово expression, следующее за ним выражение вычисляется как имя экрана. Для передачи аргументов экрану вместе с expression используйте ключевое слово pass:

$ screen_name = "my_screen"
show screen expression screen_name
# Или если нужно передать аргументы
show screen expression screen_name pass ("Foo", message="Bar")
with

Интерпретируется точно так же, как предложение with оператора show:

show screen clock_screen with dissolve
nopredict

Ключевое слово nopredict не принимает значений. Оно отключает предсказание экрана. Во время предсказания аргументы экрана вычисляются заранее. Пожалуйста, убедитесь, что вычисление аргументов экрана не вызывает нежелательных побочных эффектов.

Предупреждение

Если вычисление аргументов экрана вызывает побочные эффекты, игра может вести себя непредсказуемо.

Экраны, показанные таким образом, отображаются до тех пор, пока не будут явно скрыты. Это позволяет использовать их в качестве оверлеев.

show screen overlay_screen
show screen clock_screen(hour=11, minute=30)

if rare_case:
    show rare_screen nopredict

Hide Screen

Оператор hide screen используется для скрытия экрана, отображаемого в данный момент. Он принимает тег экрана. Сначала он пытается найти экран с заданным тегом на указанном слое (см. предложение onlayer). Если таковой не найден, он ищет экран с этим именем на данном слое, независимо от тега, под которым экран отображается. Если экран не найден, ничего не происходит:

show screen A
show screen B as A # B заменяет A (что скрывает A)
hide screen A # скрывает B, отображаемый под тегом A

show screen A as B
show screen B as C

hide screen B
# скрывает экран A, отображаемый как B
# экран B, отображаемый как C, остается видимым

hide screen B
# скрывает экран B

Также принимает предложение onlayer, по умолчанию имеющее значение слоя screens.

Предложение with интерпретируется так же, как предложение with оператора show.

Аналогично оператору show screen, оператор hide screen поддерживает ключевое слово expression, позволяя использовать произвольное выражение в качестве имени экрана.

hide screen rare_screen
hide screen clock_screen with dissolve
hide screen overlay_screen
$ screen_name = "some_screen"
hide screen expression screen_name

Call Screen

Оператор call screen отображает экран, а затем скрывает его по окончании текущего взаимодействия. Если экран возвращает значение, оно помещается в глобальную переменную _return.

Это можно использовать для отображения карты изображений. Карта изображений может поместить значение в переменную _return с помощью действия Return() или перейти к метке с помощью действия Jump().

Оператор call screen принимает различные необязательные предложения, большинство из которых аналогичны предложениям оператора show screen:

as

Принимает имя. Если не указано, по умолчанию используется тег экрана (см. Оператор screen). Если тег не задан, используется имя экрана.

onlayer

Слой, на котором будет показан экран.

zorder

Порядок отображения по оси Z. По умолчанию берется из объявления экрана или равен 0.

nopredict

Отключает предсказание экрана. Во время предсказания аргументы экрана вычисляются. Убедитесь, что вычисление аргументов не вызывает нежелательных побочных эффектов.

Предупреждение

Если вычисление аргументов экрана вызывает побочные эффекты, игра может вести себя непредсказуемо.

expression

Аналогично show screen, оператор call screen принимает ключевое слово expression, позволяя использовать произвольное выражение в качестве имени экрана. Также поддерживается ключевое слово pass для передачи аргументов.

with

В операторе call screen предложение with вызывает переход при отображении экрана.

Это не вызывает перехода with None перед показом экрана, поэтому все предшествующие операторы show и hide выполнятся. Если вам нужен with None, добавьте его явно.

Поскольку вызов экрана является взаимодействием, а взаимодействия запускают неявный переход with None, использование оператора with после инструкции call screen не приведет к плавному скрытию экрана с помощью перехода, так как к этому моменту экран уже исчезнет. Чтобы отключить неявный переход with None, передайте экрану специальный именованный аргумент _with_none=False, как показано в примере ниже.

Другие способы запуска переходов также работают, например список действий [ With(dissolve), Return() ].

call screen my_imagemap

call screen my_screen(side_effect_function()) nopredict

# Показывает экран с растворением (dissolve)
call screen my_other_screen with dissolve
# Экран мгновенно исчезает с None, затем выполняется переход pixellate
with pixellate

# Показывает экран с dissolve и скрывает его с pixellate.
call screen my_other_screen(_with_none=False) with dissolve
with pixellate

$ screen_name = "my_screen"
call screen expression screen_name pass (foo="bar")

Варианты экранов

Ren'Py работает как на традиционных устройствах с управлением мышью (ПК под управлением Windows, macOS и Linux), так и на современных сенсорных устройствах (смартфоны и планшеты на базе Android и iOS). Варианты экранов позволяют игре предоставлять несколько версий одного экрана и использовать ту версию, которая лучше всего соответствует текущему аппаратному обеспечению.

Ren'Py выбирает вариант экрана для использования, просматривая варианты в том порядке, в котором они перечислены в config.variants. Используется первый найденный вариант.

Если присутствует переменная окружения RENPY_VARIANT, config.variants инициализируется путем разделения значения переменной по пробелам с последующим добавлением None. Установка RENPY_VARIANT в такие значения, как "medium tablet touch" или "small phone touch", позволяет тестировать экраны для устройств Android прямо на ПК.

Если переменная окружения отсутствует, список вариантов формируется автоматически путем последовательного прохода по следующему списку и выбора записей, применимых к текущей платформе:

"steam_deck"

True, если игра запущена на Steam Deck или эквивалентном оборудовании.

"steam_big_picture"

True, если запуск произведен в режиме Steam Big Picture.

"large"

Достаточно большой экран, на котором относительно мелкий текст читается комфортно, а по кнопкам легко кликать мышью. Используется для экранов настольных компьютеров.

"medium"

Экран, на котором некрупный текст читается хорошо, но кнопкам может потребоваться увеличенный размер для комфортного нажатия пальцем. Используется для планшетов.

"small"

Экран, на котором текст должен быть увеличен для нормального чтения. Используется для телефонов и телевизоров. (Телевизор может быть физически большим, но часто находится далеко, что затрудняет чтение мелкого текста.)

"tablet"

Определен на устройствах с сенсорным экраном, диагональ которого составляет 6 дюймов или более. (Как правило, вместо "tablet" рекомендуется использовать "medium".)

"phone"

Определен на устройствах с сенсорным экраном, диагональ которого менее 6 дюймов. На таких маленьких экранах важно делать кнопки достаточно большими для удобного нажатия. (Как правило, вместо "phone" рекомендуется использовать "small".)

"touch"

Определен на устройствах с сенсорным экраном.

"tv"

Определен на телевизионных приставках и смарт-ТВ.

"firetv"

Определен на консоли Amazon Fire TV (также определены "tv" и "small").

"chromeos"

Определен при запуске в качестве приложения Android на Chromebook.

"android"

Определен на всех устройствах Android.

"ios"

Определен на устройствах iOS, таких как iPad (где также определены "tablet" и "medium") и iPhone (где также определены "phone" и "small").

"mobile"

Определен на мобильных платформах, таких как Android, iOS и мобильные веб-браузеры.

"pc"

Определен в Windows, macOS и Linux. Предполагается наличие мыши и клавиатуры, что обеспечивает точное наведение курсора и появление эффекта наведения (hover).

"web"

Определен при запуске внутри веб-браузера.

None

Определен всегда.

Пример определения варианта экрана:

# Вариант экрана hello_world, используемый на небольших сенсорных устройствах.
screen hello_world():
     tag example
     zorder 1
     modal False
     variant "small"

     text "Hello, World." size 30
