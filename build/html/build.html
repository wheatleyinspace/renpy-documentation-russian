Сборка дистрибутивов

Ren'Py включает встроенную поддержку сборки дистрибутивов игры. При выборе пункта «Сборка дистрибутивов» («Build Distributions») в лаунчере Ren'Py просканирует сам движок и проект, чтобы определить, какие файлы включить в дистрибутив, создаст все необходимые архивы, сформирует пакеты и файлы обновлений.

Без дополнительной настройки Ren'Py может собирать следующие типы пакетов:

PC: Windows и Linux

Zip-архив для Windows x86_64 и Linux x86_64.

Linux

Архив tar.bz2 для Linux x86_64. Он также включает 32- и 64-битные ARM-версии Ren'Py, если они установлены (они содержатся в пакете Ren'Py sdkarm).

Macintosh

Zip-архив, содержащий приложение Macintosh для macOS на процессорах Intel и Apple Silicon. Данные игры включаются внутрь приложения, которое выглядит для пользователя как единый файл. Средство обновления не работает с этим пакетом.

Windows

Zip-архив для Windows x86_64.

Windows, Mac и Linux для торговых площадок

Дистрибутив, содержащий информацию, необходимую для работы на площадках распространения игр, таких как itch.io и Steam. Он не предназначен для прямого запуска (и, скорее всего, не запустится на Mac), но должен передаваться в процесс загрузки магазина приложений.

Предупреждение

Файлы zip и tar.bz2, создаваемые Ren'Py, содержат информацию о правах доступа к файлам, которая необходима для корректного запуска Ren'Py на Linux и Macintosh.

Распаковка и повторная запаковка zip-архива в Windows с последующим запуском на Linux или Macintosh не поддерживается.

Базовая настройка

Процесс сборки можно настроить, задавая переменные и вызывая функции из пространства имён build. Это должно выполняться внутри блока init python. Настройки по умолчанию для этих конфигураций задаются в файле options.rpy.

Существует несколько основных переменных и функций, которые используются во многих играх.

build.name = "..."

Используется для автоматической генерации build.directory_name и build.executable_name, если ни одна из них не задана явно. Не должна содержать пробелов, двоеточий или точек с запятой.

build.directory_name = "..."

Используется для создания имён каталогов в архивных файлах. Например, если задано значение "mygame-1.0", то версия проекта для Linux будет распаковываться в каталог "mygame-1.0-linux".

Также используется для определения имени каталога, в который помещаются файлы пакетов. Например, если установить build.directory_name в mygame-1.0, архивные файлы будут помещены в каталог mygame-1.0-dists на уровень выше базового каталога.

Эта переменная не должна содержать специальных символов, таких как пробелы, двоеточия и точки с запятой. Если не задана, по умолчанию принимает значение build.name, дефис и номер версии. Версия берётся из build.version, если она задана, либо из config.version.

build.executable_name = "..."

Эта переменная управляет именем исполняемых файлов, которые пользователь запускает для старта игры.

Она не должна содержать специальных символов, таких как пробелы, двоеточия и точки с запятой. Если не задана, по умолчанию принимает значение build.name.

Например, если задано значение "mygame", пользователь сможет запускать mygame.exe в Windows, mygame.app на Macintosh и mygame.sh в Linux.

Специальные файлы

Существует два файла, которые можно поместить в базовый каталог игры для настройки сборки:

icon.ico

Значок приложения, используемый в Windows.

icon.icns

Значок приложения, используемый на Macintosh.

Файлы значков должны быть в соответствующих форматах. Для их конвертации потребуется использовать программу или веб-сервис (например, https://anyconv.com/png-to-ico-converter/ и https://anyconv.com/png-to-icns-converter/).

Классификация и игнорирование файлов

Процесс сборки сначала распределяет файлы дистрибутива Ren'Py и вашей игры по спискам файлов. Затем эти списки файлов добавляются в файлы пакетов.

Классификация выполняется с помощью функции build.classify. Она принимает шаблон и разделённый пробелами список файлов. Шаблоны проверяются по порядку от первого к последнему, при этом первое совпадение имеет приоритет (даже если далее следует более конкретный шаблон). Шаблоны сопоставляются как с ведущим слешем /, так и без него. Шаблоны могут содержать следующие специальные символы:

/

Разделитель каталогов.

*

Соответствует любым символам, кроме разделителя каталогов.

**

Соответствует абсолютно любым символам.

Например:

**.txt

Соответствует всем txt-файлам.

game/*.txt

Соответствует txt-файлам в каталоге game.

По умолчанию существует семь списков файлов, по которым можно распределять файлы (Ren'Py помещает свои собственные файлы в первые шесть из них):

all

Эти файлы будут включены во все пакеты, а также в сборки для Android.

linux

Эти файлы будут включены в пакеты для Linux.

mac

Эти файлы будут включены в пакеты для Macintosh.

windows

Эти файлы будут включены в пакеты для Windows.

renpy

Эти файлы будут включены в пакеты, требующие файлов движка Ren'Py (Linux, Macintosh и Windows).

android

Эти файлы будут включены в сборки для Android.

Этот набор допустимых списков файлов можно расширить, передав новые имена в качестве аргумента file_list функции build.classify().

Файлы также могут быть классифицированы в архивы. По умолчанию объявлен архив "archive":

archive

Эти файлы будут включены в архив archive.rpa.

Набор архивов также можно расширить с помощью функции build.archive().

Файлы, которые не были классифицированы иначе, помещаются в список файлов "all".

Чтобы исключить файлы из дистрибутива, классифицируйте их как None или как пустую строку. В этом случае знаки * и ** в конце шаблона должны соответствовать хотя бы одному символу.

Например:

# Включить README.txt
build.classify("README.txt", "all")

# Но исключить все остальные txt-файлы.
build.classify("**.txt", None)

# Добавить png и jpg файлы из каталога game в архив.
build.classify("game/**.png", "archive")
build.classify("game/**.jpg", "archive")

Документация

Вызов функции build.documentation с шаблонами помечает файлы, соответствующие этим шаблонам, как документацию. Файлы документации включаются в приложение для Macintosh дважды — как внутри самого приложения, так и снаружи.

Например, чтобы пометить все txt- и html-файлы в базовом каталоге как документацию, вызовите:

build.documentation("*.txt")
build.documentation("*.html")

Пакеты

В процесс сборки Ren'Py также можно добавлять новые типы пакетов. Это делается с помощью вызова функции build.package с указанием имени пакета, его типа и строки, содержащей включаемые списки файлов.

Предположим, мы хотим собрать обычную версию нашей игры и версию, содержащую бонусные материалы. Мы можем классифицировать бонусные файлы в список файлов "bonus", а затем объявить премиум-пакет следующим образом:

# Объявляем новый архив, принадлежащий новому списку файлов "bonus".
build.archive("bonus_archive", "bonus")

# Помещаем бонусные файлы в новый архив.
build.classify("game/bonus/**", "bonus_archive")

# Объявляем пакет.
build.package("all-premium", "zip", "windows mac linux renpy all bonus")

Поддерживаемые типы пакетов: "zip" и "tar.bz2" для создания файлов в этих форматах, а также "directory" для создания каталога с файлами.

Архивы

Ren'Py поддерживает объединение файлов в простой формат архива. Хотя он и не является защищённым от взлома, он предотвращает простое копирование файлов.

По умолчанию все файлы, классифицированные в список файлов "archive", будут помещены в архив archive.rpa, который включается в список файлов "all".

С помощью вызова build.archive можно объявлять новые архивы и списки файлов, в которые они будут включены (однако практически всегда используется список "all"). Чтобы использовать архив, классифицируйте файлы в список с его именем.

Например, следующий код упакует изображения в images.rpa, а игровые скрипты — в scripts.rpa:

# Объявляем два архива.
build.archive("scripts", "all")
build.archive("images", "all")

# Помещаем файлы сценариев в архив scripts.
build.classify("game/**.rpy", "scripts")
build.classify("game/**.rpyc", "scripts")

# Помещаем изображения в архив images.
build.classify("game/**.jpg", "images")
build.classify("game/**.png", "images")

Если архивный файл пуст, он не будет создан.

Пожалуйста, дважды подумайте перед тем, как архивировать свою игру. Сохранение файлов открытыми поможет другим запускать вашу игру на будущих платформах — платформах, которые могут появиться лишь спустя годы.

Каталог old-game

Ren'Py использует скомпилированные файлы скриптов (файлы .rpyc) для быстрой работы игры. В этих файлах также хранятся важные данные, такие как уникальные идентификаторы каждой строки диалога или сцены, на которые опираются файлы сохранений. Когда игра обновляется и скрипты .rpy изменяются, Ren'Py обновляет или создаёт соответствующие файлы .rpyc при запуске игры.

Эта динамическая природа файлов .rpyc может создать трудности для разработчиков, выпускающих частые обновления (например, в раннем доступе или на Patreon), или работающих в больших командах. Во время разработки легко внести серию изменений в файл .rpy, из-за чего созданный файл .rpyc получит идентификаторы, отличные от тех, что использовались в вашей текущей стабильной версии. Для команд это ещё более сложная задача, так как несколько разработчиков могут одновременно редактировать один и тот же .rpy. Как Ren'Py может сохранить идентификаторы без единого авторитетного файла .rpyc?

Чтобы такие изменения не нарушали совместимость файлов сохранений, разработчики могут использовать каталог old-game. Эта специальная папка, располагающаяся рядом с папкой game в каталоге проекта, позволяет хранить копию файлов .rpyc из вашего предыдущего релиза. Её структура должна полностью повторять структуру папки game. Например, переместите game/scripts/day1.rpyc в old-game/scripts/day1.rpyc. Любые файлы в old-game, не являющиеся .rpyc, игнорируются.

При наличии каталога old-game с файлами .rpyc из прошлого релиза Ren'Py использует их для формирования новых файлов .rpyc изменённых скриптов .rpy. Он сохраняет прежние идентификаторы для тех частей скрипта, которые не изменились, поэтому старые файлы сохранений по-прежнему смогут корректно загружаться.

Как извлечь максимум пользы из каталога `old-game`:

  • При запуске игры, если файл .rpy изменился и в old-game есть соответствующий ему файл .rpyc, Ren'Py использует этот файл .rpyc для обновления файла в game. Это сохраняет идентификаторы согласованными с вашим прошлым релизом для максимальной совместимости сохранений.

  • Перед сборкой нового релиза включите опцию «Принудительная перекомпиляция» («Force Recompile») на странице сборки дистрибутивов в Ren'Py SDK и нажмите «Обновить old-game» («Update old-game») перед тем, как нажать «Собрать» («Build»). Это перекомпилирует все файлы .rpyc, используя файлы из old-game в качестве основы, а затем обновит old-game этими новыми стабильными файлами .rpyc для следующего релиза.

  • Если вы уже выпустили игру, вы всё равно можете воспользоваться преимуществами old-game, скопировав файлы .rpyc из каталога game вашего последнего релиза в каталог old-game вашего проекта с сохранением той же структуры папок.

Более подробную информацию о том, как файлы .rpyc помогают загружать сохранения в изменённых играх, можно найти по ссылкам:

Системные требования

Некоторые магазины запрашивают системные требования для запуска приложений Ren'Py. Хотя они различаются от игры к игре, ниже приведён набор базовых минимальных требований для типовой визуальной новеллы.

Windows

  • Версия: Windows 10 или выше.

  • Процессор: 64-битный Intel-совместимый с частотой 2.0 ГГц

  • ОЗУ: 2.0 ГБ

  • Видеокарта: OpenGL 3.0 или DirectX 11

macOS

  • Версия: 10.10+

  • Процессор: 64-битный Intel-совместимый с частотой 2.0 ГГц или Apple Silicon (M1+)

  • ОЗУ: 2.0 ГБ

  • Видеокарта: OpenGL 3.0

Linux

  • Версия: Ubuntu 20.04+

  • Процессор: 64-битный Intel-совместимый с частотой 2.0 ГГц

  • ОЗУ: 2.0 ГБ

  • Видеокарта: OpenGL 3.0

Объём необходимого дискового пространства полностью определяется ресурсами вашей игры; объём необходимой оперативной памяти и требования к процессору также могут различаться. Ren'Py также может работать под OpenGL 2 при наличии определённых расширений.

Функции сборки

build.archive(name, file_list='all')

Объявляет существование архива, чьё имя name добавляется в список доступных имён архивов, которые можно передавать в build.classify().

Если один или несколько файлов классифицированы с именем name, создаётся архив с именем name.rpa, который затем распространяется в пакетах, включающих указанный здесь список файлов file_list.

build.archive("secret", "windows")

Если какой-либо файл включён в архив "secret" с помощью функции build.classify(), этот файл будет включён в архив secret.rpa в сборках для Windows.

Как и в случае с функцией build.classify(), если имя, переданное в качестве file_list, не существует среди списков файлов, оно создаётся и добавляется в набор допустимых списков файлов.

build.classify(pattern, file_list)

Классифицирует файлы, соответствующие шаблону pattern, в список файлов file_list, который также может являться именем архива.

Если имя, переданное в качестве file_list, не существует как имя архива или списка файлов, оно создаётся и добавляется в набор допустимых списков файлов.

build.clear()

Очищает список шаблонов, используемых для классификации файлов.

build.documentation(pattern)

Объявляет шаблон, соответствующий файлам документации. В сборке приложения для Mac файлы, соответствующие шаблону документации, сохраняются дважды — один раз внутри пакета приложения и ещё раз снаружи.

build.executable(pattern)

Добавляет шаблон, помечающий файлы как исполняемые на платформах, где это поддерживается (Linux и Macintosh).

build.package(name, format, file_lists, description=None, update=True, dlc=False, hidden=False, update_only=False)

Объявляет пакет, который может быть собран инструментом упаковки.

name

Имя пакета.

format

Формат пакета. Строка, содержащая разделённый пробелами список следующих значений:

zip

Файл формата zip.

tar.bz2

Файл формата tar.bz2.

directory

Каталог, содержащий файлы.

dmg

Образ диска Macintosh DMG, содержащий файлы.

app-zip

Файл zip, содержащий приложение для Macintosh. Этот формат не поддерживает средство обновления Ren'Py.

app-directory

Каталог, содержащий приложение для Mac. Этот формат не поддерживает средство обновления Ren'Py.

app-dmg

Образ диска Macintosh, содержащий dmg (только для Mac). Этот формат не поддерживает средство обновления Ren'Py.

bare-zip

Файл zip без добавления префикса build.directory_name.

bare-tar.bz2

Файл tar.bz2 без добавления префикса build.directory_name.

null

Используется для генерации только файлов обновлений без создания самого пакета.

Пустая строка означает, что форматы пакета собираться не будут (что позволяет создавать DLC).

file_lists

Список, содержащий списки файлов, которые будут включены в пакет.

description

Необязательное описание собираемого пакета.

update

Если True и выполняется сборка обновлений, для этого пакета будет создано обновление.

dlc

Если True, любые файлы zip или tar.bz2 будут собраны в автономном режиме DLC без каталога обновлений.

hidden

Если True, этот пакет будет скрыт из списка пакетов в лаунчере.

Информация о сборке

Существуют две переменные, которые можно использовать для получения информации о сборке. Эта информация используется для создания файла game/cache/build_info.json, который загружается при запуске Ren'Py.

build.time = None

По умолчанию эта переменная равна None, но после сборки игры ей будет присвоено время сборки игры в секундах, прошедших с 1 января 1970 года (Unix timestamp).

build.info = { }

Эта переменная позволяет сохранять информацию, которая будет помещена в файл game/cache/build_info.json собранной игры. При запуске собранной игры файл game/cache/build_info.json загружается, а его содержимое помещается в эту переменную.

Как правило, рекомендуется проверять отсутствие поля и устанавливать его с помощью метода setdefault.

Например, следующий код сохраняет имя компьютера, на котором была собрана игра, в файле build_info.json:

python hide:
    import socket
    build.info.setdefault("build_host", socket.gethostname())

Данные в этой переменной должны быть типов, поддерживаемых форматом JSON (то есть None, логические значения, строки, числа, списки и словари).

Расширенная настройка

Следующие переменные обеспечивают более тонкий контроль над процессом сборки:

build.allow_integrated_gpu = True

Позволяет Ren'Py работать на встроенном графическом процессоре (iGPU) на платформах, имеющих как встроенную, так и дискретную видеокарту. В настоящее время это поддерживается только на macOS.

build.destination = "{directory_name}-dists"

Задаёт путь к каталогу, в который будут помещаться архивные файлы. Может быть абсолютным или относительным путём. Относительный путь отсчитывается от каталога проектов.

Следующие значения подставляются с помощью функции Python str.format:

{directory_name}

Значение переменной build.directory_name.

{executable_name}

Значение переменной build.executable_name.

{version}

Значение переменной build.version.

build.change_icon_i686 = True

Если True и файл icon.ico существует, значок 32-битного исполняемого файла Windows будет изменён. Если False, значок изменяться не будет. Установка этого параметра в значение False может предотвратить ложные срабатывания некоторых антивирусных программ.

build.exclude_empty_directories = True

Если True, пустые каталоги (включая каталоги, оставшиеся пустыми после архивирования файлов) будут удалены из создаваемых пакетов. Если False, пустые каталоги будут включены.

build.game_only_update = False

Если True, параметр build.include_update включается, и становится доступен пакет обновления игры для мобильных устройств («Game-Only Update for Mobile»).

build.include_i686 = True

Если True, файлы, необходимые для запуска на 32-разрядных процессорах x86, будут включены в сборки для Linux и Mac. Если False, эти файлы не будут включены.

build.include_old_themes = True

Если True, файлы, необходимые для поддержки тем оформления, существовавших до Ren'Py 6.99.9, будут включены в сборку. Если False, такие файлы исключаются.

Принимает значение False при вызове gui.init().

build.include_update = False

Если True, Ren'Py создаст файлы, необходимые для работы средства обновления.

build.itch_project = None

Настройка этого параметра позволяет лаунчеру Ren'Py загружать ваш проект на itch.io. Здесь должно быть указано имя проекта, зарегистрированного на itch (например, "renpytom/the-question").

После того как эта переменная задана, после завершения сборки дистрибутивов вы можете нажать «Сборка дистрибутивов» -> «Загрузить на itch.io», чтобы выполнить загрузку.

build.wavedash_id = None

Если задана непустая строка, лаунчер Ren'Py записывает файл wavedash.toml при сборке веб-дистрибутива. Этот файл настраивает дистрибутив для загрузки на Wavedash.

Значение используется в качестве ID игры на Wavedash. Созданный файл указывает мажорную, минорную и патч-версию запущенного Ren'Py, использует game.zip в качестве исполняемого файла и задаёт каталог загрузки на папку веб-дистрибутива.

Например:

define build.wavedash_id = "YOUR_GAME_ID_HERE"

После задания этого параметра нажмите «Веб» -> «Загрузить на wavedash.com», чтобы загрузить веб-сборку. Если веб-дистрибутив ещё не собран или ID игры изменился с момента сборки, лаунчер предложит собрать или пересобрать его перед загрузкой. Лаунчер автоматически загружает и обновляет CLI Wavedash. Если вы не авторизованы, он откроет страницу входа в браузере перед загрузкой.

build.itch_channels = { ... }

Сопоставляет шаблон имени файла (например, "*-win.zip") со строкой, задающей канал itch, на который должен быть загружен файл. По умолчанию:

{
    "*-all.zip" : "win-osx-linux",
    "*-market.zip" : "win-osx-linux",
    "*-pc.zip" : "win-linux",
    "*-win.zip" : "win",
    "*-mac.zip" : "osx",
    "*-linux.tar.bz2" : "linux",
    "*-release.apk" : "android",
}
build.mac_info_plist = { }

Словарь, сопоставляющий строки со строками, который можно использовать для добавления или переопределения ключей в файле Info.plist для Mac.

build.update_formats = [ "rpu" ]

Список форматов, которые будет собирать средство обновления. Формат по умолчанию, "rpu", поддерживается начиная с Ren'Py 7.7 и 8.2. Если вам необходимо поддерживать обновления с использованием более раннего механизма на основе zsync, добавьте "zsync" в этот список.

build.version = None

Задаёт версию сборки, используемую процессом создания дистрибутива. Если None, по умолчанию используется config.version. Основное назначение — позволить использовать в config.version символы, недопустимые в именах файлов или папок.
