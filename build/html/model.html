Модельный рендеринг

Хотя Ren'Py традиционно используется для отображения двухмерных прямоугольных изображений, типичных для визуальных новелл, внутри движка работает модельный рендерер (Model-Based Renderer), созданный для полного использования возможностей современных графических процессоров (GPU). Это позволяет реализовывать множество визуальных эффектов, невозможных ранее.

Предупреждение

Это одна из самых продвинутых систем в Ren'Py. Во многих случаях понимать внутреннее устройство модельного рендерера не требуется: такие функции, как matrixcolor и поддержка Live2D, можно использовать без глубоких знаний графического конвейера. Данная документация предназначена для опытных разработчиков и создателей расширений.

Модельный рендеринг опирается на принципы OpenGL, OpenGL ES, GLSL и GLSL ES. Поскольку части шейдеров и геометрии передаются напрямую драйверам вашего GPU (которые могут вести себя по-разному), важно тестировать проект на различном оборудовании.

Модели, Render-объекты и операции отрисовки

Базовым элементом, который Ren'Py выводит на экран, является Модель (Model). Модель состоит из:

  • Полигональной сетки (Mesh) из одного или нескольких треугольников. Треугольник состоит из трёх вершин, каждая из которых содержит позицию в 2D или 3D пространстве и может содержать дополнительные атрибуты (чаще всего текстурные координаты).

  • Нуля или более текстур (точное количество ограничено GPU; все современные GPU поддерживают не менее трёх текстур на модель). Текстура — это прямоугольная область памяти с изображением на GPU.

  • Списка имён фрагментов шейдеров (shader parts). Ren'Py собирает из этих фрагментов итоговые шейдеры — программы, выполняемые на GPU. Имена фрагментов могут иметь префикс "-", чтобы исключить данный фрагмент.

  • Значений uniform-переменных. Uniform — это константные данные, одинаковые для всей модели (например, сплошной цвет).

  • GL-свойств (флаги режима фильтрации, маски цветов, функции смешивания).

Поскольку на экране отображается множество элементов, Ren'Py строит дерево объектов Render. Эти объекты Render могут содержать в качестве дочерних элементов Модели или другие Render-объекты. Объект Render содержит:

  • Список дочерних элементов со смещением (offset) для каждого.

  • Матрицу Matrix, описывающую трансформацию дочерних элементов в 3D пространстве.

  • Списки фрагментов шейдеров, uniform-переменных и GL-свойств.

  • Флаги обновления области отсечения (clipping polygon).

Ren'Py отрисовывает экран путём обхода дерева Render-объектов в глубину до обнаружения Модели. В процессе обхода обновляются матрица трансформации, область отсечения и списки шейдеров. При достижении Модели на GPU активируется скомпилированная шейдерная программа, передаются все данные и выполняется аппаратная операция отрисовки (draw call).

Где создаются Модели

Ren'Py создаёт Модели автоматически в ходе стандартной работы. Понимание того, где создаются модели, важно потому, что именно к ним применяются шейдеры:

Изображения и графические манипуляторы

Создают модель с полигональной сеткой из двух треугольников, покрывающих прямоугольник изображения. Сетка содержит текстурные координаты. Модель использует шейдер "renpy.texture".

Solid()

Создаёт сетку из двух треугольников без текстурных координат. Модель использует шейдер "renpy.solid", а цвет передаётся через uniform-переменную u_renpy_solid_color.

Dissolve(), ImageDissolve(), AlphaDissolve(), Pixellate(), AlphaMask(), Flatten()

Каждый из этих переходов и отображаемых объектов создаёт Модель с сеткой, шейдерами и uniforms, необходимыми для выполнения эффекта.

Live2D

Отображаемые объекты Live2D при рендеринге создают несколько Моделей — обычно по одной на каждый слой/меш.

Transform() и ATL

Трансформация создаёт модель, если свойство mesh равно True или используется blur. В этом случае дочерние элементы рендерятся в текстуры, а сетка первой текстуры используется для модели. Не каждая трансформация создаёт модель: некоторые просто добавляют шейдеры и uniforms к Render-объекту (например, alpha), другие влияют только на геометрию.

Render

Объект Render создаёт модель, если его атрибут mesh равен True.

Генерация шейдерных программ

Ren'Py генерирует шейдерную программу, сначала собирая список имён фрагментов шейдеров: стандартный "renpy.geometry", фрагменты из объектов Render и фрагменты из самой выводимой Модели.

Затем список дедуплицируется. Если фрагмент начинается с "-", он удаляется из списка вместе с соответствующим фрагментом без префикса "-" (так, "-renpy.geometry" удалит и себя, и "renpy.geometry").

Далее Ren'Py извлекает списки переменных, функций, фрагментов вершинного шейдера и фрагментов пиксельного (фрагментного) шейдера. Они собираются в исходный код шейдеров, при этом части шейдеров включаются в порядке возрастания целочисленного приоритета.

Это означает, что любая переменная, созданная одним фрагментом шейдера, будет доступна всем последующим фрагментам. В GLSL нет изоляции областей видимости, как в функциях Python.

Ren'Py кэширует скомпилированные комбинации шейдеров в файле game/cache/shaders.txt и загружает их при запуске.

Когда config.predict_shaders равно True, комбинации шейдеров компилируются во время фонового предсказания.

Динамические системы могут регистрировать ожидаемые комбинации шейдеров через renpy.start_predict_shader() и удалять через renpy.stop_predict_shader().

Создание пользовательских шейдеров

Новые фрагменты шейдеров регистрируются с помощью функции renpy.register_shader с передачей кода GLSL.

Имена фрагментов обычно имеют формат "пространство_имён.имя", например "mygame.recolor" или "mylibrary.warp". Имена, начинающиеся с "renpy.", "live2d." или "_", зарезервированы.

renpy.register_shader(name, **kwargs)

Регистрирует фрагмент шейдера (shader part). Принимает name и именованные аргументы.

name

Строка, задающая имя фрагмента шейдера. Имена, начинающиеся со знака подчёркивания или префикса "renpy.", зарезервированы для Ren'Py.

glsl

Диалект языка GLSL, на котором написан фрагмент: 300 для GLSL ES 3.00 или 100 для GLSL ES 1.00.

По умолчанию None — используется значение переменной config.glsl_version: 300 для новых проектов и 100 для проектов с совместимостью с Ren'Py 8.5 или более ранними версиями.

Ren'Py автоматически транслирует код между диалектами, поэтому часть с glsl=300 будет работать и на устройствах с GLSL ES 1.00, если в ней не используются отсутствующие возможности.

Если диалект не указан и фрагмент трактуется как GLSL ES 3.00, производится проверка на конструкции, существующие только в GLSL ES 1.00 (такие как gl_FragColor, texture2D, attribute и varying). Обнаружение таких конструкций вызовет ошибку.

Квалификаторы layout зарезервированы для объявления дополнительных выводов фрагментного шейдера при будущей поддержке multiple render targets: location 0 соответствует стандартному fragment_color Ren'Py, а дополнительные выводы начинаются с 1. Обычное ключевое слово out передаёт значение из вершинного шейдера во фрагментный.

variables

Переменные, используемые фрагментом шейдера, по одной на строку: класс хранения, тип, имя и точка с запятой.

В glsl=300 классами хранения являются uniform, in для значений из сетки или out для значений, передаваемых из вершинного шейдера во фрагментный:

variables='''
uniform sampler2D tex0;
in vec2 a_tex_coord;
out vec2 v_tex_coord;
'''

В glsl=100 используются uniform, attribute или varying:

variables='''
uniform sampler2D tex0;
attribute vec2 a_tex_coord;
varying vec2 v_tex_coord;
'''
vertex_functions

Строка, содержащая функции, включаемые в вершинный шейдер.

fragment_functions

Строка, содержащая функции, включаемые во фрагментный шейдер.

Другие именованные аргументы должны начинаться с vertex_ или fragment_ и оканчиваться целочисленным приоритетом (например, "fragment_200" или "vertex_300"). Они содержат код, вставляемый в соответствующий шейдер с указанным приоритетом (меньшие номера вставляются перед большими).

Ren'Py поддерживает следующие типы переменных в шейдерах:

  • float (вещественное число Python)

  • vec2 (кортеж из 2 чисел)

  • vec3 (кортеж из 3 чисел)

  • vec4 (кортеж из 4 чисел)

  • int (целое число Python)

  • ivec2 (кортеж из 2 целых чисел)

  • ivec3 (кортеж из 3 целых чисел)

  • ivec4 (кортеж из 4 целых чисел)

  • bool (логическое значение)

  • bvec2 (кортеж из 2 bool)

  • bvec3 (кортеж из 3 bool)

  • bvec4 (кортеж из 4 bool)

  • type[n] (массив из [n] элементов любого типа выше, например int[5])

  • mat2, mat3, mat4 (объект Matrix)

  • sampler2D (отображаемый объект, строка пути к изображению или Render)

Имена uniform-переменных должны начинаться с префикса u_, атрибутов — с a_, а интерполируемых переменных (varying) — с v_. Имена, начинающиеся с u_renpy_, a_renpy и v_renpy, зарезервированы.

Приоритет 100 обычно настраивает геометрию, приоритет 200 вычисляет исходный цвет фрагмента (fragment_color или gl_FragColor при glsl=100), а более высокие приоритеты накладывают эффекты.

Пример фрагмента шейдера, накладывающего горизонтальный градиент:

init python:

    renpy.register_shader("example.gradient", variables="""
        uniform vec4 u_gradient_left;
        uniform vec4 u_gradient_right;
        uniform vec2 u_model_size;
        out float v_gradient_done;
        in vec4 a_position;
    """, vertex_300="""
        v_gradient_done = a_position.x / u_model_size.x;
    """, fragment_300="""
        float gradient_done = v_gradient_done;
        fragment_color *= mix(u_gradient_left, u_gradient_right, gradient_done);
    """)

Шейдер можно применить через трансформацию:

transform gradient:
    shader "example.gradient"
    u_gradient_left (1.0, 0.0, 0.0, 1.0)
    u_gradient_right (0.0, 0.0, 1.0, 1.0)

show eileen happy at gradient

Версии GLSL. Фрагменты шейдеров пишутся на одном из двух диалектов: GLSL ES 3.00 (основной диалект, используемый в этой документации) или GLSL ES 1.00.

В GLSL ES 3.00 переменные объявляются как uniform, in для входных значений из сетки и out для значений, передаваемых из вершинного шейдера во фрагментный. Выборка текстур производится функцией texture(), а фрагментный шейдер записывает цвет в fragment_color.

define config.glsl_version = 300

Версия по умолчанию для фрагментов шейдеров без явного указания glsl. По умолчанию 300 в новых проектах и 100 в проектах с совместимостью с Ren'Py 8.5 или ранее.

Ren'Py автоматически транслирует код между диалектами, поэтому фрагменты на разных версиях могут сочетаться в одном шейдере. GLSL ES 3.00 рекомендуется для всех новых шейдеров.

На мобильных платформах и Web Ren'Py компилирует шейдеры как GLSL ES 3.00. На настольных платформах используется GLSL 3.30 (или GLSL 1.20 при отсутствии поддержки OpenGL 3.3, например на macOS).

Переменные имеют точность highp (числа с плавающей запятой в диапазоне от 2-62 до 262, 32-битные целые числа в GLSL ES 3.00).

Переменная для отладки шейдеров:

define config.log_gl_shaders = False

Если True, исходный код шейдеров GLSL записывается в log.txt при запуске.

Локальные переменные фрагментов шейдера

Переменные можно сделать локальными для конкретного фрагмента шейдера, используя префиксы u__, a__, v__ или l__. Двойное подчёркивание автоматически заменяется на имя шейдера с заменой точек на подчёркивания. Например, для шейдера example.gradient префикс u__ станет u_example_gradient_.

Это активно используется в текстовых шейдерах, где большинство uniform-переменных являются локальными.

Трансформации и модельный рендеринг

Модельный рендеринг добавляет следующие свойства в язык ATL и класс Transform():

mesh
Type:

None, True или кортеж

Default:

None

Если не None, трансформация отрисовывается как модель:

  • Создаётся полигональная сетка. Если передан кортеж из 2 чисел, он задаёт количество точек сетки по осям X и Y (каждое измерение не менее 2). Если True, сетка берётся из дочернего элемента.

  • Дочерний элемент рендерится в текстуру.

  • Добавляется шейдер renpy.texture.

По умолчанию текстура не мипмаппируется. Чтобы включить мипмапы, установите gl_mipmap True.

mesh_pad
Type:

None или кортеж

Default:

None

Кортеж из 2 или 4 чисел. Задаёт внутренний отступ для текстур сетки (для кортежа из 2 чисел — справа и снизу; из 4 чисел — слева, сверху, справа и снизу).

Используется вместе со свойством gl_pixel_perfect для рендеринга текста в сетку. Текст рендерится в разрешении экрана и может слегка выходить за границы исходной текстуры. Добавление нескольких пикселей отступа предотвращает обрезание глифов:

transform adjust_text:
    mesh True
    mesh_pad (10, 0)
    gl_pixel_perfect True
    shader "shaders.adjust_text"
shader
Type:

None, str или список str

Default:

None

Имя фрагмента шейдера или список имён фрагментов шейдеров, применяемых к данной Модели.

blend
Type:

None или str

Default:

None

Режим наложения. Строка ищется в словаре config.gl_blend_func для установки свойства gl_blend_func. Стандартные режимы: "normal", "add", "multiply", "min" и "max".

Кроме того, все uniform-переменные, начинающиеся с u_ (кроме u_renpy_), доступны как свойства Transform. GL-свойства доступны как свойства Transform с префиксом gl_ (например, gl_color_mask).

Функции смешивания (Blend Functions)

define config.gl_blend_func = { ... }

Словарь, сопоставляющий имя режима наложения (blend mode) с функцией смешивания. Режимы наложения передаются в свойство gl_blend_func.

Режимы наложения по умолчанию:

gl_blend_func["normal"] = (GL_FUNC_ADD, GL_ONE, GL_ONE_MINUS_SRC_ALPHA, GL_FUNC_ADD, GL_ONE, GL_ONE_MINUS_SRC_ALPHA)
gl_blend_func["add"] = (GL_FUNC_ADD, GL_ONE, GL_ONE, GL_FUNC_ADD, GL_ZERO, GL_ONE)
gl_blend_func["multiply"] = (GL_FUNC_ADD, GL_DST_COLOR, GL_ONE_MINUS_SRC_ALPHA, GL_FUNC_ADD, GL_ZERO, GL_ONE)
gl_blend_func["min"] = (GL_MIN, GL_ONE, GL_ONE, GL_MIN, GL_ONE, GL_ONE)
gl_blend_func["max"] = (GL_MAX, GL_ONE, GL_ONE, GL_MAX, GL_ONE, GL_ONE)

Поскольку Ren'Py использует предварительно умноженную альфу (premultiplied alpha), цвета пикселей в GPU представлены как (r * a, g * a, b * a, a). Функции смешивания оперируют этими значениями, что может давать результаты, визуально отличающиеся от стандартных режимов наложения в графических редакторах на полупрозрачных пикселях.

Скалярные, текстурные и векторные Uniform-переменные

Следующие uniform-переменные доступны во всех моделях:

vec2 u_model_size

Ширина и высота модели в пикселях. Доступна для 2D-моделей; для 3D-моделей равна (0, 0).

float u_lod_bias

Смещение уровня детализации (LOD bias) при выборке текстур. Значение по умолчанию берётся из переменной config.gl_lod_bias (-0.5), что заставляет Ren'Py выбирать более крупный уровень мипмапа и масштабировать его вниз для максимальной чёткости.

float u_time

Время текущего кадра в секундах. Отсчёт циклически сбрасывается раз в сутки (по модулю 86400).

vec4 u_random

Четыре псевдослучайных числа от 0.0 до 1.0, меняющихся от кадра к кадру.

vec4 u_viewport

Текущая область вывода (viewport). u_viewport.xy — координаты нижнего левого угла viewport относительно окна, u_viewport.pq — ширина и высота.

vec2 u_virtual_size

Виртуальное разрешение игры (config.screen_width, config.screen_height). Используется для пересчёта координат из gl_Position в виртуальные координаты:

v_position = u_virtual_size * vec2(gl_Position.x * .5 + .5, -gl_Position.y * .5 + .5);
vec2 u_drawable_size

Фактический размер области отрисовки окна в физических пикселях (например, (1920, 1080) при масштабировании окна игры 1280x720 на FullHD мониторе).

sampler2D tex0, sampler2D tex1, sampler2D tex2

Текстурные сэмплеры первой, второй и третьей текстур модели.

vec2 res0, vec2 res1, vec2 res2

Размеры соответствующих текстур в пикселях.

Если доступен текстурный сэмплер, суффикс __res возвращает вектор vec2 с его размером (например, u_markup__res).

Если доступен вектор vec4, суффикс __premul возвращает цвет с предварительно умноженной альфой (например, u_color__premul умножает компоненты r, g и b на альфа-канал).

Матричные Uniform-переменные

Следующие матрицы доступны во всех моделях (предполагается, что трансформация с perspective одна; если их несколько, мировая система координат задаётся самой внутренней):

mat4 u_projection

Матрица перехода из пространства вида (view space) в пространство отсечения OpenGL (clip space). Обновляется свойствами перспективы perspective.

mat4 u_view

Матрица перехода из мирового пространства (world space) в пространство вида (view space). По умолчанию единичная матрица, формируется трансформациями с perspective.

mat4 u_model

Матрица перехода из локального пространства модели (model space) в мировое пространство (world space).

mat4 u_projectionview

Произведение u_projection * u_view. Служит для оптимизации вычислений на GPU.

mat4 u_transform

Произведение u_projectionview * u_model. Преобразует координаты вершин из пространства модели напрямую в пространство отсечения OpenGL.

Суффиксы матриц:

__inverse

Возвращает обратную матрицу (например, u_projection__inverse).

__transpose

Возвращает транспонированную матрицу (например, u_view__transpose).

__inverse_transpose

Возвращает обратную транспонированную матрицу (например, u_model__inverse_transpose). Необходима для корректного преобразования нормалей при масштабировании.

Атрибуты вершин

Следующий атрибут доступен во всех моделях:

vec4 a_position

Координаты визуализируемой вершины в виртуальных пикселях относительно левого верхнего угла текстуры.

При наличии текстур доступен:

vec2 a_tex_coord

Текстурные координаты вершины (UV).

При наличии нормалей доступен:

vec3 a_normal

Вектор нормали вершины.

При наличии касательных доступны:

vec3 a_tangent

Касательный вектор вершины (tangent).

vec3 a_bitangent

Биторганальный (бикасательный) вектор вершины (bitangent).

GL-свойства

GL-свойства управляют глобальным состоянием OpenGL и модельного рендерера. Их можно задавать в трансформациях или через метод Render.add_property().

gl_blend_func

Кортеж из 6 элементов, задающий функции и коэффициенты смешивания пикселей: (rgb_equation, src_rgb, dst_rgb, alpha_equation, src_alpha, dst_alpha). Вызывает системные вызовы OpenGL:

glBlendEquationSeparate(rgb_equation, alpha_equation)
glBlendFuncSeparate(src_rgb, dst_rgb, src_alpha, dst_alpha)

Константы OpenGL импортируются из модуля renpy.uguu:

init python:
    from renpy.uguu import GL_ONE, GL_ONE_MINUS_SRC_ALPHA

Обычно удобнее использовать готовое свойство blend.

gl_color_mask

Кортеж из 4 логических значений (red, green, blue, alpha). Определяет, в какие каналы разрешена запись.

gl_cull_face

Включает отсечение невидимых граней (face culling). Принимает порядок обхода вершин: "cw" (по часовой стрелке) или "ccw" (против часовой стрелки) в системе координат Ren'Py (ось +Y направлена вниз).

gl_depth

Если True, очищает буфер глубины и включает тест глубины (Z-тест) для данного отображаемого объекта и его дочерних элементов.

Обратите внимание: отрисовка любого пикселя (даже полностью прозрачного) обновляет буфер глубины. Для изображений с прозрачностью используйте клаузы zorder и behind оператора show.

gl_pixel_perfect

Если True, первая вершина сетки точно совмещается с физическим пикселем экрана. Используется для сохранения максимальной резкости текста.

gl_anisotropic

Определяет, применяется ли анизотропная фильтрация к текстурам сетки. По умолчанию True.

gl_texture_scaling

Режим фильтрации текстур при масштабировании:

  • "nearest"

  • "linear"

  • "nearest_mipmap_nearest"

  • "linear_mipmap_nearest"

  • "nearest_mipmap_linear"

  • "linear_mipmap_linear"

Можно настраивать для конкретных текстур: gl_texture_scaling_tex0, gl_texture_scaling_tex1 и т. д.

gl_texture_wrap

Кортеж из 2 элементов, задающий режим адресации текстуры по осям S и T (горизонтали и вертикали):

init python:
    from renpy.uguu import GL_CLAMP_TO_EDGE, GL_MIRRORED_REPEAT, GL_REPEAT

Также настраивается индивидуально: gl_texture_wrap_tex0 и т. д.

Следующие свойства действуют при создании текстуры в Transform с mesh или в объекте Model():

gl_drawable_resolution

Если True, текстура отрисовывается в физическом разрешении экрана игры. Если False — в исходном виртуальном разрешении отображаемого объекта.

gl_mipmap

Определяет, создаются ли мипмапы для текстур сетки. По умолчанию True.

Отображаемый объект GLTFModel

Отображаемый объект GLTFModel позволяет загружать трёхмерные модели в формате GLTF. Это основной способ использования сторонних 3D-моделей в Ren'Py.

class GLTFModel(filename: 'str', shader: 'str | tuple[str]' = (), tangents: 'bool' = False, zoom: 'float' = 1.0, report: 'bool' = False, **kwargs)

Отображаемый объект, загружающий 3D-модель в формате GLTF. Этот формат поддерживается большинством программ для 3D-моделирования. Ren'Py использует библиотеку Open Asset Importer (assimp) для загрузки моделей GLTF.

Для двухмерной системы разметки Ren'Py объект GLTFModel имеет нулевую ширину и высоту. По умолчанию модель загружается с размерами, указанными в исходном файле. При необходимости масштабирования используйте параметр zoom.

При использовании нескольких моделей к камере следует применить свойство gl_depth True для включения буфера глубины. В настоящее время Ren'Py не выполняет отсечение невидимой геометрии (culling), поэтому важно использовать модели, достаточно оптимизированные для полной отрисовки.

filename

Имя файла модели для отображения.

shader

Строка или кортеж строк с именами используемых шейдеров.

tangents

Если True, в полигональную сетку включаются касательные векторы (tangents).

zoom

Коэффициент масштабирования, применяемый к модели. Многие модели создаются в диапазоне от -1 до 1, поэтому этот коэффициент может быть достаточно большим, чтобы сделать модель видимой.

report

Если True, подробный отчёт о модели и используемых ею uniform-переменных выводится в файл log.txt.

Рекомендации:

  • Некоторые модели имеют очень малый масштаб и требуют увеличения в 100 или 1000 раз через параметр zoom.

  • Набор uniform-переменных различается в зависимости от материалов модели.

Рекомендуется создавать GLTFModel с параметром report=True и просматривать файл log.txt для анализа доступных uniform-переменных и текстур.

Ограничения

GLTFModel не содержит шейдера по умолчанию, поэтому шейдер необходимо объявить и передать явно. Пример базового шейдера освещения для GLTFModel:

init python:

    renpy.register_shader("example.lighting", variables="""
        uniform mat4 u_model__inverse_transpose;
        uniform vec4 u_color_diffuse;
        uniform vec4 u_color_specular;
        uniform sampler2D u_tex_diffuse;

        out vec3 v_normal;
        out vec2 v_tex_coord;

        in vec3 a_normal;
        in vec2 a_tex_coord;
""", vertex_201="""
        v_normal = (u_model__inverse_transpose * vec4(a_normal, 1.0)).xyz;
        v_tex_coord = a_tex_coord;
""", fragment_201="""

        // Направление источника света.
        vec3 lightDir = normalize(vec3(0.0, -1000.0, 1000.0));

        vec3 normal = normalize(v_normal);

        float lambertian = max(dot(normal, lightDir), 0.0);
        vec4 diffuse_color = texture(u_tex_diffuse, v_tex_coord);
        diffuse_color *= vec4(lambertian * u_color_diffuse.rgb * u_color_diffuse.a, u_color_diffuse.a);

        vec3 viewDir = normalize(vec3(0.0, 0.0, -1.0));
        vec3 halfDir = normalize(lightDir + viewDir);
        float specular = pow(max(dot(normal, halfDir), 0.0), 4.0);

        vec4 specular_color = vec4(u_color_specular.rgb * u_color_specular.a * specular, u_color_specular.a * specular);

        fragment_color = diffuse_color + specular_color;

        if (fragment_color.a < 0.9) {
            discard;
        }
""")

GLTFModel ограниченно поддерживает прозрачные поверхности: хотя команда discard эмулирует прозрачность, порядок отрисовки треугольников может вызывать визуальные артефакты.

Отображаемый объект Model

Класс Model служит фабрикой создания программных моделей для модельного рендерера в Python.

class Model(size=None, **properties)

Отображаемый объект, создающий 2D или 3D-модель для визуализации в модельном рендерере Ren'Py, отрисовываемый за одну операцию отрисовки с указанными шейдерами или шейдерами, заданными внешней трансформацией или отображаемым объектом.

size

Если не None, кортеж (width, height), задающий размер Model. Если не указан, размер модели соответствует выделенной области. Параметр fit текстуры имеет приоритет.

Если метод сетки mesh не вызван явно, создаётся стандартная сетка с атрибутами a_position и a_tex_coord (если добавлена хотя бы одна текстура) или сетка только с a_position.

Все методы этого класса возвращают сам объект, позволяя выстраивать цепочки вызовов (fluent interface).

child(displayable, fit=False)

Аналогичен методу texture, но параметры focus и main принудительно установлены в True.

grid_mesh(width, height)

Создаёт полигональную сетку из сетки равномерно распределённых точек размером width x height, соединяя соседние точки по вертикали и горизонтали и разделяя прямоугольники сетки на треугольники.

width, height

Количество точек по горизонтали и вертикали (целые числа не менее 2).

property(name, value)

Устанавливает значение GL-свойства.

name

Строка с именем GL-свойства (включая префикс "gl_").

value

Значение GL-свойства.

shader(shader)

Добавляет шейдер к этой модели.

shader

Строка с именем используемого шейдера.

texture(displayable, focus=False, main=False, fit=False, texture_wrap=None)

Добавляет текстуру к модели путём рендеринга переданного отображаемого объекта. Первая добавленная текстура будет доступна как tex0, вторая — tex1 и так далее.

focus

Если True, события фокуса передаются отображаемому объекту.

main

Если True, объект помечается как основной дочерний элемент для инспектора отображаемых объектов.

fit

Если True, модель принимает размер отображаемого объекта (может быть True только для одной текстуры).

texture_wrap

Если не None, GL-свойство gl_texture_wrap, применяемое к текстуре.

uniform(name, value)

Устанавливает значение uniform-переменной, передаваемой в шейдеры.

name

Имя uniform-переменной (включая префикс "u_").

value

Значение uniform-переменной (число с плавающей запятой, кортеж из 2, 3 или 4 вещественных чисел или объект Matrix).

Примеры использования Model

Объект Model в сочетании с трансформацией ATL и встроенным шейдером позволяет воссоздать эффект Dissolve:

transform dt(delay=1.0, new_widget=None, old_widget=None):
    delay delay
    Model().texture(old_widget).child(new_widget)
    shader [ 'renpy.dissolve' ]

    u_renpy_dissolve 0.0
    linear delay u_renpy_dissolve 1.0

Использование объекта Model в качестве дочернего элемента несовместимо со свойством mesh, так как оба механизма создают внутренние модели в Ren'Py.

Анимированные шейдеры

При создании шейдеров, зависящих от переменной времени u_time, необходимо помнить: Ren'Py не обновляет экран с постоянной частотой кадров без необходимости и снижает частоту до 5 кадров/сек, если нет отображаемых объектов, требующих перерисовки.

Чтобы анимированный шейдер работал плавно без задержек, добавьте пустой цикл ATL, форсирующий перерисовку:

transform fancy_shader:
    shader 'my_fancy_shader'
    pause 0
    repeat

Команда pause 0 заставляет движок обновлять кадры с максимальной частотой экрана. Для ограничения частоты кадров можно указать фиксированное значение, например pause 1.0/30.
