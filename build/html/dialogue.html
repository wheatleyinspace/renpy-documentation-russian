Диалог и повествование

Текст лежит в основе визуальных новелл и играет важнейшую роль в играх, ориентированных на сюжет. Этот текст может состоять из реплик диалога с указанием говорящего персонажа и повествования (слов автора), у которого нет конкретного говорящего. (Для удобства мы будем объединять диалог и повествование под общим понятием диалога, за исключением случаев, когда различия между ними принципиальны.) Также важно, чтобы разработчик мог настроить внешний вид диалога под стиль своей игры.

В Ren'Py большая часть текста пишется с помощью инструкций say. Внешний вид реплик можно настраивать индивидуально для каждого персонажа с помощью объектов Character.

Инструкция say

Инструкция say используется для вывода диалога и повествования. Поскольку это почти всегда самая часто используемая инструкция в скриптах Ren'Py, её синтаксис минимизирует усилия при написании. Вот несколько примеров инструкций say:


    "Это слова автора (повествование)."

    "Эйлин" "Это диалог с явным указанием имени персонажа строкой."

    e "Это диалог с использованием объекта Character."

    "Бабах!!" with vpunch

Первая форма инструкции say состоит из одиночной строки текста. Эта форма используется для повествования (слов автора), при этом содержимое строки является самим текстом.

Вторая форма состоит из двух строк. Первая строка — это имя говорящего персонажа, а вторая — произносимая реплика диалога.

Третья форма состоит из простого выражения, за которым следует строка. Простое выражение должно вычисляться либо в строку с именем персонажа, либо в объект Character. В последнем случае объект Character определяет правила отображения диалога.

Последняя форма состоит из строки и конструкции with, содержащей переход. В этом случае отображается строка текста и одновременно с этим встряхивается экран.

Хотя конкретное поведение инструкции say определяется используемым объектом Character, обычно инструкция say отображает диалог на экране до тех пор, пока игрок не кликнет для его закрытия, после чего скрывает этот диалог с экрана.

Некоторые символы имеют специальное значение для Ren'Py и не могут использоваться в строках диалога напрямую. Символ { начинает текстовый тег, а символ [ начинает подстановку переменной. Чтобы использовать их в тексте диалога, удвойте их: {{ или [[. Также может потребоваться экранировать кавычки обратным слэшем, чтобы они не закрывали строку раньше времени. Например:

"Я прошёл мимо вывески с надписью: \"Выложимся на все 100%%!\""

Вместо объекта Character можно также использовать прокси-функцию. Подробнее об этом см. в соответствующем разделе.

Определение объектов Character

Создавая объект Character и используя его в инструкции say, вы можете настраивать внешний вид (и в некоторой степени поведение) диалога. Персонажи создаются с помощью инструкции define, присваивающей объект Character переменной. Например:

define e = Character("Эйлин", who_color="#c8ffc8")

После этого персонажа можно использовать в инструкции say:

e "Привет, мир."

Character — это функция Python, принимающая множество именованных аргументов. Эти аргументы управляют поведением персонажа.

Character(name=..., kind=adv, **args)

Создаёт и возвращает объект Character, управляющий внешним видом и поведением диалога и повествования.

name

Если строка — имя персонажа для диалога. Если name равно None, отображение имени опускается, как при повествовании (словах автора). Если имя не указано, оно берётся из kind, а в противном случае по умолчанию равно None.

kind

Объект Character, на основе которого создаётся данный персонаж. При использовании значение по умолчанию для любого аргумента, не переданного явно данному Character, берётся из значений, переданных в kind. Это позволяет определить базовый шаблон персонажа, а затем копировать его с необходимыми изменениями.

Также может быть пространством имён; в этом случае в качестве kind используется переменная 'character' из этого пространства имён.

Связанное изображение (Linked Image). С персонажем можно связать тег изображения. Это позволяет инструкции say с участием этого персонажа отображать изображение с этим тегом, а также позволяет Ren'Py автоматически выбирать боковое изображение для показа во время реплики этого персонажа.

image

Строка, задающая тег изображения, связанный с этим персонажем.

Тег озвучки (Voice Tag). Если персонажу назначен тег озвучки, аудиофайлы голоса, связанные с ним, можно заглушать или воспроизводить на экране настроек.

voice_tag

Строка, позволяющая заглушать или воспроизводить привязанный к персонажу аудиофайл озвучки в канале 'voice'.

Префиксы и суффиксы. Позволяют добавлять префикс и суффикс к имени персонажа и к отображаемому тексту реплики. Это можно использовать, например, для автоматического заключения каждой реплики диалога в кавычки.

what_prefix

Строка, добавляемая перед произносимой репликой диалога перед её показом.

what_suffix

Строка, добавляемая в конец произносимой реплики диалога перед её показом.

who_prefix

Строка, добавляемая перед именем персонажа перед его показом.

who_suffix

Строка, добавляемая в конец имени персонажа перед его показом.

Настройка отображения имени. Эти параметры помогают управлять отображением имени.

dynamic

Если true, то name должно быть либо строкой с выражением Python, либо функцией, либо вызываемым объектом. Если это строка, она будет вычисляться перед каждой строкой диалога, а результат будет использоваться как имя персонажа. В противном случае функция или вызываемый объект будут вызываться без аргументов перед каждой строкой диалога, и возвращённое значение будет использовано в качестве имени персонажа.

Управление взаимодействием. Эти параметры определяют, отображается ли диалог, происходит ли взаимодействие с пользователем и какой режим активируется при показе.

warp

Если true (по умолчанию), диалоги этого персонажа могут воспроизводиться во время перехода к строке для восстановления истории, страниц NVL и сохранённых спич-бабблов. Повтор не вызывает взаимодействия с пользователем. Установите False, если пользовательское поведение персонажа не может безопасно выполняться во время warp.

condition

Если задано, должно быть строкой с выражением Python. Если выражение ложно, диалог не отображается, как если бы инструкция say вообще не выполнялась.

interact

Если true (по умолчанию), взаимодействие с пользователем происходит при каждом показе диалога. Если false, взаимодействие не происходит, и на экран можно добавлять дополнительные элементы.

advance

Если true (по умолчанию), игрок может кликнуть для продвижения по диалогу, а также работают другие способы перехода (такие как пропуск и режим авточтения). Если false, игрок не сможет продвинуться дальше этой инструкции say, если не предоставлен альтернативный способ (например, гиперссылка перехода jump или экран).

callback

Функция, которая вызывается при возникновении событий во время реплики персонажа. Подробнее см. раздел Функции обратного вызова персонажа.

Индикатор продолжения по клику (Click-to-continue / CTC). Индикатор продолжения по клику отображается после завершения вывода всего текста, подсказывая пользователю нажать для продолжения.

ctc

Отображаемый объект, используемый в качестве индикатора продолжения по клику, если не задан более специфичный индикатор.

ctc_pause

Отображаемый объект для индикатора клика, когда вывод текста приостановлен текстовыми тегами {p} или {w}.

ctc_timedpause

Отображаемый объект для индикатора клика, когда вывод текста приостановлен текстовыми тегами {p=} или {w=}. Если None, значение берётся из ctc_pause. Используйте Null(), если нужен ctc_pause, но не нужен ctc_timedpause.

ctc_position

Управляет расположением индикатора продолжения по клику:

"nestled"

Индикатор отображается как часть выводимого текста сразу после последнего символа.

"nestled-close"

Аналогично "nestled", но перенос строки между текстом и индикатором CTC запрещён.

"fixed"

Если экран с именем "ctc" существует, отображается он. В противном случае отображается объект CTC, а для его позиционирования используются свойства стиля положения объекта CTC.

"screen-variable"

При передаче этого значения переменной с именем "ctc" присваивается отображаемый объект CTC, когда индикатор CTC должен быть показан. Это можно использовать в языке экранов следующим образом:

default ctc = None
showif ctc:
    add ctc

Экраны. Для вывода диалога используется экран. Эти аргументы позволяют выбрать этот экран и передать ему параметры.

screen

Имя экрана, используемого для отображения диалога.

retain

Если значение не True, для каждой строки диалога генерируется неиспользуемый тег, и экраны показываются непостоянно (non-transiently). Вызовите renpy.clear_retain(), чтобы удалить все сохранённые экраны. Практически всегда используется вместе с Текстовые облачка (Speech Bubbles).

Именованные аргументы, начинающиеся с show_, отбрасывают этот префикс и передаются экрану в качестве аргументов. Например, значение show_myflag станет значением переменной myflag в экране. (Переменная myflag не используется по умолчанию, но может использоваться в пользовательском экране say.)

Одна переменная показа по историческим причинам обрабатывается самим Ren'Py:

show_layer

Если задано, строка с именем слоя, на котором должен отображаться экран say.

Стилизация текста и окон. Именованные аргументы, начинающиеся с who_, what_ и window_, отбрасывают префикс и используются для стилизации имени персонажа, произносимого текста и содержащего их окна соответственно.

Например, если персонажу передан аргумент who_color="#c8ffc8", цвет имени персонажа изменится (в данном случае на зелёный). Аргумент window_background="frame.png" задаёт фоновое изображение окна с диалогом этого персонажа.

Стиль, применяемый к имени персонажа, тексту реплики и окну, также можно задать этим способом с помощью аргументов who_style, what_style и window_style соответственно.

Настройка config.character_id_prefixes позволяет стилизовать и другие отображаемые объекты. Например, при использовании стандартного GUI стили с префиксом namebox_ используются для оформления плашки имени говорящего персонажа.

Инструкция say с атрибутами изображений

Когда персонаж определён со связанным тегом изображения, инструкция say с участием этого персонажа может содержать атрибуты изображения, размещённые между именем персонажа и строкой реплики.

В этой форме, если изображение с указанным тегом уже отображается на экране, Ren'Py выполнит команду show с тегом персонажа и указанными атрибутами. Если изображение ещё не показано, Ren'Py сохранит эти атрибуты для использования боковыми изображениями, но не станет показывать само изображение.

Например:

define e = Character("Эйлин", image="eileen")

label start:

    show eileen concerned
    e "Я немного расстроена из-за тебя."

    e happy "Но это быстро пройдёт."

эквивалентно следующей записи:

define e = Character("Эйлин", image="eileen")

label start:

    show eileen concerned
    e "Я немного расстроена из-за тебя."

    show eileen happy
    e "Но это быстро пройдёт."

В приведённом выше примере атрибуты concerned и happy заменяют друг друга. Однако можно вернуться к Эйлин без атрибута happy, не указывая атрибут concerned явно. Имя атрибута со знаком минус ( - ) перед ним даёт именно такой эффект, точно так же, как и в инструкции show.

Например:

define e = Character("Эйлин")

label start:

    show eileen
    e concerned "Я немного расстроена из-за тебя."

    e happy "Это забавно."

    e -happy "Даже не знаю, что теперь думать."

Если в список атрибутов включён знак @, любой элемент после него оказывает только временный эффект и сбрасывается в конце данной строки диалога.

Например, следующий код эквивалентен предыдущему примеру:

define e = Character("Эйлин", image="eileen")

label start:

    show eileen concerned
    e "Я немного расстроена из-за тебя."

    e @ happy "Это забавно."

    e "Даже не знаю, что теперь думать."

В одной строке можно объединять постоянные изменения, идущие до знака @, и временные, идущие после него:

e happy @ vhappy "Правда?! Это всё меняет."

Знак минус можно также использовать после знака @:

e @ right -concerned "Мой гнев временно утих..."
e "ОДНАКО!"

Чтобы при каждом таком изменении изображений воспроизводился переход, присвойте желаемый переход переменной config.say_attribute_transition. Для более тонкого контроля используйте функцию обратного вызова config.say_attribute_transition_callback.

Примеры персонажей

Вот несколько примеров объявления персонажей:

# Персонаж, реплики которого автоматически заключаются в круглые скобки.
define e = Character("Эйлин", what_prefix='(', what_suffix=')')

# Персонаж, имя которого берётся из переменной.
define p = Character("player_name", dynamic=True)

Специальные персонажи

Несколько имён персонажей определены по умолчанию и используются автоматически в определённых ситуациях. Намеренное переопределение этих персонажей может изменить поведение Ren'Py, но их случайное использование может вызвать проблемы.

adv

Тип персонажа по умолчанию, используемый функцией Character. Настраивает персонажа так, чтобы на экране одновременно отображалась одна строка текста.

nvl

Тип Character, заставляющий диалог отображаться в Руководство по режиму NVL, когда на экране одновременно выводится несколько строк текста.

narrator

Персонаж, используемый для вывода слов автора (повествования) инструкциями say без указания имени персонажа.

name_only

Персонаж, используемый для диалогов, в которых имя персонажа передано строкой. Этот персонаж копируется в нового персонажа с указанным именем, и затем этот новый персонаж используется для вывода диалога.

centered

Персонаж, текст которого отображается по центру экрана вне какого-либо окна.

vcentered

Персонаж, текст которого отображается по центру экрана вертикально ориентированным текстом вне какого-либо окна.

extend

Персонаж, заставляющий последнего говорившего персонажа произнести строку диалога, состоящую из последней произнесённой строки, тега "{fast}" и текста, переданного в extend. Это можно использовать для изменения выражения лица или экрана прямо посреди реплики.

Extend поддерживает режим NVL-mode и обрабатывает его корректно. Extend не работает должным образом, если язык перевода меняется между начальной инструкцией say и вызовом extend.

Например:

# Показываем первую часть реплики, ждём клика, меняем выражение лица и показываем
# остальной текст.

show eileen concerned
e "Иногда мне бывает грустно."
show eileen happy
extend " Но обычно я быстро справляюсь с этим!"

# Аналогично, но выражение лица меняется автоматически сразу по завершении вывода
# первой строки. Это имеет смысл, только если у пользователя скорость текста
# не выкручена на максимум.

show eileen concerned
e "Иногда мне бывает грустно.{nw}"
show eileen happy
extend " Но обычно я быстро справляюсь с этим!"

Управление окном диалога

Ren'Py включает несколько инструкций для управления окном диалога. Поскольку диалоговое окно всегда отображается во время диалога, эти инструкции определяют наличие или отсутствие окна во время взаимодействий, не являющихся диалогом.

window show

Инструкция window show отображает диалоговое окно. В качестве аргумента она принимает необязательный переход, используемый для показа окна. Если переход опущен, используется config.window_show_transition.

window hide

Инструкция window hide скрывает диалоговое окно. В качестве аргумента она принимает необязательный переход, используемый для скрытия окна. Если переход опущен, используется config.window_hide_transition.

window auto True

Включает автоматическое управление окном. Окно показывается перед инструкциями, перечисленными в config.window_auto_show (по умолчанию — инструкции say). Окно скрывается перед инструкциями из списка config.window_auto_hide (по умолчанию — инструкции scene, call screen и инструкции menu без подписи).

Учитываются только синтаксические инструкции, но не их эквивалентные функции Python.

window auto False

Отключает автоматическое управление окном. Окно больше не будет показываться или скрываться автоматически.

Инструкция window auto использует config.window_show_transition и config.window_hide_transition для показа и скрытия окна соответственно. Режим window auto отменяется явными инструкциями window show и window hide.

Например:

window show # показывает окно с переходом по умолчанию, если он задан.
pause       # окно отображается во время этой паузы.
window hide # скрывает окно.
pause       # окно скрыто во время этой паузы.

window show dissolve # показывает окно с переходом dissolve.
pause                # окно отображается во время этой паузы.
window hide dissolve # скрывает окно с переходом dissolve.
pause                # окно скрыто во время этой паузы.


window auto True

"Окно автоматически показывается перед этой строкой диалога."
pause                # окно отображается во время этой паузы.

scene bg washington  # окно скрывается перед сменой сцены.
with dissolve

window show     # Показывает окно раньше, чем оно обычно появилось бы.

show eileen
with dissolve

"Без команды window show окно появилось бы только на этой строке."

Управление окном диалога подчиняется настройке «показывать пустое окно». Если эта настройка отключена игроком, приведённые выше инструкции не действуют.

Инструкция say с аргументами

Инструкции say можно передавать дополнительные аргументы, указав их в круглых скобках после строки реплики. Например, можно написать:

e "Привет, мир." (what_color="#8c8")

Аргументы инструкции say сначала обрабатываются функцией config.say_arguments_callback, если она задана. Оставшиеся аргументы передаются персонажу, который обрабатывает их так, как если бы они были переданы при объявлении персонажа. Таким образом, в приведённом примере реплика отобразится зелёным цветом. Именованный аргумент _with_none переопределяет атрибут with_none персонажа.

Параметр interact является особым случаем: если при определении Character было передано interact=False, передача interact=True в инструкции say не переопределит это значение, то есть взаимодействие с игроком в этом случае всё равно не произойдёт.

Обратите внимание, что config.say_arguments_callback вызывается при каждом выполнении инструкции say, а не только когда аргументы переданы явно. Это удобно для реализации условного переопределения параметров персонажей. Например:

init python:
    def say_arguments_callback(char, *args, **kwargs):
        if colorblind_mode:
            kwargs["what_color"] = "#000"
        return args, kwargs

define config.say_arguments_callback = say_arguments_callback

Режим монолога

В некоторых визуальных новеллах встречаются длинные монологи повествователя или несколько блоков реплик одного и того же персонажа подряд. В таких случаях писать имя персонажа и открывать кавычки на каждой строке утомительно.

Для таких ситуаций Ren'Py поддерживает режим монолога. Если текст диалога помещён в тройные кавычки, Ren'Py разбивает диалог на отдельные блоки по пустым строкам. Каждый блок затем преобразуется в отдельную инструкцию say. Вот пример с тремя блоками слов автора, за которыми следуют три реплики персонажа:

"""
Это первая строка повествования. Она длиннее двух других строк,
поэтому переносится на новую строку.

Это вторая строка повествования.

Это третья строка повествования.
"""

e """
Это первая реплика диалога. Она длиннее двух других реплик,
поэтому переносится на новую строку.

Это вторая реплика диалога.

Это третья реплика диалога.
"""

Хотя дополнительные конструкции (такие как аргументы или атрибуты) разрешены, они передаются каждой строке в монологе, что может быть менее удобно.

Если вы хотите убрать пустые строки между блоками, добавьте директиву rpy monologue single на верхнем уровне файла перед первой строкой монолога.

Если вы хотите полностью отключить такое поведение и отображать весь текст между тройными кавычками как единое сообщение с сохранением переводов строк, используйте директиву rpy monologue none.

Хранилище character

Основная статья: Другие именованные хранилища

Инструкция say ищет имена в именованном хранилище character перед тем, как обратиться к хранилищу по умолчанию. Если вы хотите создать персонажа с тем же именем, что и переменная в хранилище по умолчанию, его можно объявить так:

define character.e = Character("Эйлин")

Этого персонажа затем можно использовать параллельно с переменной в стандартном хранилище:

default e = 0

label start:

    # По-прежнему не лучшее имя для переменной, но допустимое.
    $ e = 100

    e "Текущий запас энергии: [e] единиц."

Это особенно полезно для хранения параметров персонажа в пространстве имён без конфликтов с инструкцией say:

define character.naomi = Character("Наоми Нагата", who_color="#8c8")
default naomi = PersonClass(engineering=5, max_g_force=.7) # может быть объектом...
define character.fred = Character("Фред Джонсон", who_color="#72f")
default fred.money = 1000 # ...или отдельным именованным хранилищем
default fred.rank = "Полковник"

label traded:
    fred "Вот, держи."
    $ fred.money -= 50
    $ naomi.money += 50
    naomi "Спасибо! Я знала, что ты оценишь мои инженерные навыки [naomi.engineering]-го класса."

Альтернативные варианты отображения

Руководство по режиму NVL : режим, в котором диалог выводится на весь экран.

Текстовые облачка (Speech Bubbles) : режим, отображающий диалог в комиксных спич-бабблах (диалоговых облачках), которые можно позиционировать интерактивно.
