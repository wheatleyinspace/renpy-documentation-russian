Постоянные данные

Ren'Py поддерживает постоянные (персистентные) данные — сохранённые данные, не привязанные к конкретной точке прохождения или файлу сохранения игры. Доступ к постоянным данным осуществляется через поля специального объекта, хранящегося в переменной persistent.

Все данные, доступные через поля объекта persistent, автоматически сохраняются на диск при выходе из Ren'Py или при явном вызове функции renpy.save_persistent(). Постоянные данные загружаются при запуске Ren'Py, а также каждый раз, когда движок обнаруживает их изменение на диске.

Объект persistent уникален тем, что обращение к ещё неопределённому полю вернёт значение None вместо вызова исключения AttributeError. Если значение по умолчанию для поля должно быть отличным от None, используйте оператор default:

default persistent.main_background = "princess_not_saved"

Типичным примером использования persistent является создание галереи открываемых иллюстраций. Для этого в persistent сохраняется флаг, определяющий, разблокирована ли галерея:

label gallery:

    if not persistent.gallery_unlocked:
        show background
        centered "Вы ещё не открыли эту галерею."
        $ renpy.full_restart()

    # Здесь отображается сам экран галереи.

Когда игрок достигает концовки, открывающей галерею, флаг устанавливается в True:

$ persistent.gallery_unlocked = True

Поскольку постоянные данные загружаются до выполнения блоков init python, они должны содержать только стандартные встроенные типы Python или Ren'Py. Также можно использовать классы, объявленные в блоках python early, при условии, что они поддерживают сериализацию pickle и реализуют оператор равенства.

Поля, начинающиеся с двух знаков подчёркивания (__), поддерживаются, но подвергаются подмене имён (name mangling), как описано в этом разделе, становясь привязанными к имени исходного файла. Если файл будет переименован в следующем обновлении, доступ к сохранённому значению поля будет утерян. Кроме того, такие поля не сбрасываются методом persistent._clear().

Напоминаем: поля с одним ведущим подчёркиванием _ зарезервированы движком и не должны использоваться.

Слияние постоянных данных

В некоторых случаях Ren'Py выполняет слияние постоянных данных из двух источников — например, при синхронизации данных на флеш-накопителе с локальным компьютером или облачным хранилищем.

По умолчанию слияние выполняется по каждому полю индивидуально: выбирается значение с более свежей меткой времени. Если требуется иное поведение (например, для множества открытых концовок необходимо сохранить объединение обоих множеств), используйте функцию renpy.register_persistent():

init python:
    if persistent.endings is None:
        persistent.endings = set()

    def merge_endings(old, new, current):
        current.update(old)
        current.update(new)
        return current

    renpy.register_persistent('endings', merge_endings)

Функции для работы с постоянными данными

persistent._hasattr(field_name)

Проверяет, было ли установлено поле field_name в объекте persistent. Позволяет отличить поля, явно установленные в None, от полей, к которым ещё ни разу не обращались.

persistent._clear(progress=False)

Сбрасывает все постоянные данные (за исключением полей с префиксом __).

progress

Если True, также сбрасывает данные о прогрессе прохождения игры.

Обратите внимание: после сброса повторно применяются значения операторов default.

renpy.register_persistent(field, func)

Регистрирует функцию слияния значений постоянного поля при загрузке с диска со значениями текущего объекта persistent.

field

Имя поля объекта persistent.

function

Функция, принимающая три параметра: old, new и current:

old

Значение поля в более старом объекте данных.

new

Значение поля в более новом объекте данных.

current

Значение поля в текущем объекте persistent (позволяет мутировать существующий объект).

Функция должна вернуть новое итоговое значение поля объекта persistent.

renpy.save_persistent()

Сохраняет постоянные данные на диск.

Межигровые постоянные данные

Межигровая сохраняемость данных (Multi-Game Persistence) позволяет обмениваться информацией между различными играми на Ren'Py (например, в рамках серии эпизодических новелл).

Для использования межигровых данных на этапе инициализации создаётся объект MultiPersistent (рекомендуется использовать оператор define). Затем игра может изменять этот объект и сохранять его на диск методом save. Неопределённые поля по умолчанию равны None. Чтобы объект мог быть корректно загружен в другой игре, настоятельно рекомендуется хранить в нём только стандартные базовые типы данных.

class MultiPersistent(name, save_on_quit=False)

Создаёт объект MultiPersistent. Должен вызываться только на этапе инициализации и возвращает новый объект с указанным именем name.

name

Имя для доступа к межигровым данным. Игры с одинаковым именем получают доступ к общим данным.

save_on_quit

Если True, объект автоматически сохраняется при выходе из игры.

save()

Сохраняет межигровые данные на диск. Метод необходимо вызывать после каждой модификации данных.

Пример в первой части игры:

define mp = MultiPersistent("demo.renpy.org")

label start:

    # ...

    # Записываем факт прохождения первой части игры.

    $ mp.beat_part_1 = True
    $ mp.save()

    e "Вы прошли часть 1. До встречи в части 2!"

И во второй части:

define mp = MultiPersistent("demo.renpy.org")

label start:

    if mp.beat_part_1:
        e "Я вижу, вы прошли часть 1, с возвращением!"
    else:
        e "Хм, кажется, вы не играли в часть 1. Почему бы не попробовать сначала её?"
