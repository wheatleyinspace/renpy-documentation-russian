Несовместимые изменения

В этом разделе перечислены изменения, которые могут потребовать ручного вмешательства в виде правок в сценариях игры или в конфигурации среды разработки. Разработчики Ren'Py стремятся к тому, чтобы все прочие изменения движка не влияли на работу существующих проектов.

Обратите внимание, что установка переменной config.script_version отменяет многие из этих изменений ценой потери доступа к новым возможностям движка.

Несовместимые изменения в графическом интерфейсе задокументированы в разделе Несовместимые изменения GUI, поскольку они вступают в силу только при повторной генерации GUI.

Планируемые прекращения поддержки

Возможность создания обновлений по протоколу zsync будет удалена в релизе Ren'Py 8.7.

8.6.0

Слои экранов диалога и выборов Переменные config.say_layer, config.choice_layer и config.nvl_choice_layer теперь по умолчанию равны None, позволяя свойству экрана layer иметь приоритет. Экраны без явно объявленного слоя по-прежнему используют слой "screens". Игры, объявляющие совместимость с Ren'Py 8.5 или более ранними версиями, сохраняют старое поведение. Чтобы восстановить прежние настройки явно:

define config.say_layer = "screens"
define config.choice_layer = "screens"
define config.nvl_choice_layer = "screens"

Версия библиотеки в renpy.get_sdl_dll Ren'Py перешёл на использование SDL3, поэтому функция renpy.get_sdl_dll() теперь принимает аргумент version, который необходимо установить в 3 для получения библиотеки SDL3. Вызовы без аргумента version возвращают None, обозначая отсутствие библиотеки SDL2.

Кандидаты методов ввода (IME) Теперь Ren'Py самостоятельно отрисовывает список кандидатов IME, когда SDL передаёт соответствующие события (включая Windows), вместо использования системного окна ОС. В Linux диспетчеры IBus и Fcitx по-прежнему используют свои нативные окна. Играм с кастомизированным вводом текста может потребоваться стилизация нового экрана _ime_candidates, как описано в Методы ввода (IME).

Позднее сканирование аудиофайлов Теперь Ren'Py регистрирует автоматически найденные аудиофайлы на позднем уровне инициализации, а не на init 0. Чтобы вернуть прежнее поведение, добавьте в проект:

define -1 config.late_audio_scan = False

Оператор Voice и идентификаторы перевода По умолчанию оператор voice больше не влияет на генерацию идентификаторов строк перевода (translation ID). Это означает, что добавление или удаление озвучки не сломает существующие переводы. Если в вашей игре присутствуют и реплики voice, и переводы, идентификаторы могли измениться. Чтобы вернуть прежнюю схему хеширования, добавьте:

define config.tlid_only_considers_say = False

8.5.4

Ren'Py теперь использует интерпретацию кривых Безье по Кардано в анимациях Live2D в соответствии с официальным Live2D SDK. Это может незначительно изменить траектории некоторых движений. Чтобы вернуть старое поведение, добавьте:

define config.live2d_old_beziers = True

8.5.3

Live2D Ren'Py теперь поддерживает и требует Live2D Cubism 4 SDK версии 5.3 (Native). Может потребоваться обновить библиотеку Live2D для продолжения работы в Ren'Py 8.5.3+.

8.5.0

Свойства Maximum могут увеличивать размер Свойства xmaximum и ymaximum теперь могут использоваться для запроса размера, превышающего предлагаемый контейнером. Это может приводить к увеличению объектов по сравнению с предыдущими версиями Ren'Py. Чтобы вернуть старое поведение, добавьте:

define config.maximum_embiggens = False

Определение языка системы Теперь Ren'Py отдаёт предпочтение коду языка ("en") перед кодом региона ("us"), если оба являются допустимыми языками в игре. Комбинация языка и региона ("en_us") имеет наивысший приоритет.

pygame_sdl2 Модуль pygame_sdl2 исключён из поставки Ren'Py и заменён совместимым пакетом renpy.pygame. Для обратной совместимости пакет доступен под псевдонимами pygame и pygame_sdl2, поэтому существующие инструкции import продолжают работать. Ранее pygame_sdl2 автоматически импортировался в пространство имён store; этот автоимпорт удалён. При необходимости его можно вернуть кодом:

init python:
    import renpy.pygame as pygame_sdl2

Каталоги изображений Переменная config.images_directory заменена на config.image_directories, представляющую собой список каталогов, в которых Ren'Py ищет графику. Сценарии, изменяющие эту переменную, следует обновить. Например, замените:

define config.images_directory = "myimages"

на:

define config.image_directories = [ "myimages" ]

Масштабирование Zoom и ось Z В Ren'Py 8.4 свойство трансформации zoom применяется не только к осям X и Y, но и к оси Z. Это могло изменить отображение в старых проектах с 3D-сценами. Чтобы отключить масштабирование по оси Z, добавьте:

define config.zoom_zaxis = False

8.4.1

Панорамирование звука с постоянной мощностью Появилась возможность отменить алгоритм панорамирования аудио с постоянной мощностью (constant-power panning), появившийся в 8.1.0. Для этого добавьте в игру:

define config.adjust_audio_amplitude = 1.0 / 0.7071067811865476

8.4.0

Автоматический оверсемплинг При значительном увеличении масштаба окна Ren'Py может автоматически искать и подгружать текстуры повышенного разрешения. Подробнее см. документацию. Эту функцию можно отключить с помощью:

define config.automatic_oversampling = None

Поскольку оверсемплинг полезен и не нарушает логику старых игр, он остаётся включённым по умолчанию.

Оператор Show Expression Поведение оператора show expression изменено таким образом, что:

show expression "bg washington"

теперь полностью эквивалентно:

show bg washington

Ранее в качестве тега изображения использовалось само строковое выражение. Если выражение не является строкой, для него создаётся уникальный тег. Чтобы вернуть прежнее поведение, добавьте:

define config.old_show_expression = True

LayeredImage Если свойствам "variant" и "prefix" переданы имена без кавычек, они интерпретируются как строковые литералы, а не как имена переменных init. Если вашему проекту требовалось старое поведение, используйте:

variant f"{old_expression}"

Кроме того, имена групп "multiple" больше не поддерживаются.

Пользовательские операторы и config.label_callbacks Пользовательские операторы CDS теперь вызывают функции из config.label_callbacks при объявлении метки. Чтобы вернуть прежнее поведение, добавьте:

define config.cds_label_callbacks = False

Отступы сетки (Mesh Padding) Изменилось поведение mesh_pad при наличии левого или верхнего отступа. Ранее дочерний объект смещался на величину отступа; теперь дочерний объект остаётся на месте, а отступ добавляется к внешним границам сетки.

Размер области прокрутки в стандартном GUI Рекомендуется добавить следующий стиль в проекты со стандартным GUI:

style game_menu_viewport:
    variant "small"
    xsize 1305

Это гарантирует отображение полос прокрутки на смартфонах и телевизорах. Число 1305 рассчитано на разрешение 1920x1080. Для разрешения 1280x720 используйте 870, для 3840x2160 — 2010 (для других разрешений — 0.68 ширины экрана).

Порядок применения частей шейдеров Ранее порядок частей шейдера с одинаковым приоритетом был неопределён. Теперь они строго упорядочиваются по имени шейдера, что гарантирует стабильный результат на всех видеокартах.

Пути к модулям Python При загрузке модулей Python из каталога game/ переменная __file__ теперь всегда содержит относительный путь к модулю, пригодный для передачи в renpy.open_file().

8.3.4 / 7.8.4

Растворение отображаемых объектов разного размера (часть 2) При переходах ImageDissolve и AlphaDissolve между объектами разного размера Ren'Py задаёт результату размеры наибольшего из них по каждой оси. Чтобы вернуть поведение до 8.1.2 (минимальный размер по каждой оси), добавьте:

define config.dissolve_shrinks = True

Удаление события ATL 'update' В предыдущих версиях Ren'Py событие "update" могло ненадёжно посылаться трансформациям ATL внутри экранов при смене языка. Это событие удалено из движка.

8.3.0 / 7.8.0

Свойства box_reverse и box_align Свойство box_reverse больше не корректирует выравнивание бокса. Для настройки выравнивания задайте свойство box_align равным 1.0 либо используйте:

define config.box_reverse_align = True

для возврата к поведению версии 8.2.

Очистка речевых бабблов (Retained speech bubbles) Нескрытые бабблы теперь автоматически очищаются при переходе к другим операторам say, menu или call screen. Это поведение контролируется переменной bubble.clear_retain_statements. Чтобы отключить автоочистку, добавьте:

define bubble.clear_retain_statements = [ ]

Установка дочернего объекта Transform из параметров ATL Правила назначения дочернего объекта (child) в трансформациях ATL на основе передаваемых параметров были уточнены:

  • Позиционный аргумент для параметра old_widget больше не устанавливает child (это было недокументированным побочным эффектом).

  • Именованный аргумент child, переданный трансформации с параметром child, теперь корректно устанавливает дочерний объект.

Коллбэки персонажей (Character Callbacks) Теперь принимают расширенный набор именованных аргументов (см. Коллбэки персонажей (Character Callbacks)). Функции обратного вызова должны принимать **kwargs для игнорирования неизвестных параметров.

Оператор Window Операторы window show и window hide больше не отключают режим window auto. Для отключения авторежима используйте window auto False либо задайте:

define config.window_functions_set_auto = True

При выполнении window show после window hide движок теперь смотрит вперёд на следующий оператор say для определения типа открываемого окна. Чтобы вернуть просмотр назад, используйте:

define config.window_next = False

Манглинг имён в строках (String Munging) Манглинг имён, начинающихся с двух подчёркиваний (__), теперь выполняется и внутри текстовых строк сценария так же, как и в коде Python. Чтобы отключить это нововведение, создайте файл 01nomunge.rpy в папке game/ со строкой:

define config.munge_in_strings = False

Обрезка за пределами границ объекта Значения, передаваемые в Crop(), crop, corner1 и corner2, больше не ограничиваются исходными размерами объекта. Чтобы восстановить поведение версий 8.2.x/7.7.x (обрезка справа и снизу), добавьте:

define config.limit_transform_crop = True

Для возврата к поведению до 8.2/7.7 (обрезка только при значениях float):

define config.limit_transform_crop = "only_float"

8.2.2 / 7.7.2

Свойства Fill и Frames В некоторых случаях свойства стиля xfill и yfill могли уменьшать размеры фреймов Frame, окон Window и кнопок Button. Теперь разрешено только увеличение размеров. Чтобы вернуть прежнее поведение, добавьте:

define config.fill_shrinks_frame = True

8.2.1 / 7.7.1

Вертикальный текст Была исправлена отрисовка вертикального текста в шейпере HarfBuzz. Позиционирование глифов стало корректным. Поскольку предыдущее поведение было ошибочным, специальный флаг совместимости не предусмотрен.

8.2.0 / 7.7.0

Строковые аннотации и PEP 563 Директива from __future__ import annotations больше не включается принудительно по умолчанию при компиляции Python. Чтобы использовать строковые аннотации, добавьте в начало файла:

rpy python annotations

Отрисовка текста через HarfBuzz Ren'Py перешёл на шейпер HarfBuzz, что может влиять на кернинг и интервалы символов. Чтобы вернуть старый механизм FreeType, добавьте:

style default:
    shaper "freetype"

Ren'Py теперь автоматически использует цветные эмодзи-шрифты при наличии символов эмодзи. Чтобы отключить это:

style default:
    emoji_font None

Интерполяция выражений в строках Подстановки в квадратных скобках теперь вычисляются как полноценные выражения Python. Например, выражение [player[money]] теперь обращается к словарю по значению переменной money, а не по строковому ключу 'money'. Чтобы вернуть старый синтаксис:

define config.interpolate_exprs = False

Либо используйте переходный режим, пытающийся сначала новое поведение, а при ошибке — старое:

define config.interpolate_exprs = "fallback"

Полярные координаты Значения углов в свойствах angle и anchorangle теперь строго ограничиваются диапазоном от 0 до 360 градусов (включая 0, исключая 360). Изменение на 360 градусов трактуется как 0. При интерполяции углов в ATL без указания направления выбирается кратчайшая дуга.

Запрет пустых блоков ATL Пустые блоки ATL теперь вызывают ошибку синтаксиса. Замените show eileen happy: на show eileen happy.

Свойство Box Reverse Изменилось поведение свойства стиля box_reverse: доступное пространство предлагается объектам в порядке их объявления на экране, а переносы строк (box_wrap) выполняются сверху вниз (для hbox) и слева направо (для vbox). Для возврата к старому поведению:

define config.simple_box_reverse = True
